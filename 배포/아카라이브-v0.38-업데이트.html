처음 보시는 분께

SimCore는 봇에 숫자로 굴러가는 상태를 붙여 주는 플러그인입니다. 식량·호감도·재정 같은 걸 AI에게 세라고 시키는 대신 시스템이 직접 계산하고, 그 결과를 상태창과 프롬프트로 내보냅니다.

먼저 쓰고 계셨다면 지금 올려 주세요

SimCore가 다른 플러그인·모듈의 보조 모델 호출을 망가뜨리고 있었습니다. v0.37.2에서 고쳤습니다. 짚은 분들 덕에 찾았습니다.

리수는 앱에서 나가는 모든 요청에 플러그인의 프롬프트 훅을 걸어 줍니다 — 메인 생성만이 아니라 번역·요약·감정·기타 보조 호출까지 전부요. SimCore는 그게 어떤 요청인지 안 보고 자기 상태 블록을 얹고 있었습니다. 

모듈이 보조모델에게 보내려던 것
   "이 서사에 감정 태그를 달아라. JSON 배열만 출력."

실제로 나간 것
   "이 서사에 감정 태그를 달아라. JSON 배열만 출력."
   + "지금 영지 상태는 이렇다. 바뀐 값을 changes로 내라."  ← 우리가 얹은 것

받은 것
   둘 중 뭘 하라는 건지 모르는 답 → 모듈은 아무것도 못 얻는다
— 모듈이 보조 모델에게 시키던 일(감정 이미지 태그 같은 것)이 안 되던 것.
— 보조 모델을 쓰는 다른 플러그인이 안 돌던 것도 같은 원인입니다.
— 번역기도 지나갑니다. 번역 프롬프트에 영지 장부가 딸려 갔습니다.
— 반대로 그쪽 보조 호출이 SimCore의 턴을 몰래 한 칸씩 넘기고 있었습니다. 하루가 두 번 가는 식으로요.

이제 우리 블록은 메인 생성에만 실립니다. 모듈·플러그인 쪽은 손댈 것이 없습니다 — SimCore만 다시 임포트하시면 됩니다.

이번 업데이트를 한 줄로

상태창이 길어지면 탭으로 나눠 담습니다.

그리고 보조 모델에게는 이번 턴에 실제로 나온 것만 열어 줍니다 — 스물여섯 명의 호감도를 매 턴 통째로 보여 주던 걸 그만뒀습니다.

v0.38 상태창을 여러 장으로 나눈다

변수가 늘면 상태창이 세로로 한없이 길어집니다. 영지·인물·탐사·창고를 다 켜 두면 상태창 하나가 화면을 넘깁니다. 이제 그룹을 탭으로 접어 담을 수 있습니다.

이렇게 보입니다.

▾ 베리디아 남작령
영지 인물 탐사 창고
주민154
금화1,240
하루 수지+384

고르는 건 넷입니다. 봇 편집 → 상태창 → [그룹 배치]에서 하나 고르면 끝이에요.

쌓기        지금까지 그대로 — 전부 세로로
탭          한 번에 한 장. 그룹 이름이 곧 탭 이름
접기/펼치기  여러 장을 동시에 펴 둘 수 있다
버튼 팝업    평소엔 버튼만. 누르면 그 장이 떠오른다

쓰던 봇은 아무것도 안 바뀝니다. 고르지 않으면 예전 그대로 쌓입니다.

알고 쓰셔야 하는 것 하나

전환은 CSS만으로 돕니다. 리수는 메시지 안의 버튼을 누를 때 어느 것이 눌렸는지를 플러그인에 안 넘겨 줘서, 스크립트로는 애초에 만들 수가 없어요. 그 대가로 새 턴이 오면 맨 아래 메시지의 탭 선택이 첫 탭으로 돌아갑니다. (지난 메시지들은 그대로 남습니다.)

그게 거슬리시면 접기/펼치기를 쓰세요 — 여러 장을 동시에 볼 수 있어서 애초에 왔다 갔다 할 일이 적고, 모바일에서도 이쪽이 더 확실합니다.

v0.37 등장한 것만 연다

보조 모델에게 매 턴 스물여섯 명의 호감도를 전부 열어 두고 있었습니다. 그 턴에 나오지도 않은 사람의 값이 분위기에 밀려 ±1씩 움직입니다. 상한을 걸어도 소용없어요 — 상한은 크기를 막지 횟수를 못 막습니다. 

이번 턴 서사 — 리비아만 나온다
   …리비아는 장부를 덮고 창가로 갔다.

v0.36까지 보조 모델이 받던 목록
   호감_리비아 47   호감_카일 30   호감_마르타 22   호감_에런 18
   호감_요한 25   호감_세실 41   … 스물여섯 줄   ← 안 나온 사람도 만질 수 있다

v0.37부터
   호감_리비아 47                                  ← 나온 사람만

로어북 키워드와 같은 방식입니다. 변수에 이름을 걸어 두면 그 이름이 이번 턴 서사에 실제로 나왔을 때만 보조 모델에게 열립니다. 안 나온 값은 아예 못 건드리니 흔들릴 수가 없습니다.

이름이 서로 겹칠 때는 긴 쪽이 이깁니다. "리비아"와 "리비아 부인"이 다른 사람이면, "리비아 부인"이 나온 문장이 "리비아"를 같이 열어 버리지 않게요.

v0.37.1 보조 모델을 버텍스로 걸면 죽던 문제

보조 모델을 버텍스(Gemini)로 잡으면 이 오류가 났습니다. 같은 모델을 LLM Gateway로 돌려 잡으면 멀쩡했고요 — 뒤에 붙은 백엔드는 똑같은데도요. 

테스트 결과: 실패 — 호출 예외: Cannot read properties of undefined (reading 'role')

프로바이더 탓이 아니라 우리가 보내는 모양이 틀렸던 것입니다. 보조 호출을 system 한 통으로만 보내고 있었는데, 구글 계열은 system을 본문에서 빼내 따로 담습니다 → 본문이 빈 채로 나가고 리수가 없는 걸 읽다 죽습니다. OpenAI 호환 쪽은 그냥 넘겨 줘서 안 죽었을 뿐, 우리가 맞은 적은 없었습니다.

이제 짧은 유저 턴을 하나 붙여 보냅니다. 직접 호출·루아 브리지 양쪽 다요. 제보해 주신 분이 고친 버전으로 확인해 주셨습니다. 버텍스로 걸었다가 안 돼서 접으셨던 분은 이제 됩니다.

봇 만드시는 분께

배치는 한 줄입니다. 상태창 탭에서 [그룹 배치]만 고르면 되고 HTML도 CSS도 안 씁니다. 직접 짜고 싶으시면 표시 방식을 커스텀 HTML 템플릿으로 두고 [탭 뼈대 넣기]를 누르세요 — 빈 예제가 아니라 그 봇의 그룹·변수가 이미 채워진 HTML이 나옵니다.

뼈대 안의 {uid}는 지우면 안 됩니다. 상태창은 메시지마다 그려지는데 그게 없으면 맨 아래 글의 탭을 눌렀는데 맨 위 글의 탭이 바뀝니다. 같은 이름표가 화면에 여러 개 생기기 때문이에요. {uid}가 그 메시지 번호입니다.

(접기/펼치기와 버튼 팝업은 이름표를 안 써서 이 문제가 아예 없습니다.)

루아 브리지를 쓰고 계셨다면

다시 임포트한 뒤 [루아 브리지 설치/갱신]을 한 번 눌러 주세요. 브리지 쪽에도 같은 버텍스 수정이 들어갔는데, 이미 깔린 브리지는 스키마가 그대로면 낡은 걸 계속 쓰고 있었습니다. 이제 그것도 낡음으로 잡힙니다.
