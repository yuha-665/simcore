# 🧩 번들 조각 1단계 (v1.25.0) 구현 계획

> 실행: `executing-plans`로 작업 순서대로 진행한다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** 고른 항목만 담는 조각 번들(`simcoreBundle: 2`)을 만들고, 받는 쪽은 번들 id별 기준 지문으로 3자 비교해 내 것을 남긴 채 넣는다.
**구조:** 순수 로직은 새 코어 모듈 `core/bundle.js`(단위 걷기·지문·판정·적용·조각 만들기)에, 어댑터는 화면·저장·흐름만.
전체 번들(형식 1)은 id·rev를 싣고 지문만 저장한다 — 캐릭터에 쓰는 결과는 지금과 같다.
**기술:** 순수 JS(CommonJS → build.js 번들), Node 테스트(`테스트/test-*.js`), 가짜 리수 하니스(test-profile ⑤와 같은 결).
**설계 문서:** `docs/design-번들-조각.md` (실행자는 둘 다 읽는다)
**커밋:** 작업마다 (브랜치 `feat/bundle-piece`). 배포 리포(simcore-release) 반영은 유저 실기 뒤 — 이 계획 밖.

## 전역 제약

- `id` 없는 옛 번들(형식 1)이 캐릭터에 쓰는 결과는 한 글자도 안 바뀐다 — 테스트로 못 박는다.
- Dusk Atelier(AGPL-3.0-only) 코드를 옮기지 않는다. 전부 새로 짠다.
- 루트 문서에 요소를 넣지 않는다(금지 #14). 패널이 떠 있는 동안 호스트 알림창을 안 쓴다(금지 #6) — 확인은 패널 안 두 번 누르기(60초).
- 엔진·상태·프롬프트는 안 건드린다. `FEATURE_MAP` 줄 없음.
- editor.js에는 내보내기(`module.exports`)만 늘린다 — 세그먼트 안에 모듈급 의존성을 늘리지 않는다(금지 #8).
- 본문에 줄머리 `//@`를 두지 않는다(test-bundle이 잡는다).
- 릴리스 규약: `//@version`·`//@display-name` 같이 올리고, `node build.js` 산출물과 `simcore.plugin.js` 바이트 일치, 스위프 실패 0.

## 정한 것 (설계가 작업자에게 맡긴 자리)

- **단위 열쇠**: `lore:<comment>#<n>`(comment 빈칸 → `lore:~k:<key>#<n>`, 그것도 빈칸 → `lore:~h:<내용 해시>#<n>`),
  `regex:<comment>|<type>#<n>`, `schema:<a.b.c>`, `schema:<a.b>[<id>]`. `#n`은 같은 이름 안에서 나온 순서(0부터, 늘 붙인다).
- **빈 것은 단위가 아니다**: `undefined`·`[]`·`{}`는 "없음". (조각이 빈 배열을 "번들이 준 것"으로 만들지 않고, 삭제 = 그 키를 지우는 것으로 통일.)
- **함께 걷기**: 내 것(C)과 번들(I)을 같은 경로에서 같이 내려간다 — 둘 다 객체면 키마다, 둘 다 id 목록(한쪽이 없음이어도)이면 항목마다,
  모양이 어긋나면 그 자리가 잎 하나. 지문(B)은 I를 혼자 걸은 열쇠라 모양이 바뀐 자리는 "기준 없음"으로 떨어진다(안전한 쪽).
- **병합 결과는 `shapeFill` 모양으로 쓴다**: C는 채운 사본에서 계획하고 결과도 채워서 싣는다(편집기가 싣는 모양과 같다).
  스키마 단위가 하나도 안 바뀌면 `⚙simcore` 글은 원문 그대로 둔다.
- **스키마를 건드리는 조건**: `data.schema`가 있거나 지문에 `schema:` 열쇠가 있을 때만. 로어·정규식만 든 조각은 `⚙simcore`를 읽지도 않는다.
- **조용한 판정**: 지문 없는 "내 것"(C만 있음)은 요약 줄에 안 올린다(받는 봇 전체가 여기 든다). "같음"·"내가 지움(I=B)"도 줄 없음, 내가 지움은 개수만.
- **줄 종류**: `add` 추가 · `update` 번들 수정 · `mineEdit` 내 수정 유지 · `removed` 제작자 삭제 · `revive`(내가 지웠는데 제작자가 고침) 충돌 ·
  `conflict` 충돌 · `locked` 🔒. 줄마다 `choice: 'bundle'|'mine'`, 🔒만 고정.
- **딸린 것 묶기**: `varReferenceIndex`의 '기타'(분류 밖 원문 정규식) 적중은 안 따라간다 — 글 속 낱말 우연 일치로 엉뚱한 변수가 끌려온다.
  못 잡은 참조는 끝 관문(혼자 검증)이 이름을 대며 막는다. 색인이 추첨 `sample`을 변수로 보도록 원본 변수의 `{id}` 그루터기를 넣어 돌린다.
- **[캐릭터에서 제거]** 는 번들 백업을 안 만드는 길이라 지문만 지운다(사본 없음 — 다음에 넣을 때 첫 설치 길로 떨어진다).
- **더티 작업본 멈춤**은 조각·전체 번들 둘 다에 건다(설계 §7 — "지금은 말없이 덮는다"가 고칠 대상). 캐릭터에 쓰는 결과와는 무관.
- **형식 1의 흐름은 IIFE 수준 함수로 올린다**(`bundleWholeApply`·`bundleRevert`) — 가짜 리수에서 굴리려면 패널 배선 밖에 있어야 한다. 문장 순서는 그대로.

## 검토 초점

1. 받는 봇의 `⚙simcore` JSON이 깨져 있는데 스키마 든 조각을 넣는다 → 거절하고 이유를 보여 준다, 아무것도 안 바뀐다.
2. 같은 comment의 로어가 둘인 봇에서 받는 사람이 앞 것을 지웠다 → `#n`이 밀려도 **지문에 없는 내 항목은 안 지워진다**(지우기는 C=B일 때만).
3. 손으로 고친 조각 파일의 `schema`에 `meta`·`simcore`가 들어 있다 → 그 둘은 무시하고 넣는다(받는 봇의 제목·버전 표식을 안 바꾼다).
4. 적용은 됐는데 지문 저장이 실패한다(저장소 오류) → 캐릭터는 그대로 두고 "다음 업데이트는 처음 넣는 것처럼 물어요"라고 알린다.
5. 설치된 판보다 낮은 rev를 넣는다 → 요약에 경고만, 막지 않는다.
