> 다음 이야기가 해금되고 그런식으로 이야기 속도와 흐름을 제어하는 시나리오레이터".

## 1. 왜 루아 시절엔 안 됐고 심코어에선 되나

| 시도 | 실패 지점 |
|---|---|
| 자율주행 (기승전결 통짜 주입) | 모델이 **매 아웃풋마다 전체 줄거리를 보며 스스로 분량을 조절**해야 했다. 모델은 "지금이 이야기의 몇 %인지"를 모른다 — 아웃풋 하나가 2천 토큰인 세계에서 기승전결이 세 턴 만에 끝난다. |
| 중심 사건 생성기 v1.3 | 국면 전환이 **유저 버튼**(⏫ 국면진행)이다. 시스템이 페이스를 모르니 사람이 계속 운전대를 잡아야 했다. 대신 두 가지를 증명했다: ① 국면별 연출 지시 주입(잠복=옅게, 절정=전면)이 실제로 먹힌다 ② "표면 상황만 / 내막·결말 금지" 생성 규칙이 좋은 축을 만든다. |

심코어가 바꾸는 것: **플레이가 남긴 흔적(변수·경과일·판정·이벤트)이 이미 있다.**
- 막 전환을 **조건식이** 정한다 — 버튼도, 모델의 눈치도 아니고.
- 모델은 전체 시나리오를 **영영 못 본다.** 현재 막의 연출 지시만 받는다.
  분량 조절 문제가 구조적으로 사라진다 — **모델이 조절할 게 없으니까.**

이벤트와의 분업: 이벤트 = 세상의 리듬(반복·랜덤·조건), 시나리오 = 이야기의 척추(선형·1회).
막 해금 조건이 이벤트·판정이 세운 변수를 읽으므로 둘은 자연히 맞물린다.

## 2. 스키마 (v1 안)

```json
"scenario": {
  "label": "제1장 — 혈마심경",
  "acts": [
    { "id": "act1", "label": "잠복",
      "direct": "이 응답에서 중심 사건의 실마리를 아주 옅게만 암시하라. 전면에 내세우지 말 것.",
      "secret": "혈마심경 조각은 사실 세 개가 아니라 넷이다.",
      "intensity": "잠복",
      "notify": "…" },
    { "id": "act2", "label": "전개",
      "unlock": "finds >= 2 or day >= 30",
      "minTurns": 5,
      "onEnter": [{ "set": "threat", "expr": "clamp(threat + 10, 0, 100)" }],
      "direct": "…", "intensity": "전개", "notify": "…" }
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `unlock` | 이전 막이 열린 상태에서 이 조건이 참이 되면 전환. 첫 막은 생략(즉시). 판정 연계는 "판정이 세운 변수"를 읽는 기존 2단 구조 그대로. |
| `minTurns` | **페이스 바닥** — 조건이 먼저 차도 이 막에서 최소 N턴은 머문다. "이야기 속도 제어"의 핵심 손잡이. |
| `direct` | 이 막이 열려 있는 동안 매 턴 주입되는 연출 지시 (directives와 같은 기계, `{변수}` 삽입 가능) |
| `secret` | **이 막부터** 모델에게 공개되는 내막. 이전 막에선 프롬프트에 아예 안 실린다. 공개는 누적 — 밝혀진 진실은 잊히지 않는다. |
| `intensity` | 잠복/전개/고조/절정/해소 — v1.3의 국면별 기본 연출 문구를 자동 첨부 (direct는 그 위에 얹는 봇 고유 지시) |
| `onEnter` / `notify` | 전환 순간 1회 효과·통지 (이벤트와 같은 형식) |

내부 상태: `scn_act`(현재 막, 시스템 전용 — updater allow 금지), `scn_turns`(현재 막 경과 턴,
전환 시 리셋). 상태창·조건식에서 `scn_act`/`scn_label` 파생으로 읽기 가능 (진행 표시는
라벨만 — 스포일러 없이).

전환 판정 자리: outputPhase의 조건 이벤트(⑦)와 같은 층. 통지는 기존 규약대로 다음 전송에 합류.

## 3. 왜 1급 섹션인가 (변수+이벤트+지시문 수제 조립 대비)

수제로도 된다 (`act` int + once 이벤트 + `when: act == N` 지시문). 1급으로 만드는 이유:

1. **은닉 보장** — 수제는 실수로 전체 시나리오를 로어북/지시문에 싣기 쉽다. 1급은 엔진이
   "현재 막 direct + 열린 막들의 secret"만 싣는 것을 **구조로** 보장한다.
2. **minTurns** — 수제로 하려면 막마다 턴 카운터 리셋 배선이 필요한데 반드시 어긋난다.
3. **편집기 탭 + AI 생성** — 배포자가 시나리오를 표로 적는 탭 (규칙 #3) + tabAiTools 규격.
   내장 AI 생성(v0.46 기계)에 시나리오 규격만 추가하면 "이 봇 설명·로어북을 읽고 5막
   제안"이 공짜로 된다. **v1.3의 생성 규칙을 규격에 그대로 이식**: 표면 상황만 / 내막·반전은
   secret 칸으로 분리 / 주인공의 행동·결말 금지.
4. **검증·진단** — 영영 안 열리는 막(unlock 도달 불가 — 기존 '죽은 이벤트' 진단과 같은 기계),
   unlock 없는 중간 막, 마지막 막 이후 처리(해소 상태 유지)를 잡아 준다.

## 4. v1 범위

- 선형 acts만. 분기는 나중에 (unlock 조건으로 사실상 건너뛰기는 가능하지만 공식 지원 아님).
- 편집기 [시나리오] 탭 + AI 내보내기/가져오기 + 내장 AI 생성 연결.
- 상태창 자리표시자 `{scenario}` (현재 막 라벨·진행, 선택 사항) — 대장 탭에서도 동일하게.
- 새 시작 페이지에 막 강제 이동(디버그·구제) — 상태 보정과 같은 자리.
- 검증: unlock 표현식 검사, direct/secret 문자열, 도달 불가 진단.
- 규모 감: 편성표(v0.55~0.59)급 — 엔진·검증·편집기·진단·테스트 한 바퀴.

## 5. 경쟁작 확인 — S2D.추리 (2026-08-25)

유저가 발견한 남의 플러그인: S2D.추리 v4.32.19 (22,812줄 / 3.5MB, 추리 사건 전용 게임 엔진).
"PUBLIC STATE = 사건 사실의 유일한 권위, 미공개 = 거짓이 아니라 아직"이라는 은닉 계약 +
증거 항목별 Lv0→Lv2 단계 해금 + 행동마다 별도 보조 판정(runLLMModel, 자체 API 키).

**겹치는 건 은닉 원리 하나뿐 — 축이 다르다.** S2D의 해금은 공간·항목 축(플레이어가 조사해서
엶)이고 페이싱 제어(acts·minTurns·intensity)가 아예 없다 — 루아 시절 "⏫ 국면진행 버튼"과
같은 자리. 시나리오레이터는 시간·막 축(조건식+minTurns가 엶)이고, 해금 조건이 심코어
변수·판정을 읽는 것 자체가 S2D가 구조적으로 못 하는 일이다(자체 세션이라 심코어 상태를 모름).

- **범위 선언: 추리 게임은 비목표.** 추리봇은 S2D가 이미 4.x까지 다듬은 정답이다.
  시나리오레이터는 심코어가 이미 굴리는 봇들(영지·아이돌·연애·무협)에 이야기 척추를 꽂는다.
- **검증 획득**: "은닉을 구조로 보장 + 모델에겐 현재 공개분만" 원리로 남이 성숙한 플러그인을
  실전 운용 중 — §3-1이 탁상공론이 아니라는 증거.
- **훔칠 어법 (미결 1번에 쓸 것)**: ① FACT LOCK의 양면 문장 — "새 사실 금지, 단 이건 사고를
  잠그는 규칙이 아니다. 공개된 정보의 비교·해석·추론·가설은 자유롭고 적극적으로" →
  잠복 막 direct에서 모델 위축 방지. ② "미공개 = 거짓이 아니라 아직 공개되지 않은 것.
  빈칸을 창작으로 메우지 마라" → secret 미공개 막의 기본 문구.
- 공존 가능(S2D는 로어북 조각 주입이라 훅 안 부딪힘) — [live-test] 영역.
