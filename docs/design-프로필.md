# 🔀 프로필 — 한 봇에 판 여러 벌 (v1.24.0)

커뮤니티 요청(2026-11-09, 유저 전달): "프로필이라고 해서 — 한 봇에서 심코어 스키마를 토글값을 활용해 **채팅별로 따로 상태창**.
가끔 다른 능력을 그 봇에 하고 싶은데 기능으로 해 두면 좋을 것 같다." → 유저 "프리셋처럼 쓸 수 있는지 물어본 것 같은데 가능한가" →
문제점 검토 뒤 "추천대로 가자"(덧칠 + 스냅샷).

## 0. 그전에 있던 것

| | 되는 것 | 모자란 것 |
|---|---|---|
| 새 시작 프리셋 (`setup.presets`) | 시작값만 바꾼다 (값, 수식 아님) | 판(변수·상태창·규칙)은 하나 |
| 모드 변수 + `when` (조퇴악녀 시점 셋) | 한 스키마 안에서 판마다 상태창(`templates[].when`)·지시문·`allow[].when` | 항목마다 `when`을 손으로 · 같은 id로 판마다 다른 정의 불가 · **남의 봇에 내 판을 얹으려면 원본을 고쳐야 하고 그게 모든 채팅에 번진다** |

요청의 핵심은 마지막 칸 — "가끔 다른 능력으로, 다른 채팅은 그대로".

## 1. 결정 두 개

**A. 덧칠(기본 판 + 달라진 부분만) — 통째 사본이 아니다.**
- 큰 봇 스키마가 수백 KB(아틀리에 494KB, 베리디아 350KB). 사본 세 벌이면 로어북이 1.5MB 늘고, 플러그인은 전송·채팅 전환마다
  `getCharacter()`로 캐릭터를 통째로 읽는다 — 포켓리스가 먼저 느려진다.
- 제작자가 봇을 업데이트(번들)하면 사본은 옛 버전에 멈춘다. 덧칠은 새 기본 판 위에 다시 얹힌다.
- 대가: 차이 계산·얹기가 필요하고(패치 병합은 상태창·AI 설정을 못 다룬다 → 별도 모듈), 업데이트로 덧칠이 깨질 수 있다(→ 기본 판으로 돌고 알림).
- 나중에 사본 → 덧칠로 옮기기는 이미 만든 프로필을 쪼개야 해서 처음부터 덧칠로.

**B. 이 채팅의 판 = 상태(스냅샷)의 예약 키 `sim_profile` — 채팅 변수는 그 거울.**
- 스냅샷에 실리니 과거 상태창이 그때 판으로 그려지고(채팅 변수에만 두면 옛 메시지가 새 판 모양에 옛 값으로), 되감기(체크포인트)가 판까지 돌려놓는다.
- 미러가 `$sim_profile`을 쓰니 로어북 CBS `{{getvar::sim_profile}}`로 판마다 로어를 켜고 끈다 — 요청의 "토글값 활용"이 이 자리.
  리수 토글(`toggle_*`)은 `getglobalvar`로 읽는 전역 값이라 채팅마다 따로 못 둔다고 봤다 ([live-test] 확인 안 함).

## 2. 저장 모양

로어북 항목 `⚙simcore:<이름>` (키 ` __simcore_never__` — 절대 안 걸린다). 내용:

```json
{ "simcoreProfile": 1, "desc": "마나를 쓰는 판", "aka": ["옛 이름"], "overlay": { … } }
```

덧칠 노드 (`core/profile.js`):
- `{ "$set": 값 }` — 통째 교체
- `{ "$list": { "put": [항목…], "del": [id…], "order": [id…] } }` — id 달린 목록(vars·events·actions·allow…). **put은 항목 통째** —
  기본 판이 그 항목을 지워도 프로필 것이 살고, 고친 항목은 프로필 것이 이긴다. order는 순서가 바뀌었을 때만.
- `{ 키: 노드, …, "$del": [키] }` — 객체는 바뀐 키만.
- **편집기 모양(`shapeFill`)을 양쪽에 맞춘 뒤 잰다** — 실측 사고(구현 중): 기본 판을 편집기에 실어 그대로 새 프로필로 저장했더니
  편집기가 채운 빈 절 일곱 개(`derived: []`·`directives: []`·기본 promptState…)가 덧칠에 `$set`으로 실렸다. 그대로 두면 제작자가 나중에
  기본 판에 지시문을 넣어도 프로필에선 빈 목록이 덮는다. `shapeFill` = editor.js `normalize`(같이 고친다 — test-profile이 둘을 대조).
- 통째 스키마를 붙여 넣은 항목(표식 없고 `vars` 배열)도 받는다 — 그 자리에서 덧칠로 계산, 한 번 적용하면 덧칠로 바뀐다.

이름: 20자, 앞뒤 빈칸·중괄호·제어 문자·'기본' 금지. 콜론은 된다(앞의 `⚙simcore:`만 떼므로). 이름을 바꾸면 옛 이름이 `aka`로 남아
그 이름을 적어 둔 채팅(스냅샷)이 새 이름을 찾아온다. 최대 12개(만들 때만 막는다 — 번들로 온 건 다 읽는다).

## 3. 판 고르기 (어댑터 로드)

1. 기본 판 검증 → `profileListFor(char, base, baseContent)` — 항목 글·기본 판 글이 그대로면 지난 결과(얹기+검증이 큰 봇에서 무겁다).
2. 세션을 기본 판으로 만들고 상속·재정렬 → `sess.peekState(lastCharIdx)` = init이 고를 상태를 **정합 없이** 엿본다
   (다른 판 스키마로 정합하면 그 판에만 있는 선택지 값이 시작값으로 깎인다).
3. 이름 = 상태의 `sim_profile` (스냅샷 없으면 채팅 변수 `$sim_profile`). **시작 전(턴 0)이면 캐릭터에 저장된 "새 채팅의 판"이 이긴다**
   (`sim:start-profile:<캐릭터>`, 새 시작 프리셋 v0.85.2와 같은 규약). 시작 전 슬롯이 다른 판이었으면 새 판의 시작값으로 다시 세운다.
4. `pickProfileSchema` — 못 얹으면(없음·손상·검증 실패) **기본 판으로 돌고 알림**(상태줄 🔀 줄). 이름은 지킨다 — 고치면 돌아온다.
5. 그 뒤 모듈 팩 스캔(사본 위에 — 캐시된 판을 더럽히지 않게) → `sess.useSchema(schema, 이름)` → init(이름을 상태에 적는다).

프로필이 하나도 없는 봇은 `profile = null` — 상태에 아무것도 안 적는다(예전과 같다).

## 4. 판이 바뀌는 자리

| 자리 | 동작 |
|---|---|
| 현황 [새 시작] 🔀 단추 | 시작 전 = 바로, 새 판의 시작값으로(+저장된 프리셋). 진행 중 = 두 번 누르기 — 같은 이름 변수는 이어지고 새 변수는 시작값. "새 채팅의 판"으로도 저장 |
| 리롤·메시지 지우고 이어 가기 | 세션의 판(유저의 마지막 선택)으로 적는다 (`onSend`) — pre:U가 옛 판 이름을 들고 있어도 |
| 되감기(체크포인트) | 칸의 `sim_profile`로 돌아간다 → 출력 훅이 그 자리에서 판을 갈아 끼운다(`applyProfileInPlace` — 재로드는 안 된다: 그 순간 채팅엔 새 응답이 없어 한 턴 전을 현재로 잡는다) |
| 세이브 가져오기 | 세이브의 판으로 먼저 갈아 끼우고 정합. 동봉 스키마 복원은 그 판(프로필)에 |
| 과거 상태창 | 캐시(`histPut`)가 그때 판으로 정합하고 그때 판으로 그린다 — 지금 판 상한에 옛 값이 깎이던 것(마법사 체력 최대 80 → 기본 판 시절 90이 80) |

## 5. 편집기 — 고치는 판을 붙잡는다

- `editorProfile` = 편집기가 고치는 판. **[캐릭터에 적용]은 이 판에만**: 기본 판이면 `⚙simcore`, 프로필이면 `diffSchema(기본 판, 작업본)` → `⚙simcore:<이름>`.
- 손대지 않은 편집기는 채팅이 판을 바꾸면 따라간다(`editorChatProfile`로 "채팅이 바꿨나"를 잰다 — 늘 "이 채팅의 판"과 대면 [편집기에 열기]로 연 다른 판이 곧장 되돌아간다).
  손댄 편집기는 그 판을 붙잡고, 배너에 판 이름과 "이 채팅은 '…' — 적용해도 이 채팅엔 안 보여요".
- 비교 서명 `sig` = `profile.shapeSig` — 키 순서·편집기 빈 칸을 안 본다(얹은 판은 기본 판의 키 순서·모양이라 글자로는 늘 달라 배너가 안 꺼졌다).
- 작업공간 [🔀 프로필] 카드: 지금 작업본을 새 프로필로(기본 판을 연 채면 복제) · 편집기에 열기(반영 안 한 변경이 있으면 두 번) · 이름·설명 · 지우기(두 번) ·
  ↶ 되돌리기(`sim:profile-backup:<캐릭터>:<ts>` 최근 8개 — 수정·이름·삭제 직전, 한 번에 한 단계 소모). [백업 복원]은 기본 판 백업 그대로.
- 지운 판을 들고 있던 깨끗한 편집기는 이 채팅의 판으로. 손댄 편집기는 그대로(적용하면 그 이름으로 다시 생긴다 — 배너가 "아직 없는 프로필").

## 6. 함께 고친 것

- **번들** — 로어북 통째 교체가 유저 프로필까지 지우던 것: 번들에 없는 `⚙simcore:…`는 남긴다(같은 이름은 번들 것). 덧칠 속 📌 작업 지침도 뺀다.
- **루아 브리지** — 판마다 템플릿을 굽고 `getChatVar(id, 'sim_profile')`로 고른다(`simcorePick`). 판이 하나면 예전과 글자 하나 다르지 않은 코드 —
  지문이 그대로라 설치된 브리지가 업데이트만으로 노후로 뜨지 않는다. 판 세트 지문 = 이름+판별 지문의 FNV. `writeBridgeControl`이 `$sim_profile`을 먼저 쓴다.
- **[캐릭터에서 제거]** — 프로필은 남기고 알린다(꺼진 항목이라 무해, 기본 판을 다시 설치하면 이어진다).
- **로어북 목록에서 빼기** — 편집기 생성 맥락(`getBotContextForEditor`)·메신저 인물 찾기가 이름 그대로 비교라 프로필 항목이 끼었다 → `isSchemaLore`.
  (편집기 쪽 프롬프트 빌더는 원래 `includes('⚙simcore')`로 걸러서 생성 프롬프트로 새진 않았다 — 설계 때 "샌다"고 본 것은 과장이었다.)
- **검증** — 변수 id `sim_profile` 금지(예약 키).

## 7. 안 한 것 · 다음 후보

- 편집기 대화(💬)·봇 제작이 "지금 고치는 판"을 따로 의식하지는 않는다 — 작업본이 그 판이라 그대로 된다.
- 조건식에서 `sim_profile` 읽기(기본 판에서 "마법사 판이면…") — 덧칠이 있어 필요 없다고 봤다. 로어북은 CBS로 된다.
- 프로필별 첫 메시지 — 리수 대체 인사말(alternate greetings)이 있다.
- 판 바꿀 때 값 옮기기 규칙(이름이 다른 변수끼리 잇기) — 지금은 이름이 같으면 잇고 아니면 시작값.
- [live-test] 실기에서 볼 것: publishing.md 체크 목록.
