# 기능 프리셋 (🧩 기능 추가) — 설계 초안

유저 방향 제시 (2026-08-01): "일괄 템플릿이 아닌 소규모 기능 프리셋을 만들어서 편의성을
확장하는 게 좋을 것 같다." 발단은 퀘스트 보드 문답 — 신규 기능 0개로 조립이 되는데,
그 조립 레시피를 사람마다 손으로 다시 짜야 한다는 게 남은 비용이었다.

## 개념

- **템플릿** = 통짜 시작용 (빈 봇 → 완성 스키마). 13종, 그대로 유지.
- **기능 프리셋** = **굴러가는 봇에 서브시스템 하나 얹기** (퀘스트 보드, 상점, 성장 시스템…).
  큐레이션된 패치 조각이다 — AI 패치와 같은 문으로 들어간다.

3단 사다리 완성: 초보는 프리셋 딸깍 → 익숙해지면 AI에게 맡기기 → 고수는 심층 편집.

## 왜 지금 재료로 되는가

- **patch.js가 이미 설치기다** — add/update/remove 병합, 충돌 감지(전부 새 id/교체/건너뛰기
  일괄 버튼, v0.44.2), 검증 실패 시 무변화(원자 반영), 되돌리기 한 번. AI 패치용 안전장치를
  프리셋 설치가 그대로 탄다. **새 병합 코드를 쓰지 않는다.**
- 편집기의 골격 버튼들("일정 목록 만들기" v0.61, "편성표 만들기" v0.55, "🌙 액션 추가" v0.49)이
  이미 초소형 프리셋이다 — 이걸 탭 밖으로 꺼내 목록화하는 것이 본질.

## 구조 스케치

```js
// core/recipes.js (가칭)
// 레시피 = 고정 JSON이 아니라 생성 함수 — 기존 스키마를 보고 적응한다.
{
  id: 'quest_board', label: '퀘스트 보드', icon: '📜',
  desc: '의뢰 목록 + 수주 갈림길 + 기한 자동 폐기 + 달력 연동',
  needs: (schema) => timeConfig(schema) ? null : '시간 체계(time)가 필요합니다 — [시간] 탭에서 먼저',
  params: [{ key: 'listId', label: '의뢰 목록 id', default: 'quests' }],   // 선택
  build: (schema, params) => ({ patchVersion: 1, add: { vars: [...], events: [...], ... } }),
}
```

- `needs` — 전제 검사 (시간·enum 변수·points 등). 설치 전에 말해 준다.
- `params` — "호감도 인물" 프리셋처럼 이름 하나 받아 찍어내는 것 (id는 자동 파생 + 충돌 회피).
- `build` 결과는 **표준 패치 형식** → planPatch 미리보기(추가 N·충돌 N) → 적용.
- 패치가 못 다루는 섹션(statusUI·party·calendar·time)이 필요한 레시피는 build가 패치 +
  **직접 병합 조각**을 나눠 돌려주고, 적용부가 검증-후-원자 반영으로 함께 넣는다
  (임포터의 팩 반영과 같은 규약 — 오류 늘면 통째 되돌림).

## UI 자리

편집기 창작 층(✨)에 "🧩 기능 추가" 구역 — 레시피 카드(이름·한 줄 설명·전제 상태) +
[추가] → 계획 미리보기 → [적용] / [↩ 되돌리기]. AI 생성 입력창 바로 아래가 후보
(프리셋으로 안 되면 자연스럽게 "말로 시키기"로 흐르게).

## 1차 레시피 후보 (전부 기존 기계 조합)

| 레시피 | 내용물 | 전제 |
|---|---|---|
| 📜 퀘스트 보드 | 의뢰 list + 발행 랜덤이벤트(choices 수주) + `@+N` 기한 + expire + 완료 자동판정 이벤트 예시 + 지시문 | time |
| 🛒 상점 | 골드 차감 + 소지품 add 액션 묶음 (품목은 params) | int 골드, list 소지품 |
| 📈 레벨·성장 | exp/level/sp + 레벨업 이벤트(sp 지급) + 수련 탭(party items) | — |
| 💕 호감도 인물 | 인물명 params → 호감 int + 단계 enum + 전이 이벤트 + 지시문 3종 + mentions | — |
| 📅 달력+일정 | calendar 섹션 + plans list + expire (v0.61 골격 버튼의 상위 호환) | time |
| 🗓 시간표 | 요일 marks 묶음 (params: 과목×요일) | calendar |

## 원칙

- 레시피 내용물은 **템플릿과 같은 코퍼스 기준** — 예제가 곧 교본이다 (ai-mistakes.md #1).
  주석 대신 desc·notify 문구로 패턴을 가르친다.
- 설치 후 진단이 깨끗해야 한다 — 레시피가 만든 것이 '못 버는 포인트'류에 걸리면 안 된다
  (v0.60 정적 검사가 레시피의 품질 게이트가 된다).
- 프리셋 목록은 규격서에 싣지 않는다 — AI 경로는 이미 자유 조립이 되므로 (중복 가르침 방지).
