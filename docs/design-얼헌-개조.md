# 얼터헌터 → 심코어 개조 설계

아카라이브 인기 시뮬봇 "얼터헌터"(헌터물)를 심코어 기반으로 개조한다.
원본 자료: `얼헌 개조용/` (봇설정·로어북 123항목·루아·정규식 54종·CSS·헌터넷).

목표 (유저 지시, 2026-08-29):
1. 상태창·시스템 로어북의 토큰 절약 — 심코어 상태 블록으로 대체
2. 로어북 캐릭터의 **변동 정보**(랭크·스킬·장비)를 로어북에서 떼어 심코어 변수로
3. 서울 구역제 게이트 출현·게이트 브레이크 등 내부변수 이벤트 (로어북 이벤트 트리거보다 생동감 있게)
4. NPC 랭크 게이팅 — 유저 랭크대와 비슷한 인물만 목록 노출, 나머지는 유동 등장
5. **헌터넷** — 채팅 후 미니 커뮤니티 보드를 심코어에 흡수. 사이드 패널, 댓글/글쓰기는
   보조모델만 호출해 추가 채팅 없이 보드만 갱신
6. CSS는 원본 봇 규격(`a-*` 클래스, 다크네이비+Rajdhani) 그대로

## 1. 원본 해부

### 1.1 상태창 (봇의 심장, 토큰 최대 소비처)

- 형식: `☆ [Date | Time | Location | Name | Level | Stat Points | EXP | HP | MP | SP |
  STR/CON/AGI/INT/SEN | Class | Weapons | Accessories | Armor | Items | Currencies | Skills | Quests]`
  (stats=0이면 ★ 경량판 — 스탯 항목 제거)
- 생성: 루아 `processStatusWindow` — **매턴 보조모델에 채팅 로그 10k~16k 토큰을 통째로 재전송**해
  상태창 한 줄을 뽑는다. 상태창 없는 컨텍스트면 13k→16k로 늘려 재시도.
- 정제: 루아 `cleanStatusText`(쉼표/괄호/헤더 필터) + 정규식 "찐빠 제거" 7종.
- 렌더: 정규식 editdisplay가 ★/☆ 줄을 잡아 CSS 상태창으로 그림.
- 게임 규칙이 로어북+루아+정규식 3곳에 흩어져 있음: EXP needed=(Lv+1)×100,
  Max HP=CON×10 / SP=AGI×10 / MP=INT×10, 레벨업 +2포인트, E랭크 기준 스탯 10,
  랭크별 스탯 구간(E:10-25 … S:100+).

### 1.2 always-on 로어북 (매턴 고정 비용)

| 항목 | 크기 | 심코어 대체 |
|---|---|---|
| 상태창 지침 | 6.7K자 | 상태 블록+지시문 (통째 삭제) |
| 시스템 메시지 지침 | 4.8K자 | 이벤트 통지·시스템 로그 |
| 측정 불가 방지 | 1.7K자 | 지시문 1줄 |
| 퓨처 플랜 | 1.5K자 | promptState/지시문 |
| NPC List (48명 요약) | 11.3K자 | 랭크 게이팅 동적 목록 |
| Hostile NPC/세력 목록 | 3.4K자 | 〃 |
| 이벤트 트리거 20종 | 7.6K자 | randomEvents (통째 삭제) |
| 아이템·경제 등 | ~5K자 | 로어북 존치(정적) |

합계 **~42K자(≈14k토큰) always-on** + 보조 상태창 호출 10k~16k/턴.
심코어 대체 시 상태 블록+지시문 ~2K자 + 보조 갱신(상태블록 중심, 로그 최소) 수준으로 감소.

### 1.3 NPC 체계 (48명)

- 개별 로어북 항목(각 ~4K자)은 이름 키워드로 활성화 — **이건 로어북이 잘하는 일, 존치**.
- 문제는 두 가지:
  - `NPC List`가 매턴 11.3K자 통째 전송. 루아가 최근 9메시지에서 이름을 감지해
    등장 인물만 목록에서 숨김(개별 항목이 뜨니 중복 방지). 미등장 47명은 계속 실림.
  - 개별 항목 안의 **변동 정보**(랭크 승급, 스킬 습득, 장비, 소속 이동)가 정적 텍스트라
    서사와 어긋나기 시작하면 되돌릴 수 없음.
- 개조: 목록은 유저 랭크 ±1 그룹만 동적 노출, 변동 정보는 심코어 변수(`npc_<id>_rank` 등)로.

### 1.4 이벤트 트리거 (로어북 20종)

전부 `{{roll::500}}<=10`(2%) 확률 게이트 + 이벤트 종류별 지시 한 단락.
심코어 `randomEvents`가 정확히 이 모양(가중치·쿨다운·조건까지 더 정교)이므로 통째 이관.
개조 시 서울 구역 게이트 시스템과 결합해 "어디서 무엇이"까지 시스템이 정한다.

### 1.5 헌터넷 (LightBoard)

- **amonamona의 LightBoard 프레임워크 (CC BY-NC-SA 4.0)** 위에 헌터넷 보드를 얹은 구조.
- 동작: 메인 모델이 `<lb-hn>` TOON 블록(게시글 n개+댓글)을 **본문과 함께** 출력 →
  루아 editDisplay가 팝오버 게시판으로 렌더. 글쓰기/댓글 버튼 → 보조 호출로 블록 재생성.
- 토큰 비용: 게시판 원문이 채팅 메시지에 실려 매턴 컨텍스트로 재전송 + 생성 지침
  (tone/thoughts/interaction ~18K자) — "엄청난 토큰을 희생"의 실체.
- ⚠ 라이선스: LightBoard 코드·포맷은 **복사 금지**(NC-SA). 심코어판은 개념만 가져와
  처음부터 자체 구현한다 (자체 저장 포맷, 자체 렌더, 자체 지침).

### 1.6 기타

- 봇설정: 시나리오 프롬프트 + 시작 변수 (기능 토글 17종 + NPC 48명 플래그).
- 정규식 54종: 상태창 렌더·찐빠 제거·에셋 표시·설정 패널·퓨처 플랜. 심코어 이관 시
  상태창/패널/퓨처플랜 계열은 소멸, 에셋 계열은 심코어 에셋(v0.94 팩)으로.
- CSS: `a-*` 클래스, #0e1015 다크 + #8aa2cc 스틸블루, Rajdhani/Noto Sans KR.
  **이 규격을 심코어 statusUI가 그대로 따른다.**

## 2. 단계 계획

### P1 — 코어 스키마 (`얼헌/hunter-vars.js` 생성기)

- 변수: 날짜/시각/장소, 레벨/EXP/스탯포인트, HP/MP/SP(파생 max), STR/CON/AGI/INT/SEN,
  랭크(파생: 주스탯 구간), 원화/코인, 클래스/장비 슬롯(무기2/장신구2/방어구1/아이템2),
  스킬 목록, 퀘스트 목록, 기능 토글(stats/lore/clock/faction… 원본 시작 변수 승계).
- 게임 규칙(EXP 공식, max 공식, 레벨업 포인트)을 checks/derived로 — 루아 강제 로직 소멸.
- statusUI: 원본 CSS 규격으로 상태창 렌더 (마커 방식이라 정규식 렌더 계열 소멸).
- 시스템 메시지: 심코어 통지/로그가 대체.
- 로어북 다이어트: always-on 8종 삭제, 세계관·아이템·신격 등 정적 항목 존치.

### P2 — NPC 레지스트리 + 랭크 게이팅

- 48명 메타(랭크·역할·소속·한 줄 요약)를 생성기 데이터로. 변동 정보만 변수화
  (`npc_<id>` 압축 문자열 1개/명 — 예: `"A|Dealer|흑사|스킬메모"`, 목록 항목 규칙 준수).
- 게이팅: 유저 랭크 파생값 기준 ±1 랭크 그룹 지시문만 노출(when 조건 6그룹).
  등장 중 인물(서사 감지 or 호감 변수 보유)은 랭크 무관 유지. 이벤트가 상위 랭크를
  끌어올 수 있음(게이트 브레이크에 S랭크 출동 등).
- 개별 로어북 항목은 존치하되 변동 정보 문장을 제거해 심코어와 이중 진실 방지.

### P3 — 서울 게이트 시스템

- 서울 권역 분할(강북/강남/도심/서남/동북 등 5~7구역) + 구역별 게이트 변수
  (등급·잔여시간·상태). randomEvents로 출현/공략/브레이크/변이 사이클.
- 헌터물 클리셰 이벤트: 던전 이변(히든 보스·이중 던전), 각성자 사건, 길드 스카웃,
  협회 소집, 암시장 접선, 언론 보도 — 원본 로어북 트리거 20종을 흡수·확장.
- 난이도 원칙 준수: 이벤트를 켜고 끄지 않고 문턱을 민다.

### P4 — 헌터넷 (신규 엔진 기능)

- 자체 구현 (LightBoard 미복사). 보드 상태는 채팅 페이로드/변수에 저장,
  **메인 모델 출력에는 싣지 않는다** → 컨텍스트 재전송 비용 소멸.
- 렌더: 사이드 패널(플러그인 iframe — 편집기와 같은 인프라). 글 목록/열람/댓글.
- 갱신: 턴 종료 시 보조모델이 보드 델타 생성(새 글 0~3개). 유저가 글쓰기/댓글 달면
  **채팅 인풋 없이 보조 호출만**으로 보드 갱신 — "진짜 커뮤니티" 실시간감.
- 메인 모델에는 "이번 턴 화제 요약" 한두 줄만 선택 주입(서사가 여론을 아는 통로).
- 스키마 옵트인 + 편집기 칸 (규칙 #3).

### P5 — 배포 정리

- 에셋 팩(v0.94) 이식, 카드 인사말/첫 장면, 신안.json 규격 문서, 아카 배포 원고.
- ⚠ 원본 얼터헌터는 타인 저작 봇 — **배포 전 원작자 허락 확인** (개인 사용은 무방).
  헌터넷 개념 출처(LightBoard) 표기 권장, 코드는 무관한 자체 구현임을 명시.

## 3. 새로 필요한 엔진 기능 (P4에서)

1. **보드 저장소**: 채팅 진행과 동기화되는 구조화 상태(리롤 시 되감기) — 마커 페이로드
   인프라 재사용 검토.
2. **사이드 패널 등록**: 편집기 패널과 별개의 상시 보드 패널.
3. **채팅 없는 보조 갱신**: 패널 버튼 → 보조 호출 → 보드 상태만 갱신 (turnBusy 경합,
   aux user-turn 규칙 #2 준수).

P1~P3은 기존 심코어 기능만으로 구현 가능 — 신규 엔진 작업 없음.
