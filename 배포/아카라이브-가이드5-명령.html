0. AI가 틀렸을 때


2탄에서 AI한테 변수를 맡겼고, 3탄에서 시스템이 정산하게 했고, 4탄에서 유저가 버튼으로 개입하게 만들었음.


근데 아직 구멍이 하나 있음. AI가 잘못 넣었을 때 고칠 방법이 없음.


보조 모델은 서사만 읽음. 대부분 잘하는데 딱 한 종류를 자주 틀림 — 아직 얘기 중인 것과 이미 정해진 것을 구분하는 일.


…상인은 하루 열두 냥을 불렀다. 남작은 잔을 내려놓고, 며칠 생각해 보겠다고 했다.


아직 계약이 아닌데 AI가 계약 목록에 등록해버렸다고 치자. 이거 놔두면 맺지도 않은 계약에서 매일 돈이 들어옴. 3탄에서 배운 매 턴 자동 처리가 성실하게 돌기 때문임.


이런 건 빨리 안 고치면 복리로 어긋남. 40턴 지나면 뭐가 맞는 값인지 아무도 모름.


그래서 채팅창에 한 줄 쳐서 바로 고치는 기능이 있음.


/계약- 양모


패널 안 열고, 편집기 안 들어가고, 채팅 치던 자리에서 그냥 침.



1. 근데 이거 기본으로 안 켜져 있음


중요한 부분임. 템플릿 9개 전부 명령이 0개로 나옴.


액션은 템플릿에 이미 들어있어서 아무것도 안 해도 버튼이 떴는데, 명령은 안 그럼. 플러그인이 정해놓은 고정 명령 같은 건 없고, 봇 제작자가 변수마다 이름을 붙여야 그 이름의 명령이 생김.


그래서 /계약 같은 건 정해진 이름이 아님. 현대물이면 /잔고, 학원물이면 /친밀도가 되는 식임. 제작자가 아무 데도 안 붙였으면 그 봇엔 명령이 하나도 없음.



2. 명령 붙이기


봇 편집 > 명령 탭으로 들어감.


[스샷: 명령 탭 전체]


아래쪽 [— 명령을 붙일 변수 —] 에서 변수를 고르고, 이름만 적으면 끝임.


[스샷: 변수 고르고 이름 적는 부분]


문법은 적을 필요가 없음. 변수 타입이 알아서 정해줌. 이름만 붙이면 그 아래에 쓰는 법이 바로 뜸.


목록  /계약 내용 — 목록에 넣는다
           /계약- 내용 일부 — 목록에서 뺀다

숫자  /금 +5 — 지금 값에서 더하거나 뺀다 (-5도 됨)
           /금 30 — 부호가 없으면 그 값으로 지정

선택지  /날씨 맑음 / 비 / 눈 — 선택지 중 하나로

ON/OFF  /기근 on — 켠다 (끄려면 off / 0 / false)

텍스트  /위치 내용 — 적은 그대로 넣는다


이름 규칙 세 개만


- 공백 / "/" / "-" 는 이름에 못 씀 (인자랑 구분이 안 됨)
- 이름이 겹치면 안 됨
- 파생 변수엔 못 닮 (계산 결과라서)



3. 뭐부터 열어야 하나


전부 다 열 필요 없음. 기준은 하나임.


틀렸을 때 복리로 어긋나는 것부터.


- 지속 수입·계약·봉급 같은 목록  →  1순위. 잘못 등록되면 매 턴 돈이 새거나 빠짐
- 금화·식량 같은 재고  →  2순위. 한 번 어긋나면 계속 어긋남
- 기분·날씨 같은 건  →  굳이 안 열어도 됨. 다음 턴에 AI가 알아서 덮어씀


명령 탭도 목록형 변수를 맨 위로 올려서 보여줌. 거기가 제일 급한 자리라서 그럼.



4. 목록에서 뺄 땐 일부만 쳐도 됨


이게 은근히 중요함. 목록에 실제로 들어가 있는 값이 이렇게 생겼다고 치자.


헤세 상단 양모 +12 @1093


뒤에 붙은 @1093은 시스템이 굳힌 날짜값이라 유저가 알 방법이 없음. 이걸 다 맞춰 쳐야 지워진다면 사실상 못 지우는 거임.


그래서 일부만 쳐도 찾아줌.


/계약- 양모

→ (시스템: 지속 수입 제거 — 헤세 상단 양모 +12 @1093)


그리고 여러 개가 걸리면 아무거나 안 지움. 후보를 보여주고 되물어봄. 조용히 엉뚱한 걸 지우는 게 제일 나쁘기 때문임.


확인 문구도 유저가 친 말이 아니라 실제로 지워진 항목을 돌려줌. 그래야 맞게 지워졌는지 알 수 있음.



5. ⚠ 이걸 빠뜨리면 아무도 못 씀


명령을 아무리 잘 열어놔도, 유저는 그 봇에 무슨 명령이 있는지 알 방법이 없음. 이름은 제작자가 마음대로 정한 거니까.


그래서 상태창에 {commands} 를 박아둬야 함. 그 자리에 접이식 명령 모음집이 그려짐.


[스샷: 상태창 아래 접힌 명령 모음집 / 펼친 모습]


▸ ⌨ 채팅창에 칠 수 있는 명령 13가지    ← 평소엔 접혀서 한 줄


펴면 그 봇의 명령이 문법까지 전부 나옴. 유저가 명령의 존재를 알 수 있는 자리는 여기뿐임.


2탄에서 배운 커스텀 HTML 템플릿을 쓰고 있으면 원하는 위치에 {commands} 를 직접 박으면 되고, 자동 구성(그룹)을 쓰고 있으면 맨 아래에 알아서 붙으니까 아무것도 안 해도 됨.


명령을 열어놨는데 {commands} 가 없으면 명령 탭이 이렇게 경고해줌.


⚠ 명령을 열어 뒀는데 상태창 어디에도 {commands} 가 없습니다. 지금은 유저가 명령의 존재를 알 수 없습니다.


참고로 commands 라는 id의 변수를 만들면 이 자리표시자를 가려버려서 명령 모음집이 안 나옴. 검증이 경고해주긴 하는데 그냥 그 이름을 피하는 게 편함.



6. 이것도 AI한테 시킬 수 있음


명령 탭에도 규격 내보내기가 있음. "어떤 변수에 무슨 이름을 붙일지"를 AI가 짜줌.


[스샷: 명령 탭 맨 위 내보내기 버튼]


이 봇에서 유저가 직접 고칠 만한 변수에 명령 이름 붙여줘. 짧고 직관적인 한국어로


받은 거 붙여넣고 [📥 가져오기] → [설치/업데이트].


여기는 다른 탭이랑 다르게 이름 배정만 얹히고 변수 자체는 안 건드림. 명령이 별도 목록이 아니라 변수에 붙은 속성이라서 그럼. 그래서 3탄·4탄에서 겪은 "나머지가 날아가는" 사고가 여기선 안 남.



정리


명령은 기본이 0개  제작자가 변수에 이름을 붙여야 생김

문법은 자동  변수 타입이 정함. 이름만 붙이면 됨

1순위는 목록  계약·수입처럼 틀리면 복리로 어긋나는 것부터

{commands} 필수  없으면 유저가 명령의 존재를 모름


여기까지 하면 한 바퀴가 다 돌았음.


AI가 서사 읽고 값을 바꾸고(2탄), 시스템이 매 턴 정산하고(3탄), 유저가 버튼으로 개입하고(4탄), 틀리면 한 줄로 고침(5탄).
