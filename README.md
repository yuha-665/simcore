# SimCore — RisuAI 시뮬 엔진 플러그인

리수AI / 포켓리수용 시뮬레이션 엔진 플러그인. 스키마 하나로 변수·파생·규칙·이벤트·상태창을 정의하면
메인 모델에는 상태 블록을, 보조 모델에는 갱신 지시를 내보낸다.

```
.claude/skills/simcore/  개발·유지보수 레퍼런스 스킬 (Claude용)
```

## 베리디아 남작령

폐허가 된 변방 남작령을 일으키는 영지 경영 RP. 스키마를 JSON으로 직접 쓰지 않고
**생성기 스크립트로 만들어 낸다** — 달력·축일·탐사·배역·고용 표가 전부 코드 안의 표라서
숫자 하나를 고치면 변수·파생·규칙·프롬프트·상태창이 한꺼번에 따라온다.

```bash
cd 베리디아
node estate-vars.js        # → 영지-변수상태창-신안.json 재생성 + 검증 + 진단 + 데모
```

출력 끝의 `검증: 통과`와 `미치환 자리표시자: ✓ 없음`을 확인할 것. 이 둘이 깨지면 임포트해도 안 뜬다.

| 파일 | |
|---|---|
| `estate-vars.js` | 생성기. **여기만 고친다** |
| `영지-변수상태창-신안.json` | 생성물. 리수에 임포트하는 것 |
| `영지-규칙이벤트-탐사.json` | 규칙/지시문 탭만 따로 뽑은 것 |
| `simcore-save-영지.json` | 이전 세이브. 상태창 CSS를 여기서 읽어 온다 |

### 고치는 자리

생성기 위쪽의 표들이 이 봇의 설정 전부다.

| 표 | 무엇 |
|---|---|
| `EXPLORE` | 방향 4개 × 발견 자리 5개. 자리 종류 배분이 그 방향의 정체성 |
| `CAT` | 자리 종류가 서사에게 건네는 문구 |
| `FEST` | 축일 12종 (달, 일, 이름, 그날이 어떤 날인지) |
| `NEIGH` | 이웃 영지 5곳 (방위, 이름, 거리, 초기 우호도) |
| `CAST` | 인물 26명 (호감도 · 고용 등급) |
| `TIER` | 등급별 몸값·명성 문턱·일 봉급 |
| `POLICY` | 노동 배분 4종의 경작/건설/경비/탐사 비율 |
| `rules.randomEvents.table` | 랜덤 사건 31종 |
| `setup.presets` | 시작 프리셋 2종 (보통 / 절망) |

### 채팅 명령

변수에 `cmd`를 달면 `/이름`이 열린다. 문법은 안 적는다 — 변수 타입이 정한다
(목록이면 `/계약 …` 등록 · `/계약- …` 제거, 숫자면 `+5` 증감 / `5` 지정).

**명령 이름은 이 스키마가 정하므로 유저가 그걸 알 곳은 상태창뿐이다.**
그래서 상태창 템플릿 끝에 `{commands}`를 박아 뒀다. 빼면 유저는 명령의 존재를 모른다.
편집기 **명령 탭**에서 붙이고 뗄 수 있고, `{commands}`가 빠져 있으면 그 탭이 경고한다.

### 난이도

프리셋은 **변수 초기값만** 바꾼다 — `chancePerTurn` 같은 스키마 상수는 못 건드린다.
그래서 "나쁜 일이 얼마나 자주 오나"를 변수 하나로 옮겼다.

| 변수 | | 보통 | 절망 |
|---|---|---|---|
| `hardship` | 나쁜 일의 문턱을 민다 | 35 | 85 |
| `hire_mult` | 몸값·봉급 배율 | 80% | 150% |

`thr(변수, 연산, 시련0에서, 시련100에서)`가 그 문턱을 만든다. **사건을 켜고 끄는 게 아니라 문턱을 민다** —
보통에서도 역병은 오고, 정말 앓아누웠을 때만 올 뿐이다. 켜고 끄면 보통은 300턴을 굴려도 그 사건을 못 본다.
좋은 일은 반대 방향이라, 절망에서 행운이 사라지는 게 아니라 걸릴 만큼 뭔가를 세워 놔야 걸린다.

생성기 끝의 프리셋 표 넷을 반드시 보고 고칠 것. 특히 **손을 쓰면** 표 —
방치 표만 보면 절망은 그냥 고장 난 판으로 보이는데, 실제로는 첫 두 수(먹을 자리 · 물자리)를 두면 살아난다.
그 둘 중 하나만 두면 못 산다. 목줄은 식량이 아니라 **식수**다(우물 0이면 취수가 인구의 0.9배뿐).

### 상태창 배치 (`statusUI.layout`)

그룹이 넷을 넘어가면 세로로 쌓인 상태창이 한 화면에 안 들어온다. 배치를 바꾼다.

| 값 | |
|---|---|
| `stack` | 기본. 전부 세로로 쌓기 |
| `tabs` | 한 번에 한 장. 그룹 이름이 탭 이름이 된다 |
| `accordion` | 접기/펼치기. **여러 장을 동시에 펴 둘 수 있다** |
| `popover` | 버튼을 누르면 그 장만 떠오른다 |

편집기 **상태창 탭 → [그룹 배치]**에서 고른다. `tabs`·`popover`는 보이는 그룹이 둘 이상이어야
동작하고, 하나뿐이면 조용히 `stack`으로 돌아간다(검증이 경고한다).

**전환은 전부 CSS로만 돈다.** 메시지 안의 버튼은 리스가 클릭 이벤트에서 `target`을 잘라 넘겨서
어느 것이 눌렸는지 알 수가 없다 — 그래서 탭은 라디오+라벨, 팝업은 `tabindex`+`:focus-within`이다.
그 대가로 **새 턴이 오면 최신 메시지의 탭 선택이 첫 탭으로 돌아간다**(지난 메시지는 그대로 남는다).
그게 거슬리면 `accordion`을 쓴다 — 펼침 상태가 같은 이유로 돌아가긴 하지만 여러 장을 동시에 볼 수 있다.

직접 뜯어고치려면 편집기 **표시 방식 → 커스텀 HTML 템플릿**에서 `[탭 뼈대 넣기]`를 누른다.
그 봇의 그룹·변수가 이미 채워진 HTML+CSS가 나온다. 탭 뼈대에는 `{uid}`가 들어 있는데,
**이건 지우면 안 된다** — 상태창은 마커가 달린 메시지마다 그려지므로 id를 고정하면 같은 id가
여러 개 생기고, `<label for>`은 문서에서 처음 만난 것을 집는다. 최신 글의 탭을 눌렀는데
맨 위 글의 탭이 바뀐다. `{uid}`는 그 메시지 번호다.

### 설계 원칙

- **로어북 = 안 변하는 것**(설정·이유·어휘), **변수 = 플레이가 남긴 흔적**.
  로어북에 "At the start …"이라고 적히는 순간 그건 변수 자리다.
- **시스템은 "무엇이 나올 차례"까지, 그게 뭔지는 서사가.** 탐사 발견도 계약도 같은 구조다.
- **지시문은 AI가 모르는 것만 말한다.** 상태 블록을 되풀이하거나 행동을 강제하면 뺀다.
- **자주 변하는 숫자는 목록 항목에 넣지 않는다.** 목록의 끝자리 숫자는 안 변하는 값 전용
  (봉급·수용 인원·경작 적성). 호감도처럼 매 턴 움직이는 값은 int 변수로.
- **금화 상한은 비대칭이다.** 지어낸 수입은 경제를 영구히 망가뜨리지만(maxGain 500),
  손실은 min 0이 받쳐 준다(maxLoss 7000 — 고용비·세납이 이 아래여야 실제로 빠진다).
