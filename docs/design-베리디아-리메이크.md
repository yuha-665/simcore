# 설계 — 베리디아 리메이크 (신안 v2)

> 2026-08-15. 유저 발제: "심코어도 많이 발전했으니 영지-변수상태창-신안.json도 업그레이드할 때가
> 됐다. 초기에 만든 거라 상태창에 거의 모든 걸 우겨넣었는데, 패널로 뺄 건 빼는 식으로 정리부터.
> 제대로 된 영지 운영 기능 설계 + 26명 전캐릭 호감도 관리 + 메이드/수녀(고용인)는 능력 디테일,
> 귀족은 우호도 중심으로 분리 + 패널 CSS를 상태창 CSS에 맞추기. 작업이 방대하니 플랜부터."
> **미구현 — 플랜 문서.**

## 0. 진단 — 신안 v1이 어느 시절 물건인가

신안.json(115KB)은 v0.4x 초기 산물이다. 실측: vars 90 · derived 111 · events 20 ·
**actions 0 · checks 0 · party 없음 · time 섹션 없음 · 에셋 없음.**

| 그 뒤에 생긴 기능 | 버전 | 신안 v1 |
|---|---|---|
| 판정 (완벽 주사위) | v0.40 | 안 씀 — 탐사·외교가 전부 서사 임의 |
| 갈림길 choices | v0.41 | 안 씀 |
| 상태창 클릭 조작 | v0.42 | 액션이 0개라 해당 없음 |
| time 1급 (flat30 달력) | v0.49 | 수제 360일 달력 (derived ~20개로 자작) |
| 게임 패널 (편성표·탭·초상·업그레이드) | v0.55~0.59 | 안 씀 |
| 에셋팩 | v0.6x~0.88 | 안 씀 |

상태창은 모달 하나에 **17개 섹션**: 연대기·환경 / 탐사 4방향 / 달력 / 인구·노동 /
재정·경제(계약·수입 목록 포함) / 경작지 / 자원지 / 인프라 / 민생·보안 6지표 / 왕위 계승 /
주변 영지 5곳 / 고용인·유대 / 인물 호감도 26명(4줄 이어붙임 문자열) / 교역·인맥 /
집중 목표 / 긴급 통지 / 명령 범례. **매 메시지마다 이 전부가 다시 그려진다.**

인물은 b_* 스칼라 26개(mentions 게이트)가 전부다. 고용인의 능력·배치라는 축이 없고,
귀족의 "영지 대 영지"(rel_*)와 "사람 대 사람"(b_*) 분리는 이미 잘 되어 있다.

## 1. 방향 — 네 문장

1. **상태창은 "오늘 아침 책상 위 한 장"** — 매 턴 변하고 매 턴 봐야 하는 것만.
2. **패널은 "서고의 대장(臺帳)"** — 열었을 때만 보는 참고 자료: 인물 대장, 영지 대장, 탐사 지도.
3. **인물은 두 부류가 다른 사물이다** — 고용인은 *운용*하고(배치·숙련·봉급), 귀족은 *상대*한다(우호·빚).
4. **개방 원칙 (유저 확정, 2026-08-15): 영지 발전 수단은 절대 규격화하지 않는다.** 아이돌 봇과
   달리 이 봇을 열린 목록(contracts·sites·stock)으로 지은 건 의도다 — "여존남비 세계관에서
   전라 스모 흥행으로 영지를 부흥시킨" 플레이처럼, 유저 상상력은 제작자가 예상 못 할 사업을
   만든다. 시스템이 지키는 선은 하나뿐: **종류는 무제한, 크기만 유한** (금화 비대칭 상한).
   따라서 사업 종류 열거(목장/광산/여관 카탈로그)는 영구 금지. 액션은 보편 행정 스위치만
   (배급·척후·축일·훈련), 판정은 시도의 이름을 모른 채 성패만 굴린다. 배치 보너스도 "정답
   배치"가 생기지 않게 완만하게.

## 2. P1 — 엔진 확장: 패널 대장(臺帳) 탭 (플러그인 쪽, 선행 필수)

**갭**: 게임 패널 탭의 콘텐츠는 `slots`(편성) · `actions`(버튼) · `items`(업그레이드) 3종뿐
(validate.js 실측). 자유형 정보 표시가 없어 **상태창 섹션을 옮길 자리 자체가 없다.**

제안: `party.tabs[].template` — 상태창과 같은 자리표시자 HTML.

**+ 탭별 플로팅 버튼** (유저 채택, 2026-08-15): 다른 봇 UI 스크린샷 제시 — 화면 가장자리의
동그란 아이콘 버튼(📋·🕐)이 각각 종이 문서풍 카드 팝업을 연다. 우리 대응물:
`party.tabs[].fab: '아이콘'` — 지정한 탭은 우상단 유틸 버튼 줄에 **자기 버튼이 따로 생기고**,
누르면 게임 패널이 **그 탭으로 바로** 열린다. registerButton 통로는 이미 있고(편성표 버튼),
버튼 n개 등록으로 확장만 하면 된다. 카드처럼 보이는 건 P5 CSS 몫 (패널 껍데기를 종이 카드로).

- 렌더는 `renderStatusHtml` 재사용 (자리표시자 `{var}` `{list:tags}` 이미 있음). 새 기계 없음.
- CSS는 기존 `party.css` 통로 그대로 (`scopeCss(css, '#sc-game')`).
- 패널은 우리 iframe DOM이라 x-risu- 접두·좌표 히트테스트 문제가 처음부터 없다.
- template과 slots/actions/items **공존 허용** (탭 하나에 설명문+편성 같이) — 단 순서는 template 먼저.
- 검증: 미치환 자리표시자 경고, statusUI template과 같은 규칙 재사용.
- **편집기 칸 필수** (규칙 #3 editor parity) — 편성표 탭의 탭 편집 UI에 template 텍스트영역.
- 갱신 시점: 패널이 떠 있는 동안 턴이 돌면 다시 그리기 (편성표가 이미 하는 방식 따름).

이 한 조각이면 인물 대장·영지 대장·탐사 지도 전부 봇 스키마(템플릿)로 그린다 —
엔진에 "인물 전용 뷰" 같은 걸 박지 않는다. **v0.89 후보, 별도 커밋으로 먼저 출고.**

## 3. P2 — 상태창 다이어트 (신안 쪽)

| 남긴다 (매턴 한 장) | 패널 대장으로 뺀다 |
|---|---|
| 날짜·시각·계절·날씨·위치·재해 | 탐사 4방향 상세 + 척후 현황 → **탐사 지도 탭** |
| 국면(phase) + 식량·식수·금 **수지 요약 3줄** | 계약·수입·물자·경작지·자원지·인프라 목록 전부 → **영지 대장 탭** |
| 민생·보안 **요약 1줄** (사기·보건·불안·위협 텍스트) | 6지표 개별 항목·노동 배분 상세 |
| 예정 + 다음 축일 **1줄** | 축일 설명·고용 시세표 → 대장 |
| 집중 목표 · 긴급 통지 | 왕위 계승 판세 · 주변 영지 5곳 · 교역·인맥 |
| 명령 범례 (접힘, 유지) | 인물 호감도 26명 → **인물 대장 탭** |

기대: 매 메시지 렌더 HTML이 지금의 1/4 수준. 모달("영지 보고서 확인" 버튼) 구조는 유지하되
내용물이 짧아진다. 상태창에서 빠진 항목도 **변수·파생은 그대로**라 프롬프트 블록(promptState)은
따로 손본다 — 화면에서 뺀 것과 모델에게 안 보내는 것은 별개 결정.

## 4. P3 — 인물 계층 재설계

26명 = 왕가·동행 5 + 귀족 5 + 광휘회 4 + 메이드 12. 호감도 b_* 26개는 **그대로 유지**
(mentions 게이트 포함 — 이 봇에서 검증된 설계다). 그 위에 부류별 축을 더한다.

### 4-1. 고용인 15명 (메이드 12 + 광휘회 3) — "운용하는 사람"

- **능력 프로필은 고정값** — 변수가 아니라 스키마 상수(생성기 표)로. 등급(J/I/S/E)이 기본기를
  정하고, 개인차는 특기 1~2개. 대장 탭 템플릿과 로어북에 실린다.
  *안 변하는 것은 변수 자리가 아니다* (설계 원칙 그대로).

  **특기 배정안 — 로어북 실측 기반** (카드 `영지부활 프로젝트6.jpeg`의 Core Ability 줄에서 추출,
  2026-08-15). 직무 슬롯 6종: 가사 / 호위 / 행정 / 의무 / 탐사 / 건설 (+대기).

  | 인물 | 등급 | Core Ability (로어북) | 주특기 | 부특기 |
  |---|---|---|---|---|
  | 유스티나 | E | 만능 마법 + CQC, 메이드장 | 호위 | 가사 (만능 — 어디 놓아도 보너스 절반) |
  | 알제리아 | E | 대지 연금(무구 변성) + 기사도 | 호위 | 건설 (돌·목재 변성) |
  | 리리카 | E | 전격 · 신속("Flash") | 탐사 | 호위 |
  | 클라리스 | S | 염동력 — 다중 정밀 조작 | 가사 | 건설 |
  | 카시아 | S | 정신 마법 + 첩보 | 행정 | — (게으름: 로테이션 없이 두면 과로 대신 태업 서사 여지) |
  | 루루 | S | 신체 강화 (괴력) | 호위 | 건설 |
  | 라라 | S | 빙결 — 방벽 · **식량 보존** | 가사 (곳간 부패 방지 → 식량 소비 절감) | 호위 |
  | 리비아 | I | 바람 궁술 | 탐사 | 호위 |
  | 피오라 | I | 소형 변성 (수리 — 깨진 것 복원) | 건설 (인프라 유지) | 가사 |
  | 메릴 | I | 물 마법 + 가사 달인 + CQC | 가사 | 의무 (돌봄) |
  | 필리아 | J | 화염 (부엌일 응용) | 가사 | — |
  | 세리에 | J | 잠재 대지 마법, 활력 | 탐사 | 가사 |
  | 라피스 | S 수녀 | 상급 신성 회복 + 위무 | 의무 | — |
  | 셀레스티아 | I 수녀 | 신성 치유 + 정화 | 의무 | 가사 |
  | 스텔라 | J 수녀 | 소치유 + **사기 진작** | 의무 (보건보다 사기 쪽 보정) | — |

  직무→지표 연결: 가사→사기·식량 효율 / 호위→외부보안·위협 / 행정→세납·계약·내부 불안 /
  의무→보건 회복 / 탐사→척후 속도 / 건설→공사 속도(건설 큐와 맞물림). 주특기 배치 = 온보너스,
  부특기 = 절반, 무특기 = 등급 기본치만.
- **변하는 것만 변수로**:
  - `duty_*` 배치 — **편성표 슬롯** (enum): 가사 / 호위 / 행정 / 의무 / 탐사 / 대기.
    슬롯 5~6개, roster = corps 목록 → 고용 안 한 사람은 후보에 안 뜬다 (v0.55 규약 그대로).
  - 배치 보너스 — 파생으로 지표에 연결 (행정에 행정 특기 → 세율·계약 효율, 의무에 수녀 → 보건 회복↑).
    **편성이 처음으로 숫자에 닿는다** — 이게 "능력 디테일 관리"의 실체다.
  - `skill_*` 숙련 — 패널 업그레이드 items (int 0~5, points = 훈련 포인트). 인물별 탭은
    `when: has(corps, '이름')` — v0.59 탭 조건이 정확히 이 용도로 만들어졌다.
  - 컨디션 — 전원 개별 int는 과하다. **과로 카운터 하나** (배치 로테이션 없이 오래 두면 사기·이탈
    리스크) 정도로 시작, 실플 보고 확장.
- 인물 대장(고용인 면): 초상(에셋, 있으면) · 등급 · 봉급 · 배치 · 숙련 · 호감도 한 줄씩.

### 4-2. 귀족·왕가 8명 + 베아트릭스 — "상대하는 사람"

- 능력치 추적 안 함 (유저 확정: "개인 능력변화를 기록하기엔 별로 안 맞으니").
- 축 셋: **rel_*** (영지 대 영지, 기존) · **b_*** (사람 대 사람, 기존) · **favors** (신설 list) —
  빚·약속·거래 ("모르웬에게 곡물 200 빚짐 @+30", "실바나에게 항구 통행 약속"). 목록 규약
  `@+N` 만료가 이미 있으니 기한 있는 약속은 자동으로 셈해진다.
- 대장(귀족 면): 이름 · 거리 · rel 단계 텍스트 · b_* · 걸린 favors.
- 왕위 계승 판세(pw_*)도 이 면으로 이동.

### 4-3. 아데레 (동행)

지금의 ally/ally_bond 특별 취급 유지 — 상태창 잔류 후보 (매턴 옆에 있는 사람이니까).

## 5. P4 — 운영 기능 (본편)

느슨한 순서 — 각각 독립 커밋 가능:

1. **판정(checks) 도입** — 탐사 성과·외교 담판·공사 사고에. 지금은 전부 서사 임의라
   "잘됐는지"를 AI 기분이 정한다. 판정이 그 자리를 가져온다. 이 봇의 원칙
   ("이 값을 AI가 매 턴 머리로 굴려야 하나?")의 연장.
2. **건설 큐** — `projects` list + `@N` 만료 = 완공. 완공 이벤트가 infra/farms에 옮겨 심으라고
   통지. 지금은 "짓기 시작했다"와 "다 지었다" 사이가 없다.
3. **액션 도입** — 현재 0개. 노동 배분 전환·척후 파견·훈련 지시 같은 반복 지시를 버튼으로.
   v0.42 상태창 클릭 조작이 이 봇엔 아직 한 번도 안 쓰였다.
4. **time 1급 이행 — ✅ 완료 (2026-08-16)** — flat30, 시작 1499-03-01. 날짜 표가 수제 달력과
   한 눈금도 안 어긋남을 실측 (1년=360일·축일 12종·계절 0불일치). 핵심 변화:
   - **진행 explicit**: days_passed → skip_day. 0이면 날짜도 정산도 멈춘다 — 같은 날 안의
     장면 여러 턴이 며칠씩 흐르던 "1아웃풋=1일" 왜곡(design-시간.md 제보) 해소.
   - **day는 거울 변수** (파생 별칭 금지 — lookup이 vars 우선 + reconcile이 잉여 키를 안
     걷어서, 구세이브의 옛 vars.day가 별칭을 영구히 가린다). onTurn 첫 규칙이 elapsed로 동기화
     — 구세이브도 첫 턴에 스냅, span 폭주 없음 (실측 3케이스).
   - 🕐 달력 패널: 축일 12종 기념일 + 계약·공사 기한 점. 일정 목록은 안 담 (appt 존치).
   - ⚠ 이행 비용: **진행 중이던 세이브는 날짜가 개막일(1499-03-01)로 스냅**된다 (epoch가
     새로 시작). 수치·호감도·목록은 전부 유지.
5. **랜덤 이벤트 확충** — hardship 문턱 방식 유지, 인물 계층(배치·favors)과 얽힌 사건 추가
   (행정 담당이 비면 세납 사고, favors 만기 도래 이벤트).

### 14-4. 4차 구현 — 혼담 (2026-09-27, 유저 "넘어가줘")
§14 합의 "번영할수록 가문들이 차지하러 온다. 수락 → 그 가문 편, 거절 → 원한, 보류 → 기한" 그대로. 전부 [초안] 수치.
**원본 근거**: 정조역전 — 여자가 원하는 남자를 "차지"하고 책임진다, 남자에게 가장 큰 영예는 강한 여자에게 선택받아 보호받는 것 ·
여왕 "외교 혼담은 책상에서 밀어낸다"(그래서 여왕은 청혼인이 아니다) · 실바나 "누구와 혼인해야 하는지 정해 주는 것"을 싫어함 ·
엘레오노라 "남자를 데려가는 건 협상이 아니라 차지하는 것" · 리아나 빚과 무너진 부두 · 발레리우스 효율(남쪽의 흡수).
- **청혼인 여덟** (SUITORS 표 하나에서 전부 굽는다): 이웃 넷(그 영지의 인식 35↑ 또는 그 사람 호감 25↑ — 실바나만 제 호감 30↑로만) ·
  엘레오노라 공작(지지의 무게 25↑ + 왕도 30↑ 또는 호감 25↑) · 왕녀 셋(왕도 35↑ · 무게 30↑ + 그 왕녀를 지지하거나 호감 25↑, 중립이면 선두 왕녀).
  공통: 명성 30 · 90일 이후 · 한 번 오면 75일은 조용(래치) · 길이 열려 있을 때 · 차지된 뒤엔 아무도 안 온다. 랜덤 사건(가중 2, 쿨 180).
- **갈림길**: 받아들인다(혼약 — 그 영지 인식 +10 · 그 사람 호감 +12 · 예순 날 뒤 혼례) / 정중히 물린다(−6 · −8, 엘레오노라 −12 —

  물렸으니 −8 · −10, 이번엔 미룰 수 없음)).
