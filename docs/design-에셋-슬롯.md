## 문제 진단

감정 이미지를 쓰는 봇은 매 턴 프롬프트에 이런 걸 싣는다 (실측: 맨션봇 8인 봇):

1. **`{{assetlist}}` 통짜 덤프** — `{{join::{{filter::{{assetlist}}::unique}}::{{br}}}}`.
   에셋이 인물 8 × 표정 70이면 **560줄**. 아래 키워드 목록 전체보다 무겁다. 매 턴.
2. **수동 키워드 목록** — 인물 8 + 표정 70 + 성적 45 + 지침 문단. 700~900토큰 추정. 매 턴.
3. 성적 키워드는 대부분의 턴에서 완전한 낭비인데도 상시 실린다.
4. **모듈 생태계**: 요즘 봇은 모듈로도 배포되니 캐릭터마다 자기 이미지 지침을 들고 온다.
   이미지 개수도 감정 목록도 출력 형식도 달라서 **같이 쓰면 찐빠를 감수해야 하고**, 지침 토큰은
   봇을 추가할 때마다 는다. 원인은 각 모듈이 **프로즈로 자기만의 사설 규약을 AI에게 가르치기**
   때문이다 — 문맥에서 서로 싸운다.

**핵심 통찰(유저): 조합(C×E)을 슬롯(C+E)으로 바꾸면 목록이 곱셈에서 덧셈이 된다.**
8×70 = 560 → 8+70 = 78. 감정·성인 키워드는 인물과 무관한 **공용 축**이라 한 번만 적으면 된다.

> **실측 (2026-08-01, 실기 확인)**: 선라이즈 맨션의 에셋 출력식이 **매 턴 14,000토큰**이었다
> (위 어림 700~900의 15배 — 어림은 지침 문단만 셌고 실물은 assetlist 덤프가 지배했다).
> 팩 전환 후 **main 모드로도 전체 프롬프트 35,000 → 19,000토큰 (-46%)**. aux 모드면
> 팩 목록마저 메인에서 빠지므로 더 줄어든다.

**그리고 emit을 SimCore가 소유하면 AI는 어떤 규약도 배울 필요가 없다** (`aux` 모드에서는
"누가·어떤 감정"만 보고). 4번이 풀리는 지점이 여기다 — 지침 블록 N개가 데이터 레지스트리 1개가 된다.

## 확정 사실 (구현 전 조사 완료)

- **output 핸들러가 저장 본문을 반환한다.** `addRisuScriptHandler('output', ...)`가 `content`를
  돌려주는 구조이고, 지금도 여기서 `⟦simcore:N⟧` 마커를 붙인다 (risu-plugin.js ②③ 구간).
  → **본문 앞/사이에 `<img="...">`를 심는 건 이미 가능한 일.** 유저가 걱정한 "아웃풋 수정" 능력이 이미 있다.
- **보조 호출이 그 핸들러 안에서 await로 끝난 뒤 content가 반환된다.** 즉 보조가 고른 값을
  **그 턴 본문에** 넣을 타이밍이 확보돼 있다. suggest(v0.43)가 정확히 이 경로.
  → 상태 갱신 호출에 피기백하면 **추가 LLM 호출 0**.
- **플러그인이 에셋 목록을 읽을 수 있다.** `Risuai.getCharacter()` → `additionalAssets:
  [이름, assetId, 확장자][]` (schemas.md). [live-test] 권한·실제 접근 확인 필요.
- **CBS로는 assetlist를 인물별로 못 거른다.** `{{filter::배열::all|nonempty|unique}}` 뿐 —
  "이름에 X가 든 것만" 필터가 없다. 즉 이 문제는 **CBS로 못 풀고 플러그인으로만 풀린다.**
- 표시 정규식(`<img="(.*?)">` → div)은 display 단계라 토큰과 무관. 그대로 둔다.

## 귀속 — 팩(pack)이 관리 단위다

> 2026-07-30 2차 논의. **만들기 전에 정해야 하는 건 스키마가 아니라 수명 관리다.**

문제는 배포 형태가 둘이라는 것:

| | 귀속 | |
|---|---|---|
| 기본봇 (캐릭터 카드) | 문제 없음 — SimCore 스키마가 그 봇 로어북에 있다 | |
| **모듈봇** | 귀속할 존재가 애매 | 하지만 **모듈도 결국 특정 봇에 붙여서 쓴다** → 그 **호스트 봇**의 스키마에 넣는다 |

호스트 봇 귀속이 유일하게 성립하는 답이다. 그 위에서, 서로 다른 출처의 이미지 규약이
공존해야 하므로 레지스트리의 단위를 **팩**으로 쪼갠다.

```json
"assets": {
  "by": "main",
  "packs": [
    { "id": "mansion", "source": "맨션봇 자체", "sep": "_",
      "format": "<img=\"{name}\">",
      "slots": [
        { "id": "who",  "label": "인물", "values": ["Hiromi", "Seiko", "…"] },
        { "id": "emo",  "label": "감정", "values": ["angry", "happy smile", "…"] },
        { "id": "wear", "label": "의상", "optional": true, "values": ["…"] }
      ] },
    { "id": "mansion_nsfw", "source": "맨션봇 자체", "sep": "_",
      "format": "<img=\"{name}\">", "when": "nsfw_on",
      "slots": [ { "id": "who", "…": "" }, { "id": "emo", "values": ["…성인 키워드…"] } ] },
    { "id": "noz", "source": "노조미 모듈 v1.2", "sep": "-", "chars": ["Nozomi"],
      "format": "<char-noz emotion=\"{emo}\">",
      "slots": [ { "id": "emo", "label": "감정", "values": ["…12종…"] } ] }
  ]
}
```

- **칸 수 자유** — `slots` 길이가 곧 칸 수. 각 칸이 무엇을 관리하는지는 `label`이 정한다.
- `optional: true`인 칸은 빼고 조합해도 된다 (`인물_감정` / `인물_감정_의상` 둘 다 유효).
- `format`의 `{name}`에 조합 결과, `{칸id}`에 칸 값. **출력 규약이 모듈마다 달라도 팩이 흡수한다.**
- `sep`도 팩마다 따로 (`_` vs `-`).

### 왜 팩이어야 하나 — 감정 목록이 전부 달라도 되는 이유

**팩이 인물 공간을 분할하므로, 팩을 늘려도 목록은 여전히 덧셈이다.**

```
Σ(팩의 인물 + 팩의 감정) = (8+70) + (8+45) + (1+12) = 144줄
```

지금은 모듈이 늘 때마다 **지침 블록이 통째로** 붙고(곱셈보다 나쁘다 — 서로 충돌한다),
팩 방식은 데이터 행만 는다. 그리고 팩 id가 이름공간이라 **AI가 남의 모듈 감정 어휘를
잘못 집어올 통로 자체가 없다** — "같이 쓰면 찐빠"가 원리적으로 사라진다.

### 라우팅 키는 인물

보조가 "이번 장면 = Nozomi / angry"를 답하면 SimCore가 **그 인물을 담당하는 팩**을 찾아
그 팩의 `sep`·`format`·어휘로 조합·대조한다.

- 시뮬봇 팩: `who` 칸이 있고 그 값 목록이 담당 인물
- 단일 캐릭 모듈 팩: `who` 칸 없이 팩 레벨 `chars: ["Nozomi"]`가 담당 선언
- **두 팩이 같은 인물을 주장하면 먼저 선언된 팩 우선 + 검증 경고.** 조용한 덮어쓰기 금지
  (왕복 패치의 충돌 원칙과 같다)

### NSFW는 값 묶음이 아니라 팩 단위 게이트

성인 출력식은 어휘만 다른 게 아니라 **형식까지 다른 경우가 있다.** 그래서 칸 안의 값 묶음을
거르는 대신 팩을 하나 더 두고 팩 레벨 `when`으로 잠근다. 게이트가 닫히면 **그 팩이 프롬프트에서
통째로 빠지므로** 절감도 가장 크다. 조건은 기존 수식 문법 그대로 — 액션 무장(`hold`)이 가장 확실하다.

### 수명 관리 (모듈을 붙였다 뗄 때)

- **`source` 필수화 수준으로 권장** — 안 적으면 모듈을 뺀 뒤 어느 팩이 고아인지 알 수 없다.
  변수 고아 문제(v0.45 정리 마법사)와 같은 부류다
- **삭제가 아니라 켜기/끄기** — 모듈을 잠깐 뺄 때 팩을 지우게 하면 다시 만들어야 한다. 팩 토글
- **팩 단위 내보내기/가져오기** — 호스트 봇 귀속의 대가는 "같은 모듈을 다른 봇에 붙이면 다시 만들어야
  함"이다. 팩 JSON 조각 복사로 우회 (이 플러그인의 복붙 문화와 맞다)
- **진단 체크** — "이 팩이 선언한 조합 중 실물 에셋에 없는 것 N개" (오탐 0 확인 후 — v0.28 원칙)

### 진입장벽 — [모듈 지침 가져오기]

기존 봇의 이미지 지침 프로즈 + `{{assetlist}}` 출력을 붙여넣으면 **팩 하나로 변환**하고
"이제 로어북에서 그 블록을 지우세요"를 안내한다. 왕복 패치의 복사→붙여넣기→검사→적용 관례를
그대로 재사용. 이게 있으면 유저가 **남의 모듈도 직접 전환**할 수 있고, 아래 "기존 봇과의 공존"
(중복 주입) 문제도 같이 해결된다.

⚠ 한계: 남의 모듈이 SimCore를 안 쓰면 그 프로즈를 우리가 없앨 수는 없다. 생태계 채택 문제라
코드로 안 풀리고, 임포터가 그 우회로다.

## 세 가지 모드 — `by` (v0.54부터 3택)

| | `by: "aux"` | `by: "aux_flow"` (v0.54) | `by: "main"` |
|---|---|---|---|
| 메인 프롬프트 비용 | **0** | **0** | 열린 팩의 Σ(인물+감정) — 560→144 |
| 배치 | 메시지당 1개(맨 앞) | 서사 위치에 최대 3장 (앵커) | 문단 사이 자유롭게 여러 개 |
| 정확도 | 실존 대조 → 깨진 이미지 0 | 실존 대조 + 앵커 대조 | 모델이 조합 (대조 불가) |
| 추가 호출 | 0 (상태 갱신에 피기백) | 0 (동일) | 0 |

- **aux**: 보조 응답 JSON에 `"image": { "who": "Hiromi", "emo": "angry" }` 를 얹어 받고,
  SimCore가 담당 팩을 찾아 조합·대조해서 output 핸들러에서 본문 맨 앞에 삽입.
  **보조에게 팩 id를 고르게 하지 않는다** — 인물만 답하면 라우팅은 SimCore 몫이다
  (고를 것이 늘면 틀릴 것도 는다).
- **aux_flow**: `"images": [{ who, emo, "anchor": "본문 인용" }]` 배열로 받는다. 위치를
  서수("3번째 문단 뒤")가 아니라 **본문 인용**으로 받는 것이 핵심 — 인용은 본문에서
  찾아지거나(탐색 사다리: 정확 일치 → 공백 정규화 → 앞 12자), 못 찾으면 그 장을 안 놓으면
  그만이다. 실존 대조와 같은 원리: **검증할 수 없는 답은 받지 않는다.** 전패 시 첫 장을
  맨 앞에 (aux 단일로 강등 — 이미지 없는 턴 방지). 설계 초기에 다중 삽입을 접은 이유가
  서수의 어긋남이었는데, 실기 확인 중 유저 제안("첫 1장은 두고 서사대로도")으로 이 우회를 찾았다.
- **main**: 슬롯 목록 + 조합 규칙을 **지시문 형태로** 메인 프롬프트에 주입. 지금 손으로 쓰던
  블록을 SimCore가 대신 쓰되, 곱셈이 덧셈이 되고 `gate`로 안 쓰는 묶음이 빠진다.

**셋 다 지원한다.** 연출 밀도(문단마다 표정이 바뀌는 봇)와 비용·정확도 중 무엇을 살릴지는
봇마다 다르다. 대조까지 되면서 여러 장을 원하면 aux_flow, 가장 안정적인 건 aux.

## 슬롯 자동 감지 (편집기)

`[에셋에서 슬롯 자동 감지]` 버튼 — **팩 하나를 만드는 버튼이다** (전체가 아니라):
1. `getCharacter().additionalAssets`에서 이름만 뽑는다
2. `sep`으로 쪼개 **칸 수의 최빈값**을 잡고, 칸별 고유값 집합을 만든다
3. "1칸 8종 / 2칸 70종 / 3칸 4종" 으로 제시 → 유저는 **칸마다 이름표만** 단다
4. 칸 수가 들쭉날쭉하면(2칸·3칸 혼재) 짧은 쪽을 기준으로 잡고 나머지를 `optional` 칸으로
5. 구분자·칸 수가 **두 규약으로 뚜렷이 갈리면** 팩 두 개로 나눠 제시 (모듈 여러 개가 붙은 봇)

에셋을 못 읽는 환경이면 이 버튼만 비활성, 손으로 채우는 경로는 그대로 둔다.

## 실존 대조 (깨진 이미지 0)

슬롯 방식의 유일한 약점은 **비어 있는 칸 조합**이다 (Hiromi엔 있는 표정이 Seiko엔 없음).
**이게 "인물마다 이미지 개수·감정 목록이 다르다"의 해답이기도 하다** — 팩은 감정 축을
합집합으로 한 번만 선언하고, 인물별 차이는 대조가 조용히 흡수한다. 인물별 목록을 따로
적으려 들면 다시 곱셈이 된다.

**팩 단위 예외 (v0.54.6)**: `verify: false`면 그 팩은 대조 없이 정조합을 신뢰한다. 에셋이
모듈에 살아서 이름을 못 읽는 환경(실측: db 권한 잠긴 리수)용 — 이게 없으면 캐릭터 이름만 든
**부분 Set**이 모듈 팩 조합을 전부 걸러 그 팩의 이미지가 영영 안 나간다.

에셋 이름 집합을 Set으로 들고 있다가:
- `aux` 모드: 조합 결과가 집합에 없으면 **같은 인물의 폴백 감정으로 강등**, 그것도 없으면 삽입 생략.
  (폴백이 있으면 "이미지가 아예 안 뜨는 턴"이 사라져 연출이 끊기지 않는다)
- `main` 모드: 대조가 불가능하므로 주입문에 "확신이 없으면 태그를 생략하라"를 항상 깐다
- 폴백률이 높으면 진단이 알려준다 — 선언한 감정 축이 그 인물에겐 과대한 것이다

  suggest와 같은 제약. 문서에 명시하고, 브리지 모드에서는 `main`을 권장.
- **화자 판별.** `aux` 모드에서 "이번 장면의 주인공이 누구인가"를 보조가 골라야 한다.
  SimCore가 이미 아는 것(`*_spot` 같은 위치 변수)을 후보 좁히기에 쓸 수 있는지 검토.
  다만 슬롯 값과 변수를 잇는 배선(`from: "var:noz_spot"`)은 v1 범위 밖으로 둔다.
- **기존 봇과의 공존.** 손으로 쓴 블록을 그대로 둔 채 이 기능을 켜면 중복 주입이 된다.
  켤 때 "기존 이미지 지시 블록을 로어북에서 빼세요" 안내가 필요하다.
  → [모듈 지침 가져오기]가 변환 직후 이 안내를 띄우는 자리다.
- **표정 목록은 안 줄어든다.** 인물과 무관한 공통 축이라 쪼갤 축이 없다. 절감의 대부분은
  ① assetlist 덤프 제거 ② 성인 팩 게이트 ③ 곱셈→덧셈 에서 나온다.
- **[live-test] 모듈 로어북을 읽을 수 있나.** 지금 스키마 로드는 **현재 캐릭터 로어북의
  `⚙simcore` 항목 하나**뿐이다 (risu-plugin.js `loadForCurrentCharInner`). 모듈이 붙인
  로어북이 `char.globalLore`에 들어오는지 확인 필요 —
  - 들어온다면: 모듈이 자기 팩을 직접 싣고 SimCore가 스캔·병합하는 길이 열린다 (자동 채택)
  - 안 들어온다면: **팩은 호스트 봇 스키마에만 존재**하고, 유저가 임포터로 넣는 경로만 남는다
    (v1은 이쪽을 가정하고 설계한다 — 확인 결과에 관계없이 굴러가야 하므로)
- **에셋 접근 권한.** `getCharacter().additionalAssets` 실제 접근 가부. 못 읽으면 자동 감지·
  실존 대조가 죽고 `main` 모드만 남는다 → 그 경우의 안내 문구도 준비해야 한다.
  → v0.54.3: **모듈봇 지원** — 이미지가 모듈의 '추가 에셋'에 사는 봇(실측: MIKU&BRS)을 위해
  `getDatabase(['modules','enabledModules'])`로 켜진 모듈의 assets를 합친다. 꺼진 모듈 제외.

## 에셋 전용 설치 (v0.64)

> "다른 기능 안 쓰고 에셋만 쓰고 싶어도 무조건 변수 등록하라고 하는 게 문제네" (유저)

이미지 태그 자동화는 **상태를 하나도 안 본다.** 그런데 설치가 변수 1개를 요구하고 있었다.
통행세다 — 그걸 내려고 만든 껍데기 변수는 상태창에도, 보조 프롬프트에도, 진단에도
평생 따라다닌다. 그래서 **변수 0개를 정식 형태로 인정**한다.

막고 있던 곳은 두 군데였고, 두 번째가 진짜였다.

| 자리 | 예전 | 지금 |
|---|---|---|
| 설치 검증 | `vars` 비면 무조건 오류 | 변수 없이 도는 기능(에셋 팩·행동 제안)이 켜져 있으면 통과 + 경고 한 줄. 아무것도 없는 빈 스키마는 그대로 오류 (`validate.varFreeWork`) |
| **보조 호출 게이트** | `updater.allow.length > 0` | `engine.auxHasWork` — 변수 \| 제안 \| **열린 팩** |

두 번째가 핵심이다. 이미지와 행동 제안은 상태 갱신 호출에 **얹혀 간다**(추가 호출 0이
이 설계의 요점). 그런데 부를지 말지를 허용 변수 **개수**로 정하고 있었으니, 변수가 없는 봇은
호출 자체가 건너뛰어져 **이미지가 영영 안 붙었다.** 설치만 풀었으면 "설치는 됐는데 아무 일도
안 일어난다"가 됐을 자리다.

딸려 오는 것들 — 전부 "없는 것을 있는 척하지 않기"다.

- **프롬프트**: 조정할 변수가 0개인 호출은 `너는 장면 분석기다`로 갈아탄다. 빈
  `[조정 가능 변수]` 목록에 "변화만 출력하라"를 붙이면 시킨 일이 없는 지시서가 되고,
  모델이 `image`까지 같이 흘린다. JSON 겉껍데기(`changes`/`reasons`)는 유지 —
  파서와 적용 경로를 두 갈래로 만들 이유가 없다.
- **빈 상자**: 변수 0개면 상태창 HTML을 아예 안 낸다. 조건 때문에 잠깐 비는 것과는 다르다
  (그쪽은 상자가 남아야 값이 돌아왔을 때 같은 자리에서 이어진다).
- **헛지침**: "수치·상태는 시스템이 관리한다" 기본 지침도 뺀다 — 있지도 않은 상태창을
  쓰지 말라는 지시가 된다.
- **진단**: 변수 0개면 시뮬을 안 굴리고 멈춘다. 안 그러면 "패배 변수를 못 찾았다",
  "시작 프리셋이 없다"로 정상 설계를 나무란다 (v0.52 원칙).
- **빈 봇 판정**: `schemaIsBlank`에 에셋 팩 합류. 팩이 있으면 빈 봇이 아니다 —
  안 그러면 "아직 스키마가 없습니다" 취급을 받아 기능 카드도 패치 경로도 안 열린다.
- **안내**: 🎨 층과 변수 탭에 "변수 없이 이대로 저장하면 됩니다" 한 줄씩. 이게 없으면
  "변수 탭이 비었는데 괜찮은 건가"에서 손이 멈추고, 결국 껍데기 변수를 만든다.

   ✅ 1차 확인(단일봇, 2026-07-31) — 삽입 정상, 제외 조합은 조용히 생략됨.
3-1. **aux_flow (v0.54)** — 삽입 주체를 "서사 위치에 여러 장"으로 바꾸고 몇 턴.

   "앵커 못 찾음 N장" 비율 확인 — 보조 모델이 인용을 얼마나 정확히 베끼는지가 관건.

4. **게이트** — when 걸린 팩이 닫힌 턴엔 보조 스펙에서 그 어휘가 통째로 빠지는지.
5. **모듈 지침 가져오기** — 실제 모듈 배포문 붙여넣고 [✨ AI로 팩 변환] 실동작
   (앱 내 AI 없으면 [📋 변환 요청서 복사] 경로).
6. **루아 브리지 모드** — 이미지가 한 턴 늦게 붙는 retro 제약 실측. 가이드의 "브리지면
   main 권장"이 실제로 맞는 안내인지.
7. **모듈 로어북 가시성** — 모듈이 붙인 로어북이 `char.globalLore`로 들어오는지.
   v1엔 영향 없고, 들어온다면 v1.1에서 모듈 팩 자동 채택의 길이 열린다 (§열린 문제).
8. **에셋 전용 봇 (v0.64)** — 변수를 하나도 안 만들고 팩만 넣어 저장 → 설치되는지,
   상태창이 안 뜨는지(빈 상자도 없어야 한다), 그러고도 **이미지는 붙는지**.
   콘솔의 `[simcore] output 처리 시작:` 로그에 `hasWork: true`가 찍히면 게이트를 통과한 것이다.

## 완료 정의

스키마 `assets.packs` + 검증(팩 id 중복·인물 중복 경고·형식 자리표시자) + 편집기 탭
(팩 카드 목록·토글·출처·슬롯 행·자동 감지·모드·게이트·팩 내보내기/가져오기·모듈 지침 가져오기) +
`main` 주입문 생성 + `aux` 피기백/라우팅/조합/대조/본문 삽입 + 폴백 + 진단(없는 조합·폴백률) +
테스트(팩 파싱·라우팅·조합·대조·게이트·두 모드 배선·임포터) + 템플릿 하나에 실물 예시 +
가이드 원고. 기존 봇은 `assets`가 없으면 **아무것도 안 바뀐다.**

## 실기 체크리스트 — 모듈 팩 이식 (v0.94, 2026-08-26 작성)

> 목적: "에셋 팩이 모듈로 봇 사이를 옮겨다니는가"의 실증. 애드온(design-모듈-애드온.md)
> 착수 여부는 이 실기의 신호를 보고 결정. **이미지가 실제로 있는 팩**으로 할 것 (실존
> 대조까지 봐야 하므로 romance 템플릿 예시 팩처럼 이미지 없는 팩은 부적합).

### A. 배포자 역할 — 모듈 만들기
1. 팩 가진 봇의 에셋 탭 → 📦 모듈 팩 매니페스트 → [매니페스트 JSON 만들기] → 복사
2. 새 모듈: 로어북 항목 추가 — **이름(코멘트) = `⚙simcore-pack`, 항상 활성은 끄기**,
   내용 = 복사한 JSON. 팩이 쓰는 이미지들을 **모듈 에셋**으로 임포트
3. 모듈 활성화 (전역 or 채팅 개별 — 둘 다 시나리오임, C-2에서 확인)

### B. 받는 봇 역할 — 이식
4. **다른 봇**(팩 없는 봇) 에셋 탭 → "활성 모듈의 ⚙simcore-pack 항목에서 팩을 자동으로
   읽어와요" 체크 → **저장(설치) 먼저** → [모듈 팩 다시 읽기] → 권한 팝업 **허용**
   (⚠ 켜고 저장 안 하면 "설치된 스키마 기준" 안내가 뜨는 게 정상)
5. 병합 목록에 팩 표시 확인 — source가 모듈 이름으로 찍히는지

### C. 확인 포인트
1. **실플 이미지 출력** — 보조가 칸을 채우고 본문 맨 앞에 1장. 몇 턴 굴려 폴백 사다리
   (없는 조합 → 한 칸 낮춤)도 눈으로
2. **채팅 개별 활성 모듈**로도 잡히는지 (전역 활성 말고 그 채팅에만 켠 모듈)
3. **플러그인 설정 module_assets=off 상태에서도** 이미지가 나오는지 — v0.94 규약:
   매니페스트 모듈의 이미지 이름은 module_assets 꺼져 있어도 실존 대조에 합류
4. **유령 방지** — 받는 봇 편집기에서 스키마 저장 → 다시 열기 → 모듈 팩이 스키마에
   박제되지 않았는지 (origin:module은 저장에서 걸러져야 정상)
5. **떼어내기** — 모듈 끄고 [모듈 팩 다시 읽기] → 팩이 목록에서 사라지는지

### D. 흔들어보기 (엣지)
- 모듈 매니페스트 JSON을 일부러 깨뜨림 → 경고만 뜨고 봇은 정상 (못 죽어야 함)
- 받는 봇에 같은 id의 자체 팩을 만들고 다시 읽기 → 스키마 우선 + 충돌 경고
- 판 중간에 모듈 토글 → 재스캔 전까지 옛 상태인 게 문서화된 동작 (다시 읽기로 갱신)

### E. 실패 시 볼 것
- 콘솔(F12) `[simcore] 모듈 팩:` 로그 — 병합 팩 목록·경고가 찍힘
- "db 권한 거부 또는 미지원" 경고 = 권한 팝업을 거부했거나 웹리스 (웹리스는 원래 불가)
