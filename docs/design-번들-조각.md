# 🧩 번들 조각 · 업데이트 병합 — 설계

> 2026-11-14. 상태: **유저 승인(2026-11-14) — §8 두 항목 포함 · 1단계(v1.25.0) 구현 완료, 집 실기 전**. 구현 계획과 판정 기록: `docs/plans/2026-11-14-번들-조각.md`.
> 구현하며 정한 것(계획의 "정한 것"·진행 기록): 빈 것(`[]`·`{}`)은 단위가 아니다 · 내 것과 번들을 같은 경로에서 함께 걷는다 · "내가 지움"도 접힌 줄로 올린다 · 프로필 항목은 조각에 안 싣는다 · 딸린 것 묶기는 색인의 '기타' 적중을 안 따라간다.
> 대상 판: 1단계 v1.25.0(조각) → 2단계 v1.26.0(전체 번들 업데이트 병합). 입력 액션(같은 제보의 ①번)은 별도 문서.

## 0. 발단

커뮤니티 제보(2026-11-14, 유저 전달):

> "번들이나 세이브 파일을 배포할 때 원하는 항목만 선택해서 배포할 수 있는 기능도 가능할까요? 제 페르소나의 능력이나 상태창 데이터가
> 함께 섞여 있어서, 이를 다른 봇으로 옮기거나 원작자님의 허락을 받아 심코어로 만든 데이터를 배포할 때 … (예: 직접 만든 던만추 지도)"

유저 판단(같은 날):
- "조각 내보내기는 **번들 방식**이 편하지 않을까" — 새 통로를 만들지 말고 번들 칸 하나로.
- "봇이랑 모듈 자체를 삭제하고 새로 임포트하는 걸 덜기 위해, 같은 모듈 업데이트판으로 보이면 **비교해서 엎어쳐 주는** 플러그인이 있다
  (Dusk Atelier) — 이쪽 기술을 참고해 보자."

## 1. 지금 있는 것과 모자란 것

| | 되는 것 | 모자란 것 |
|---|---|---|
| 개조 번들 (v1.0.5, `simcoreBundle: 1`) | 로어북 통째 + 정규식(`regex` 통째 / `regexAdd` 덧붙임)을 한 파일로, 받는 쪽은 한 번에 교체 | **전부 아니면 전무** — 스키마는 `⚙simcore` 로어북 항목 하나로 실려 가서 일부만 못 뗀다 |
| 탭 가져오기 (`TAB_SLICES` 18종) | 탭 하나를 통째 교체 (명령·시작 프리셋·상태창은 그 탭 몫의 일부만) | 딸린 변수를 안 챙긴다 — 지도만 옮기면 `locVar`·`seenVar`·`listVar`가 없어 검증 오류 |
| 패치 병합 (`core/patch.js`) | add/update/remove, 충돌 정지, 원자적 검증 | 8섹션뿐 — 지도·상점·보드 등은 "그 탭으로" |
| 번들 업데이트 | 같은 번들을 다시 넣으면 교체 | **받은 사람이 고친 것이 전부 날아간다.** 그때그때 예외를 붙여 왔다: 번들에 없는 프로필 남기기(v1.24.0), `regexAdd`(v1.7.10) |

마지막 칸의 예외 둘은 "내 것은 지킨다"의 개별 땜질이다. 이 문서는 그걸 규칙 하나로 바꾼다.
(🔒 보호 `keep`은 패치 병합과 편집기 통짜 교체에만 있고 **번들에는 지금 없다** — 번들 병합의 🔒는 이 문서가 새로 넣는 동작이다. §5.)

## 2. 참고한 것 — Dusk Atelier의 업데이트 병합

GitHub 공개 소스(`Pyser08/Dusk-Atelier`)의 업데이트 병합 쪽만 읽었다. **라이선스 AGPL-3.0-only — 코드를 옮기지 않는다.**
방식(3자 병합은 일반 기법)만 참고하고 전부 새로 짠다.

가져오는 생각:
1. **기준 지문** — 설치·업데이트 때 "제작자가 준 것"의 항목별 해시를 저장한다(본문 아님).
2. **3자 비교** — 다음 판이 오면 항목마다 기준·내 것·새 것을 대조해 갈래를 나눈다(§5 표).
3. 기준이 없으면 2자 비교로 떨어지고 내 쪽에만 있는 항목은 남긴다.
4. 적용 전에 갈래별 개수 요약, 충돌은 항목마다 고르기.

안 가져오는 것:
- **자동 감지**(리수 화면에 버튼을 넣고 DB를 주기적으로 읽기). 금지 #14(루트 문서에 요소를 넣지 않는다)와 부딪히고,
  심코어 번들은 유저가 직접 번들 칸에 넣으니 파일 안의 id로 판별하면 된다.
- 이름·제작자·로어 이름 겹침으로 "같은 봇" 추정 — 같은 이유로 불필요. **판별은 번들 id 하나.**

역할 나눔: 카드 전체(에셋·인사말·카드 필드) 업데이트는 그쪽 플러그인·리수의 몫이다. 그쪽 눈에 `⚙simcore`는 로어북 한 항목이라
유저가 스키마를 조금만 고쳐도 통째 충돌이다 — **스키마 안을 변수·액션 단위로 비교하는 것**이 심코어가 할 일.

## 3. 핵심 모델 — 번들 = 자기 항목 + 기준 지문

- 번들은 **id**를 갖는다. 적용할 때 "이 번들이 넣은 단위들의 해시"를 캐릭터별로 저장한다(기준 지문).
- **조각**은 일부 단위만 담은 번들이다. **전체 번들**은 전부 담은 조각일 뿐이라 규칙이 하나다.
- 지우기 규칙이 여기서 나온다: 번들에 없는 단위를 지울 수 있는 건 **그 번들의 기준 지문에 있던 단위**뿐이다.
  → 조각은 자기가 넣은 것만 건드리고, 여러 조각이 한 봇에 공존한다. 유저가 따로 넣은 것은 어느 번들의 지문에도 없으니 안 지워진다.

## 4. 형식

```jsonc
// 조각
{ "simcoreBundle": 2, "id": "b_k3f9x2m1", "rev": 3,
  "name": "던만추 오라리오 지도", "note": "원작: (링크) · 허락받고 배포",
  "lorebook": [ /* 고른 항목만 */ ], "regex": [ /* 고른 것만 */ ],
  "schema": { "vars": [ … ], "updater": { "allow": [ … ] }, "map": { … } } }   // 성긴 스키마 — 고른 단위만

// 전체 번들 (지금 모양 + id·rev)
{ "simcoreBundle": 1, "id": "b_…", "rev": 7, "name": "…",
  "lorebook": [ /* ⚙simcore·⚙simcore:<프로필> 포함 전부 */ ], "regex": [ … ], "regexAdd": [ … ] }
```

- **조각은 `2`, 전체는 `1`을 유지한다.** 옛 플러그인(≤ v1.24.1)은 `simcoreBundle !== 1`이면 거절한다 — 조각을 `1`로 내면 옛 플러그인이
  통째 교체로 읽어 **받는 사람 로어북을 조각 몇 개로 갈아 버린다.** 전체 번들은 `1`이라 옛 플러그인도 지금처럼 통째 교체로 받는다.
- `id` — 내보낼 때 한 번 만드는 무작위 글자. **없으면(옛 번들) 지금 동작 그대로**(통째 교체, 지문 없음).
- `rev` — 내보낼 때마다 +1. 받는 쪽이 설치된 판보다 낮은 rev를 넣으려 하면 요약에 경고(막지는 않는다).
- `note` — 제작자가 쓰는 한두 줄(원작 링크·허락 표시). 받는 쪽 요약 화면에 그대로 보인다. 200자.
- 조각의 `schema`는 **스키마와 같은 모양의 성긴 객체**다(패치 형식이 아니다). 단위 걷기(§5)가 스키마와 같은 함수로 돈다.
- `meta.notes`(📌 작업 지침)는 지금처럼 뺀다. 조각의 `schema`에는 `meta`·`simcore`를 싣지 않는다.
- **🔒 `keep`도 내보낼 때 뺀다 — 조각·전체 번들 둘 다, 1단계부터.** 제작자가 자기 작업용으로 건 잠금이 받는 사람 쪽에 실려 가면
  그 항목은 다음 판부터 제작자의 수정이 영영 안 들어온다(§5의 🔒 규칙). 지침과 같은 "제작자 메모" 취급. *(내 판단 — 전체 번들 내보내기의
  작은 동작 변화다. 리포의 아틀리에·얼헌 번들에는 `keep`이 없다.)*
- 조각은 **상태(값)를 싣지 않는다.** 들어간 변수는 시작값으로 선다(진행 중 채팅은 정합이 채운다 — 프로필 전환과 같은 길).
- 조각은 `lorebook`·`regex`·`schema` 중 하나만 있어도 된다(전체 번들의 "로어북이 비면 거절"은 `1`에만).

### 제작자 쪽 — 내보내기 구성 기억

같은 조각을 다시 내보낼 때 id가 같아야 받는 쪽이 업데이트로 본다.
- 구성(레시피) = `{ id, name, note, rev, picks }`를 `pluginStorage` `sim:bundle-recipe:<chaId>`에 둔다(목록, 조각마다 하나 + 전체 번들 하나).
- 기기를 옮겨 레시피가 없으면 **지난번에 낸 번들 파일을 골라** 그 id·구성을 되살린다(파일이 진실, 저장소는 편의).
  *(내 판단 — 스키마 `meta`에 두는 안은 프로필 덧칠·편집기 모양(`shapeFill`)·번들 걷어내기에 전부 손이 가서 버렸다.)*
- 리포의 봇 생성기(아틀리에·얼헌)는 번들을 스크립트로 만든다 → 2단계에서 **고정 id 한 줄**을 넣는다.

## 5. 단위와 3자 비교

### 단위 (지문 한 줄 = 단위 하나)

| 종류 | 열쇠 | 비고 |
|---|---|---|
| 로어북 항목 | `lore:<comment>#<n>` | comment가 비면 `key`, 그것도 비면 내용 해시. 같은 이름이 여럿이면 나온 순서 `#n`. 폴더 항목(`mode:'folder'`)도 한 단위 |
| 정규식 | `regex:<comment>\|<type>#<n>` | |
| 스키마 — id 목록의 항목 | `schema:<경로>[<id>]` | 항목 통째가 한 단위 (변수 하나, 액션 하나 …) |
| 스키마 — 그 밖 | `schema:<경로>` | 객체는 키마다 내려가고, id 없는 배열·값은 그 자리가 한 단위 |
| 프로필 항목 | `lore:⚙simcore:<이름>` | 통째 한 단위(덧칠 안은 안 쪼갠다) |

- `⚙simcore` 로어북 항목은 `lore:` 단위가 아니라 **풀어서 `schema:` 단위들로** 다룬다(전체 번들·받는 쪽 양쪽).
- 스키마 걷기는 `core/profile.js`의 `diffNode`와 같은 결(객체 → 키, id 목록 → 항목, 나머지 → 잎)이다.
- **`shapeFill`은 통째 스키마에만 맞춘다** — 내 것(C)과 전체 번들의 `⚙simcore`. 프로필에서 실측한 사고(편집기가 채운 빈 절이 차이로 잡힌다)를
  되풀이하지 않게. **조각의 성긴 `schema`(I)는 채우지 않는다** — 채우면 `promptState.template: ''`·`statusUI.mode: 'auto'`·`rules.onTurn: []` 같은
  기본값이 "번들이 준 단위"가 돼 지도 조각 하나가 받는 사람의 상태 요약과 매 턴 정산을 비운다. 조각은 **실린 잎만** 단위다.
- 지금 id 목록이 아닌 것은 **배열 통째가 한 단위**다: 지도 `places`(`name`)·`zones`(`label`), `statusUI.groups`(label뿐), `rules.onTurn`.
  유저가 장소 하나를 넣고 제작자도 장소를 고치면(또는 둘 다 상태창 그룹을 고치면) 충돌 하나로 뜬다 — 1·2단계는 이대로 두고 §9 후속.
- 목록 **순서만** 바뀐 것은 단위가 아니다. 결과 순서는 **전체 번들 = 번들 순서**(내 쪽에만 있는 항목은 내 판에서 바로 앞에 있던 항목 뒤, 없으면 끝),
  **조각 = 내 순서 유지, 새 항목은 끝**(조각의 정규식·로어가 카드 것보다 앞에 서지 않게).
- 해시 = 안정 JSON(키 정렬) → 53비트 문자열 해시(새로 짠다 — `rng.hashStr`의 32비트는 지문으로 쓰기엔 짧다).
  "내 것 = 새 것" 비교는 해시가 아니라 안정 JSON 직접.
- **해시·비교에서 빼는 필드**: 스키마 항목의 `keep`(받는 쪽 표식이지 내용이 아니다) · 로어북 항목의 `id`·`loreCache`
  (리수가 "이 채팅에만 켜기" 때 `id`를 붙인다 — 안 빼면 손대지 않은 항목이 "내 수정"으로 잡힌다. PocketRisu 소스 기준, 리스바드는 [live-test]).

### 판정 표 (단위마다 — B 기준 지문, C 지금 내 것, I 번들)

| B | C | I | 판정 | 결과 |
|---|---|---|---|---|
| – | – | 있음 | **추가** | 넣는다 |
| – | 있음 | – | **내 것** | 남긴다 |
| – | 있음 | 있음, 다름 | **충돌** | 기본 번들 것 · 고를 수 있음 |
| 있음 | =B | 있음, ≠B | **번들 수정** | 번들 것 |
| 있음 | ≠B | =B | **내 수정** | 남긴다 |
| 있음 | ≠B | ≠B, C≠I | **충돌** | 기본 번들 것 · 고를 수 있음 |
| 있음 | =B | – | **제작자 삭제** | 지운다 |
| 있음 | ≠B | – | **충돌** | **기본 내 것** — 내가 고친 걸 지우면 내 다른 항목의 참조가 끊겨 검증이 통째로 막힌다 *(내 판단)* |
| 있음 | – | =B 또는 – | **내가 지움** | 지운 채로 |
| 있음 | – | ≠B | **충돌** | 기본 번들 것(되살림) · 고를 수 있음 |
| 무관 | =I | =C | 같음 | 손대지 않음(요약에 안 센다) |

- 🔒 보호 항목(받는 쪽 내 판의 `keep`)은 판정과 무관하게 **내 것**으로 고정하고 요약에 🔒로 센다. 번들은 `keep`을 안 싣고 오니(§4)
  받는 쪽의 🔒는 전부 받는 사람이 건 것이다. (옛 번들로 딸려 온 `keep`은 그대로 지켜진다 — 풀려면 편집기에서 🔒 해제.)
- **표의 "결과"는 기본값이다. 요약의 모든 줄은 [번들 것]/[내 것]을 바꿀 수 있다** — 충돌 줄은 펼쳐진 채, 나머지는 접힌 채.
  충돌이 아닌데 병합 스키마 검증이 막히는 경우(예: "제작자 삭제"인데 내가 따로 만든 액션이 그 변수를 쓴다 · `cmd` 이름 겹침 ·
  두 조각이 같이 쓰던 딸린 변수를 한쪽이 뺐다)의 출구다 — 검증 오류에 나온 id의 줄을 펼쳐 보여 주고, 바꾸면 다시 계획한다.
- **한 이름 공간의 겹침도 충돌 줄이다** — 변수·파생·판정은 id를 같이 쓰고(`patch.js` `ns: 'idspace'`), 이벤트·랜덤 이벤트도 그렇다.
  조각의 변수 `x`와 내 파생 `x`는 경로가 달라 표로는 안 잡히니 계획이 따로 찾아 한 줄로 올린다([번들 것] = 내 쪽 `x`를 빼고 넣는다 / [내 것] = 안 넣는다).
- 적용 뒤 저장하는 지문 = **번들이 준 것(I)** 의 해시다(병합 결과가 아니다). 충돌에서 내 것을 골랐어도 다음 판에서 제작자가 그 단위를
  다시 안 고치면 "내 수정"으로 계속 남는다.

### 기준 지문 저장

`pluginStorage` `sim:bundle-base:<chaId>:<bundleId>` = `{ id, name, rev, at, units: { 열쇠: 해시 } }`.
- 캐릭터를 지웠다 새로 들이면 chaId가 달라져 지문이 없다 → 첫 설치 길(안전한 쪽으로 떨어진다).
- [교체 되돌리기]는 로어북·정규식과 함께 **지문도 이전 것으로** 돌린다(백업에 지문 사본을 같이 넣는다).
- **남은 지문 문제** — 조각을 넣은 뒤 그 단위가 다른 길로 사라지면(번들 통째 교체 · [캐릭터에서 제거] · JSON 관리자 전체 교체) 지문만 남고,
  같은 조각을 다시 넣을 때 전부 "내가 지움"으로 판정돼 아무것도 안 들어간다. 두 겹으로 막는다:
  ① 번들 칸의 **통째 교체**(id 없는 옛 번들 포함)와 **[캐릭터에서 제거]** 는 그 캐릭터의 다른 번들 지문을 지운다(백업에 사본 — 되돌리기가 같이 돌린다.
  캐릭터에 쓰는 결과는 안 바뀌니 "옛 번들 무변화"와 안 부딪힌다).
  ② 지문이 있는 번들의 요약 화면에는 늘 **[처음부터 다시 넣기]**(지문을 무시하고 첫 설치 길로)가 있다 — ①이 못 잡는 경우의 출구. *(내 판단)*
- 크기: 단위 수 × 약 40바이트. 아틀리에(스키마 494KB)에서 실측해 200KB를 넘으면 스키마 잎 단위를 최상위 절로 뭉치는 걸 다시 본다.

### 첫 설치 (지문 없음)

- **조각**: 표의 위 세 줄 — 추가·내 것·충돌. id가 겹치면(같은 id의 다른 변수 등) 충돌로 뜨고 **[번들 것] / [내 것]** 을 고른다.
  개명은 1단계에서 안 한다 — 패치 병합의 개명(`renameInPatch`)은 8섹션 안에서만 파급되고, 지도 `locVar` 같은 절 객체까지 바꿔 주는
  스키마 전체 개명 함수가 지금 없다. *(유저에게 앞서 "교체·개명·건너뛰기를 그대로 쓴다"고 말한 것과 다르다 — §8 확인 1.)*
- **전체 번들**: 지금처럼 **통째 교체가 기본**이다(얼헌식 — 원본 카드의 로어북·정규식을 걷어내야 한다). 2단계에서 요약 화면에
  [통째 교체] / [내 것 남기고 합치기] 두 단추를 둔다. `regexAdd`에 든 정규식은 언제나 "추가"다(통째 교체에서도 카드 정규식을 안 지운다 — 지금 계약 그대로).

## 6. 조각 만들기 (제작자)

💾 번들 줄의 [번들 내보내기] → **[전체] / [조각 고르기]**. 조각 고르기는 패널 안 화면이다(금지 #6 — 호스트 알림창 안 쓴다).

```
🧩 조각 고르기                                      이름 [던만추 오라리오 지도     ]
                                                    설명 [원작: … · 허락받고 배포  ]
 스키마
  ☑ 지도                       ☐ 상점        ☐ 편성표      ☐ 상태창 …
  ▸ 변수 (3/41)   ☑ dungeon_floor  ☐ hp  ☐ …
  ▸ 액션 (0/12)   ▸ 판정 (0/4)   ▸ 이벤트 (1/9)  ▸ 지시문 (0/6)
 로어북   ▸ 📁 오라리오 지리 (8)  ☑    ▸ 📁 페르소나 (5) ☐   ☐ 개별 항목 …
 정규식   ☐ …
 ─────────────────────────────────────────────────
 같이 따라가는 것 (자동)   변수 location · visited · finds  /  AI 허용 location
 ✓ 이 조각만으로 설치돼요 (검증 통과)                        [내보내기 r4]
```

- 고르는 단위: 탭(절) 하나 = `TAB_SLICES`의 그 키들, 또는 id 목록의 항목 하나. 로어북은 폴더(자식 전부) 또는 항목.
  **탭 가져오기의 부분 규칙을 그대로 따른다** — 상태창은 `groups`(+`layout`·`position`)만(꾸미기 `customCSS`·템플릿·테마는 안 실린다),
  시작 프리셋은 `setup.presets`만, 명령은 변수의 `cmd`라 따로 고르는 줄이 없다(변수를 고르면 같이 간다).
- **딸린 것 자동 묶기**: 고른 것으로 성긴 스키마를 만들고 `varReferenceIndex`로 거기서 참조하는 이름을 모은다 →
  원본 스키마의 변수·파생·판정 중 그 이름을 가진 것을 넣는다 → 넣은 것이 또 참조하는 것까지 고정점. 넣은 변수의 `updater.allow` 줄도 같이.
  색인이 못 잡는 연결(액션 `check` → 판정, 편성표 탭 `actions` → 액션)은 묶기 함수가 따로 따라간다.
  ⚠ 색인은 **원본의 변수 목록을 같이 받아야** 제대로 돈다 — 추첨 `sample`은 `schema.vars`에 있을 때만 변수로 보고, 분류 밖 참조를 받치는
  `idsUsedElsewhere`는 넘겨받은 스키마 자신의 변수만 훑는다(성긴 스키마엔 아직 변수가 없어 0건). 두 함수와 `TAB_SLICES`는 지금
  editor.js 밖으로 안 나와 있다 — 내보내거나 옮기는 건 작업자 몫(금지 #8 하니스 같이).
- **끝 관문은 검증이다** — 성긴 스키마를 **빈 칸 채운 사본으로**(`validateSchema`는 `vars`가 배열이 아니면 오류다 — 재는 사본만 채우고
  파일에 싣는 것은 성긴 그대로) `validateSchema`에 넣어 **혼자 통과해야** 내보낸다. 통과 = 빈 봇에도 설치된다는 보증
  (변수 0개 설치는 v1.20.0부터 되고 `activeSections`에 지도가 있다). 막히면 오류 줄을 그대로 보여 준다
  (예: 상태창 줄이 `{date}`를 쓰는데 시간 절을 안 골랐다 → 시간을 넣거나 그 줄을 빼라).
- 자동으로 딸려 온 것은 회색 체크로 보이고 **직접 못 뺀다**(빼려면 그걸 쓰는 항목을 뺀다).
- 구성은 레시피로 저장돼 다음에는 [내보내기 r5] 한 번이다.

## 7. 조각·번들 넣기 (받는 쪽)

번들 칸은 그대로 하나다. [번들 가져와 교체]의 이름을 **[번들 넣기]** 로 바꾼다(조각은 교체가 아니다).

1. 파일을 고르면 형식(1/2)·id·지문 유무를 보고 **계획**을 세운다(순수 함수 — 아무것도 안 바꾼다).
2. 요약을 보여 준다:
   `'던만추 오라리오 지도' r4 (설치된 판 r3) — 추가 4 · 번들 수정 6 · 내 수정 유지 2 · 제작자 삭제 1 · 충돌 1 · 🔒 1`
   + 제작자 `note` + 충돌 줄마다 [번들 것] [내 것] (기본값은 §5 표).
3. 같은 단추를 한 번 더(60초 안, 지금 규약) → 적용:
   백업(지금처럼 최근 3개 + 지문 사본) → 병합 → **병합된 스키마 검증 — 실패면 아무것도 안 바꾸고 오류를 보여 준다**(원자적, 패치 병합과 같은 약속)
   → `setCharacter` → 되읽기 대조 → 편집기 작업본 갱신 → 루아 브리지 재굽기(여기까지 지금 흐름) → **지문 저장**.
4. 프로필은 지금처럼 새 기본 판 위에 다시 얹힌다(못 얹으면 기본 판으로 돌고 알림).

- 받는 봇에 `⚙simcore`가 없으면(심코어 봇이 아님) 조각의 `schema`가 곧 그 봇의 첫 스키마가 된다(전부 "추가").
- **적용 안 한 편집기 작업본이 있으면**(더티) 계획 단계에서 멈추고 알린다: 병합의 "내 것"은 캐릭터에 설치된 판이지 작업본이 아니고,
  적용 뒤 작업본은 병합 결과로 바뀐다. [캐릭터에 적용]을 먼저 하거나 버리기를 고르게 한다. (지금은 말없이 작업본을 덮는다.)
- **번들 칸에 스키마 JSON을 넣으면**(2026-11 실기에서 유저가 겪은 것 — "개조 번들 파일이 아님"만 뜬다) → "스키마 파일이에요 — JSON 관리자에서
  [전체 작업본 교체] → [캐릭터에 적용]"으로 안내한다. 거꾸로 JSON 관리자에 번들을 넣으면 번들 칸을 가리킨다.

## 8. 유저 확인이 필요한 것

1. **첫 설치 때 id가 겹치면 [번들 것]/[내 것] 둘만** (개명 없음). 앞서 대화에서는 패치 병합의 "교체·개명·건너뛰기"를 그대로 쓴다고 했는데,
   개명이 지도·상점 같은 절 객체까지 파급되려면 스키마 전체 개명 함수를 새로 만들어야 한다. 1단계에서 빼고 §9로 미루는 안.
2. **두 판으로 나누는 선**: 1단계 = 조각(형식 2 · 고르기 화면 · 3자 판정 엔진 · 충돌 고르기 · 지문 저장), 전체 번들은 id·rev를 싣고 지문만 저장.
   2단계 = 전체 번들도 같은 엔진으로([통째 교체]/[내 것 남기고 합치기], `⚙simcore` 안 단위 병합, 생성기 고정 id).
   (앞서 말한 "조각 → 업데이트 병합"에서 선을 조금 옮겼다 — 판정 엔진은 조각에 처음부터 필요해서 1단계에 든다.)

## 9. 안 하는 것 · 후속

- **세이브 쪼개기** — 세이브는 그 채팅의 스냅샷 전체라 일부만 빼면 정합이 안 맞는다. 페르소나 수치가 섞이는 문제는 세이브 대신 조각을 배포하면 풀린다.
- 후속: 겹친 변수 **개명** · 받는 봇의 변수에 **연결**(조각의 `location` → 내 봇의 `place`, 선택지 합치기가 필요) · "지금 값을 시작값으로" 굽기 ·
  이름 달린 목록(`places`·`zones`·상점 진열)을 항목 단위로 · 충돌 줄에서 두 판의 차이 보기 · 여러 조각의 설치 목록·제거.
- 모듈 애드온(`design-모듈-애드온.md`, 미구현)과의 관계: 애드온은 모듈에 실려 **얹혀 사는** 층이고 조각은 스키마에 **한 번 섞이는** 복사다. 겹치지 않는다.

## 10. 지킬 것 (작업자에게)

- 순수 로직은 새 코어 모듈 `core/bundle.js`(지문·단위 걷기·계획·적용·딸린 것 묶기)에 두고 어댑터는 화면과 저장만. `build.js`의 `CORE`에 넣는다.
  순환 require를 피하고(fight.js 본보기), editor.js 세그먼트에 모듈급 의존성을 늘리면 테스트 하니스를 같이 고친다(금지 #8).
  모듈을 어디서 자를지·함수 이름은 작업자 몫.
- 지금 `adapter/risu-plugin.js`의 `bundleFromChar`·`bundleShapeError`·`applyBundleToChar`는 `테스트/test-bundle.js`가 소스에서 떼어 돌린다 —
  옮기면 테스트도 같이. **`id` 없는 옛 번들의 동작은 한 글자도 안 바뀐다**는 것을 테스트로 못 박는다.
- 엔진·상태·프롬프트는 안 건드린다(배포 도구다). 그래서 `FEATURE_MAP` 줄은 없다 — 대신 편집 작업공간의 번들 안내문을 고친다.
- 테스트: 판정 표 11줄 전부 · 조각 두 개 공존(서로의 단위를 안 지운다) · 옛 번들 무변화 · 딸린 것 묶기(지도 → 변수 셋 + allow) ·
  혼자 검증 안 되는 조각은 내보내기 거부 · 병합 스키마 검증 실패 시 무변화 · 되돌리기가 지문까지 · 🔒 · 프로필 보존 · 번들 칸에 스키마 안내 ·
  **지도 조각이 받는 봇의 `promptState`·`statusUI`·`rules.onTurn`을 안 건드린다** · 통째 교체 뒤 조각 다시 넣기 · 한 이름 공간 겹침이 충돌 줄로 ·
  로어 `id`가 붙어도 "같음" · 조각을 넣어도 내 변수·정규식 순서가 그대로.
- 실기 확인 거리: 아틀리에 지도 조각을 빈 봇과 얼헌에 넣기, 지문 크기 실측, 포켓리스에서 파일 고르기·내려받기.
- 릴리스 규약(SKILL.md "고치고 나면 반드시") 그대로 — 버전·표시 이름·번들 바이트 일치·스위프.
