# 설계 — 갈림길 확장 (v1.8.0): 판정 · 강제 · 보조가 쓰는 선택지

2026-09-09. 발단은 유저의 옛 실패담: 노우코메(『내 뇌내 선택지가 학원 러브코메를 전력으로 방해하고 있다』)를 메인으로 하는
봇 — "무조건 선택지를 고르게 만들고, 안 고르면 최악의 선택지와 전개로 진행시켜 버리는" — 을 만들려다 기술이 안 돼 포기했다.
로어북·정규식만으로는 모델이 선택지도 내고 강제도 해야 해서, 유저가 무시하면 모델도 따라갔다. 유저가 원한 넷:

1. 선택 시 판정 주사위가 그 행동의 성공·실패를 정한다
2. 선택지 목록을 페르소나·지금 주변인에게 맞춘 맞춤형으로
3. 자유도 높은 게임의 개막장 개그 선택지
4. 무조건 골라야 하고, 선택지 밖의 입력은 완전히 무시하고 시스템이 정해서 진행

v0.41 갈림길(`events[].choices`)은 ①·④에는 벽이 없고 ②·③은 "스키마에 미리 적힌 고정 텍스트"라는 벽이 있었다. 세 조각을
전부 **시스템 손에** 둔다 — 선택지 목록은 보조가 쓰고 시스템이 쥐고, 자유 입력은 어댑터가 모델에게 안 보여주고, 미선택
처벌은 엔진이 집행한다.

## 1. 선택지 판정 — `choices[].check`

- 집행 지점(sendPhase 0.5)이 액션 판정 굴림 바로 앞에 있어서 같은 `rollCheck`를 쓴다. 순서는 액션과 같다 —
  **굴림 먼저, 선택지 효과 나중** (굴림식이 이점 같은 소모성 변수를 읽는다). [판정] 줄·등급 전달문은 같은 턴 서사에.
- 성공/실패별 결과는 판정의 등급 밴드(effects·inject)가 이미 맡는다. 선택지마다 다른 판정을 달 수 있다.
- 타임아웃 자동 결정(outputPhase 6.5)도 굴린다 — 이벤트 판정과 같이 [판정] 줄은 통지로 다음 전송.
- allow 동결은 선택지 effects만 본다 (등급 효과는 판정의 몫 — 스키마 갈림길 규약 그대로).

## 2. 강제 갈림길 — `events[].strict` / `liveChoices.strict`

- `true`/`'last'`: 고르지 않고 보내면 **열린 것 중 맨 끝**. 타임아웃이 마지막 항목을 고르는 규약과 같은 자리라 "마지막 =
  최악"을 한 번만 정하면 두 길이 같이 듣는다. `'random'`: 열린 것 중 무작위 — 시드 rng라 리롤에 안정.
- **유저 원문은 모델이 못 본다.** sendPhase가 `userTextOverride`를 돌려주고 어댑터 beforeRequest가 마지막 유저 메시지
  본문을 `[선택 강제] N. 라벨 — 유저는 선택지 밖의 행동을 적었고, 시스템이 이 항목으로 정했다.`로 바꾼다. 리수 채팅 로그의
  원문은 그대로다(리수 메시지는 안 고친다 — 화면에선 보이지만 서사에는 없었던 일).
- 프롬프트엔 `[선택] 라벨 (유저가 고르지 않아 시스템이 정했다)` + `[선택 강제]` 안내 한 줄
  (`promptState.forcedChoiceGuide`로 교체·끄기 — checkGuide·dayCloseGuide와 같은 규약). "유저가 스스로 고른 것처럼 쓰지
  말고, 고르지 못해 그 길로 떠밀리는 장면을 써라."
- strict면 대기 상태가 다음 전송을 못 넘긴다 — timeout 없음 경고를 안 띄운다. `[선택 대기]` 줄도 strict 봇에선 안 나온다.
- 상태창 안내가 "고르지 않고 보내면 마지막 항목(아무 항목)으로 흘러간다 — 선택지 밖의 행동은 없었던 일이 된다"로 바뀐다.
- `/선택`으로 잠긴 항목을 골라 거부된 채 보내면 그것도 "안 고른 것"이다 — strict는 strict다.
- **항목 글을 그대로 보내면 고른 것** (v1.9.4). 리수는 클릭이 입력창을 못 채워 유저가 라벨을 복사해 본문으로 보내는
  습관이 있다 — 그 글은 "선택지 밖의 입력"이 아니다. sendPhase 0.5가 예약이 없을 때 본문을 대조한다(`choice.matchTypedChoice`):
  완전일치만 — `N` · `N. 라벨` · `N) 라벨` · `라벨`(+태그 꼬리표·✅🔒·끝 마침표 무시). 잠긴 항목·덧붙인 말·일부 일치는 여전히
  "안 고른 것". 예약(클릭·/선택)이 있으면 예약이 이긴다. 리롤은 같은 글이라 같은 결정.
- **온오프**: 이벤트 `when`이 심코어의 공통 스위치라 특정 상황·bool 변수(`/명령`·hold 액션·보조 allow)·시나리오 막으로
  다 걸 수 있다. 강제는 갈림길 설정마다 따로라 같은 봇 안에서 절대선택은 강제·일반 갈림길은 자유로 섞인다.

## 3. 보조가 쓰는 갈림길 — `liveChoices` (core/choice.js, 모듈 22호)

의뢰판(quest)과 같은 규약 — **보조가 쓰고 시스템이 쥔다.** 핵심은 **태그**: 라벨은 즉석이라 효과를 미리 못 붙이는데, 태그
어휘를 스키마에 고정하고 태그마다 판정·효과·전달문을 매핑하면 결과는 시스템 손에 남는다. ①과 여기서 합쳐진다.

- **흐름**: 전송 단계 `rollAsk`(when 열림 · 걸린 갈림길 없음 · chance 추첨, 시드 rng — 설정 없는 봇은 rng를 안 먹는다)
  또는 `events[].liveChoices: true` 트리거 → `meta.liveAsk` → 보조 호출에 얹힘(추가 호출 0) → `"choices": {"desc",
  "items": [{"label", "tag"}]}` → 응답 단계 `applyLive`가 정제해 `pendingChoice = { id: '@live', turn, live }`로.
  타이밍은 의뢰판과 같다: 그 응답의 상태창에 선택지가 뜨고 다음 전송에 고른다. 트리거는 보조 호출이 이미 지난 뒤라
  **다음 턴** 응답 뒤에 온다 (깃발은 걸릴 때까지 산다).
- **합성 이벤트**: 엔진 `pendingChoiceEvent(schema, state)`가 `'@live'`면 `synthEvent`로 이벤트 모양을 만들어 돌려준다.
  집행·타임아웃·동결·렌더·명령·클릭이 전부 이걸 본다 — 갈림길의 출처를 한 군데서만 가른다. `findChoiceEvent(schema, id)`는
  스키마 갈림길 전용으로 남는다.
- **정제**(뇌절 방지): 라벨 60자 · 중복 거부 · 어휘 밖 태그 거부(앞머리·부분 일치로 한 번 구제 — "굴욕적"→"굴욕") ·
  count 상한/미달 · worst 항목은 하나만 맨 끝. 부탁 안 한 턴에 온 choices는 무시.
- ③ 개막장 선택지는 여기 위에서 거의 공짜 — `guide`("둘 다 개막장이어야 한다 — 멀쩡한 길은 열에 하나")와 태그
  (굴욕·폭주·최악)에 가혹한 밴드의 판정을 매핑하면 된다. 고정 갈림길이면 작성자가 한 줄 적으면 끝.
- ② 주변인 맞춤은 보조 프롬프트에 현재 상태(위치·동석자 목록·호감도)가 이미 실리니 guide에서 "곁에 있는 {인물}에게 걸
  수 있는 행동으로"라 하면 된다. 동석자 목록 변수가 없는 봇은 하나 둬야 한다.

## 4. 노우코메 봇에 얹으면

- 절대선택 = `liveChoices` (chance는 `curse / 100`처럼 저주 변수를 읽는 식, when에 `curse_on`)
- 강제 + 미선택 최악 = `strict: 'last'` + `worst: '최악'` 태그 (그 태그의 효과에 두통·정신력 깎기)
- 신의 미션 = 의뢰판(questBoard) 재활용, 발주처 "신" 고정
- 저주 = 진행 축 — 미션 완료마다 `curse`가 깎이면 초반엔 거의 매 턴 강제, 후반엔 가끔. 막(scenario)으로 단계
- 히로인 호감도 = int 변수 + 태그별 효과
- 안전판 하나: "고르면 반드시 그대로 벌어진다" — 고른 선택지엔 판정을 안 붙이거나 붙여도 "얼마나 처참하게"만 가른다
