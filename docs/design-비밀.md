# 설계 — 비밀 (schema.secrets)

> 2026-09-17, 유저 제안: "심코어 다음 기능은 비밀유지로 해볼까 — 지금 사람들이 가장 힘들어하는 게
> LLM은 비밀유지를 뭔 짓을 해도 못 한다라서." **v1.10.0 구현** — core/secret.js(23호) + 엔진 배선
> (sendPhase 3.5.6 주입 / outputPhase 8.6 단계 열기) + 검증·진단 + [비밀] 탭 + 규격·기능 카드 +
> 상태창 🔒 칩·🔓 카드 + rpg 실물 예시. test-secret.js가 은닉을 grep으로 증명한다.
> 원형: 시나리오레이터의 `acts[].secret`(v0.90, "은닉=구조") — 막에 묶여 있고 켜짐/꺼짐 둘뿐이던 것을
> 막 없이·단계별로 일반화. 설계 대화에서 정한 것: **탭은 따로([비밀]), 기계는 하나, 종류는 어법.**

## 1. 왜 LLM은 비밀을 못 지키나 — 그리고 심코어에선 되나

프롬프트에 있는 건 전부 "아는 것"이고, 모델은 아는 것을 말하는 쪽으로 기울어 있다. "말하지 마라"는
그 정보 **옆에 붙은 또 하나의 텍스트**일 뿐이라 — 유저가 캐묻거나, 서술이 인물 내면으로 들어가거나,
복선을 깔려다 그냥 말해 버린다. 지시는 확률을 낮출 뿐이라 100턴이면 한 번은 샌다.

확실한 방법은 하나뿐이다. **모르는 건 말할 수 없다.** 프롬프트에 없으면 못 샌다.

심코어엔 이미 토대가 있다:
- 시나리오레이터의 `secret` — 막이 열려야 프롬프트에 실린다. "이 함수가 은닉 보장의 실체다".
- 스키마 로어 항목은 `__simcore_never__` 키라 프롬프트에 절대 안 실린다. 스키마에 적은 비밀은
  심코어가 손수 넣기 전엔 모델이 못 본다.
- 숨은 변수 — `promptState.template`에 안 넣으면 모델이 값을 모른다.

그래서 이건 새 원칙이 아니라 **있는 원칙의 일반화**다.

## 2. 사람들이 힘든 지점 (시나리오 secret이 못 덮는 곳)

1. **막에 묶여 있다.** 연애·일상 봇처럼 막 구조를 안 쓰면 못 쓴다. 인물 하나의 비밀 하나를 두고
   싶은데 시나리오를 짜야 한다.
2. **켜짐/꺼짐 둘뿐이다.** 실제 비밀은 단계가 있다 — 낌새 → 부분 → 전모. 여기서 진짜 모순이 나온다:
   **복선을 깔려면 모델이 알아야 하고, 알면 샌다.**
3. 비밀이 **캐릭터 카드 디스크립션에** 적혀 있다. 심코어 바깥이고, 카드 자체가 새는 구조다.

## 3. 스키마

```json
"secrets": [
  { "id": "lina_origin", "kind": "person", "about": "리나", "label": "리나의 과거",
    "tell": "exists",
    "tiers": [
      { "text": "궁정 예법에 익숙하다. 왕가 문장을 보면 움찔한다." },
      { "when": "affinity >= 60", "text": "수도를 나쁜 사정으로 떠났다.",
        "notify": "[비밀] 리나가 수도를 떠난 사정을 조금 털어놓았다." },
      { "when": "letter_found", "text": "추방된 왕녀다. 동생이 왕위를 찬탈했다.",
        "notify": "[비밀] 리나의 정체가 밝혀졌다." }
    ] },
  { "id": "twist", "kind": "plot", "label": "진상",
    "tiers": [ { "when": "scn_act == \"act3\"", "text": "의뢰인이 곧 범인이다." } ] }
]
```

| 필드 | 뜻 |
|---|---|
| `kind` | `person`(인물이 숨기는 것) / `world`(아직 드러나지 않은 사실) / `plot`(이야기의 반전). **기계는 같고 어법·기본값만 다르다** (§4). |
| `about` | 누구·무엇의 비밀인가. 존재 알림에서 "누가 숨기는지"로 쓰인다. |
| `label` | 상태창 칩·변화 로그에 보이는 이름 — 스포일러 없이. |
| `tell` | 존재 알림. `exists` = "X에겐 말 못 할 사정이 있다 — 너도 내용은 모른다, 지어내지 마라" / `none` = 신호도 없음. 기본: 인물·세계 = exists, 반전 = none. |
| `tiers[]` | 공개 사다리. `when`(조건식, 1단계는 생략 = 처음부터) + `text`(그 단계에서 밝혀지는 내용) + `notify`(선택). |

내부 상태: vars 예약 키 **`sec_<id>`** = 열린 최고 단계 번호(−1 = 아직). scn_idx와 같은 계열 —
엔진이 관리하고, 스키마 vars가 아니라 allow에 못 올리고(보조가 못 만진다), 조건식·상태창이 읽는다
(`sec_lina >= 1`이면 지시문을 바꾸는 식).

### 3-1. 은닉 보장 — 이 기능의 실체

`secretInjectionText(schema, vars)`가 프롬프트에 싣는 것은 **열린 단계까지의 text**와, 하나도 안
열렸을 때의 **존재 알림(tell:exists인 것만)**뿐이다. 안 열린 단계의 text는 이 함수의 출력 문자열에
들어갈 경로가 없다. 그래서 `테스트/test-secret.js`가 **프롬프트 문자열에 그 문장이 없음을 grep으로
단언**한다 — 모델 확률에 기대는 게 아니라 구조로 증명된다. 배포글에 "구조적으로 못 샌다"고 쓸 수 있는
근거가 이것이다.

같은 이유로 **보조 프롬프트엔 아무것도 안 간다.** 보조는 변수만 세우면 되고 내용을 볼 이유가 없다.
새는 통로 하나가 더 닫힌다. 원장(changeLog)·하이라이트 카드·변화 로그엔 라벨과 단계 번호만 남는다 —
원장은 보조에게도 가므로 내용을 실으면 거기서 샌다.

전부 tell:none이고 하나도 안 열렸으면 블록 자체가 없다 — "비밀이 있다"는 신호도 스포일러다
(시나리오의 "secret 0개면 절 자체가 없다"와 같은 원칙).

### 3-2. 두 발명

**① 복선은 이유 없는 행동으로 적는다.** 1단계에 "왕가 문장을 보면 움찔한다"만 주고 *왜*는 안 준다.
모델은 이유를 모른 채 그 행동을 한다. 배우는 극본 결말을 몰라도 "뭔가 숨기는 사람"을 연기할 수
있다 — 좋은 미스터리는 원래 그렇게 쓴다. 이유는 뒷단계가 열릴 때 오고, 그때 "지금까지의 낌새가 이것
때문이었다"가 자연히 이어진다. §2의 모순(복선을 깔려면 알아야 하고, 알면 샌다)이 여기서 풀린다.

**② 존재는 알리되 내용은 안 준다.** 이게 없으면 모델이 빈칸을 아무 설정으로 메운다. 있으면 '비밀
있는 사람'을 연기하되 내용은 못 만든다. "미공개 = 거짓이 아니라 아직, 지어내지 마라" 어법은
시나리오(S2D PUBLIC STATE 계약에서 이식)와 공유한다.

### 3-3. 단계 열기

outputPhase 8.6 — 이벤트(⑦·⑧)·막 전환(8.5) 뒤라 이번 턴이 세운 변수·막을 조건이 바로 읽는다.
**참인 가장 높은 단계까지 한 번에** 연다: 3단계 조건(편지 발견)이 먼저 참이면 2단계도 함께 —
단계는 누적 사다리라 높은 단계가 열렸다는 것은 그 아래도 지나갔다는 뜻이다. **한 번 열린 건 절대
안 내려간다** (호감이 다시 떨어져도) — 밝혀진 진실은 잊히지 않는다. 시나리오와 달리 "턴당 한
단계" 페이스 제한은 없다 — 발견은 발견하는 만큼 드러난다.

## 4. 종류는 기계가 아니라 어법이다

세계의 비밀·인물의 비밀·엔딩의 비밀은 만드는 사람에겐 완전히 다른 물건인데, 엔진 입장에선 전부
"조건이 열리기 전엔 프롬프트에 없는 글"이다. 다른 건 이것뿐:

| | 세계 | 인물 | 엔딩·반전 |
|---|---|---|---|
| 존재를 알리나 | 소문·흔적으로 알림 | **알림** — 숨기는 사람을 연기해야 하니 | **안 알림** — 반전은 예고하면 죽는다 |
| 복선(1단계) | 수군거림, 이상한 정황 | 이유 없는 행동 | 없거나 아주 얇게 |
| 여는 것 | 탐색·발견 변수 | 호감·사건 변수 | `scn_act`, 조건 |
| 열릴 때 어법 | "밝혀진 사실" | "털어놓은 것 · 드러난 것" | "밝혀진 내막" |
| 상태창 | 🔒 칩 — **수집 요소로 오히려 좋다** | 인물 옆 🔒 | 표시 없음 |

종류를 셋으로 가르는 구조(모듈 세 개)는 안 한다 — 조건식·주입·검증·테스트가 세 벌이 되는데 실제로
다른 건 문장 몇 개뿐이다. `kind`는 기본 `tell`·존재 알림 문구·열림 머리말·칩 표시만 바꾼다.

**유저의 비밀**도 같은 기계다. 잠입 설정에서 NPC들이 유저 정체를 몰라야 하는데 페르소나에 적혀
있으면 모델이 모든 NPC를 연기하니 전부 안다. `about: 유저`, 여는 조건 = "들켰다" 변수. 그 전엔
모델이 모르니 NPC도 모른다.

## 5. 시나리오와의 관계 — 자리는 둘, 보장은 하나

막의 `secret` 칸은 시나리오 탭에 **그대로 둔다**. 막을 쓰는 사람이 내막을 다른 탭에 가서 적어야
하면 시나리오 탭이 나빠진다. 대신 어법("미공개 = 거짓이 아니라 아직")과 은닉 원칙은 한 벌이고,
비밀의 여는 조건에 `scn_act == "act3"`를 걸어 막과 맞물릴 수 있다 (rpg 예시가 그 본보기 —
아린의 과거가 shadow·clash 막에서 열린다). 흡수한 것은 **보장**이지 쓰는 자리가 아니다.

## 6. 못 막는 것 (솔직하게 — 안내문이 곧 기능의 절반)

- 모델이 비밀을 **지어내는 것**은 완전히는 못 막는다. "지어내지 마라"는 결국 지시다. 다만 진짜
  비밀은 절대 안 새고, 지어낸 건 열릴 때 진짜로 덮이고, 1단계 복선이 있으면 모델이 빈칸을 그걸로
  메워 창작 여지가 줄어든다.
- 카드 소개글에 적혔거나 커뮤니티에 스포된 비밀은 무의미하다.
- 이미 새어 나간 대화 로그는 되돌릴 수 없다 (로그는 프롬프트에 실린다). 리롤뿐.
- **카드·페르소나·로어북에 적힌 건 심코어 밖이다.** [비밀] 탭 머리와 규격서가 "그쪽에서 잘라 여기로
  옮기라"고 말한다. 이걸 말해 주지 않으면 "켰는데 왜 새냐"가 된다.

## 7. 편집기·AI 경로

- **[비밀] 탭** — [진행] 묶음, 의뢰판·메신저와 같은 번호 섹션 골격(`sce-board-*`). 비밀 하나 = 카드,
  종류·about·표시 이름·존재 알림 + 단계 사다리(여는 조건·밝혀지는 내용·통지). 1단계는 "낌새 (복선)"
  라벨로 이유 없는 행동만 적으라고 상기한다.
- **TAB_SLICES.secrets** 통째 교체 (단계는 누적 사슬이라 부분 교체가 어긋난다 — 시나리오와 같은 이유).
  일반 패치(SECTIONS)엔 안 넣었다 — 개명 파급·keep·병합이 얽히는데 실익이 작다. 후보로 남긴다.
- **SCHEMA_SECRET_RULES** — 통짜 규격서·탭 규격서에 합류. 요점은 단계 나누기와 복선 어법: AI가
  1단계에 이유를 적으면 그 순간 복선이 스포일러가 된다.
- **다이제스트** — 참조 절만 (id·종류·단계 수·조건이 읽는 변수·`sec_<id>`). **내용(text)은 안 싣는다** —
  제작 어시스턴트에게 가는 글이지만 다른 프롬프트에 습관적으로 복사되면 그게 유출이다.
- 🔒 기능 카드 — "밝혀지기 전엔 모델이 몰라야 하는 것을 1~3개, 낌새 → 부분 → 전모로".

## 8. 검증·진단

- 검증: 예약 이름 충돌(`sec_<id>` 변수) / 뒷단계 when 없음(영영 안 열림) / 빈 text / when의 rand()
  금지 / kind·tell 오타 / 반전+exists 경고 / exists인데 about 없음 경고 / text의 {변수} 참조.
- 진단: **닫힌 비밀(mid)** — 판 안에 마지막 단계가 한 번도 안 열린 비밀. 변명 사다리는 닫힌 막과
  같다(설정 게이트 → 긴 판 → AI 문턱 → 진짜 결함). 첫 안 열린 단계 하나만 짚는다.

## 9. 미결

- [ ] 일반 패치(SECTIONS)에 secrets 합류 — 비밀 하나만 고칠 때 통째 교체가 무겁다. 개명 파급 설계 필요.
- [ ] 새 시작 페이지에서 단계 강제 열기/닫기 (디버그·구제 — 시나리오 §4의 막 강제 이동과 같은 자리).
- [ ] 실기: 존재 알림 문구가 실제로 "숨기는 사람" 연기를 끌어내는지, 지어내기 억제 정도, 열리는 순간의 이음새.
