# 기능 요청 (🧩 AI에게 기능 맡기기) — 설계

> 파일명은 초안 때의 '기능 프리셋'이지만, **2026-08-02 방향 전환으로 내용은 "규격에 맞춰
> AI에게 맡기기"다.** 아래 §방향 전환 참조 — 고정 JSON 레시피 안은 폐기됐다.

발단 (2026-08-01): "일괄 템플릿이 아닌 소규모 기능 프리셋을 만들어서 편의성을 확장하는 게
좋을 것 같다." 퀘스트 보드 문답에서 나왔다 — 신규 기능 0개로 조립이 되는데, 그 조립을
사람마다 손으로 다시 짜야 한다는 게 남은 비용이었다.

## 범위 확정 (2026-08-02) — 앞으로의 계획은 이 문서 하나다

> "앞으로 계획은 신규 기능 추가가 아니라 기존 기능을 활용한 조각 모음. 템플릿처럼 아예
> 통짜로 교체하는 게 아니라 상태창·편성표·스킬트리·퀘스트 보드 이런 식으로 현재 스키마에
> 조각을 추가해 주는 것. AI에게 부탁하기도 다듬어 갈 생각이고, 기능은 거의 탄탄하게
> 만들어졌다고 본다."

- **엔진 기능은 동결.** v0.61까지로 충분하다고 판단. 앞으로의 작업 = ① 기능 요청(🧩)
  ② ✨ AI에게 맡기기 다듬기. 이 둘 외에는 새 절·새 모듈을 늘리지 않는다.
- **대상은 *굴러가는 중인* 스키마다.** 통짜 템플릿(13종)은 빈 봇 전용으로 그대로 두고,
  기능 하나만 얹는다. 이미 쓰던 변수·이벤트를 건드리지 않는 것이 이 작업의 성립 조건이다.
- **비목표 2건 (웬만해선 안 한다)** — 지금 더 얹을 만한 건 이 둘뿐인데, 둘 다 안 가기로:
  - **자동 개체 추가** (AI가 인물·아이템 개체를 런타임에 스스로 늘리는 것). 레코드 층에서
    이미 범위를 좁혀 둔 결론과 같다 (design-레코드.md — 아이템 인스턴스 무산).
  - **전투 계산** (판정 위에 얹는 데미지·턴 해결 엔진). checks로 굴리는 것까지가 끝.

  → 새 요구가 오면 먼저 "이거 기능 요청으로 되나?"를 묻는다. 대개 된다는 게 이 문서의 전제다.

## 방향 전환 — 고정 프리셋을 버린 이유 (2026-08-02)

초안은 "레시피 = 큐레이션된 패치 JSON을 만드는 생성 함수"였다. **폐기한다.**

> "이걸 고정된 그런 걸로 하면 제작자가 작업하다가 프리셋 넣는 순간 망가질 테니."

- 유저가 첫 예로 든 **상태창·편성표·스킬트리는 애초에 그 봇의 변수가 있어야 성립한다.**
  고정 조각으로 못 찍어낸다 — 봇마다 다른 **디테일 개발**이다.
- 고정 조각을 굴러가는 스키마에 넣으면 이름·전제가 어긋나고, 그 어긋남을 메우려다 기존
  작업을 덮는다. 프리셋의 편의가 제작자의 손실로 뒤집히는 지점.

**→ 레시피는 JSON이 아니라 *요청서*를 만든다.** 그 절의 규격서 + 지금 스키마의 실제 변수·
항목 + 유저가 쓴 한 줄 요구를 조립해 AI에게 보내고, 받은 것을 **기존 가져오기 경로**로 넣는다.
기능마다 달라지는 건 요청서뿐이고, 병합·검증·되돌리기는 이미 있는 것을 그대로 쓴다.

## 구도 — 빈칸 하나를 채우는 일

| | 복사 왕복 (기존) | 플러그인 안에서 |
|---|---|---|
| **통짜·광범위** | 🧾 JSON 작업대 규격 복사 | ✨ AI에게 맡기기 (v0.46~) |
| **부분·기능 단위** | 📤 탭별 규격 내보내기 | **🧩 기능 요청 ← 이번 작업** |

새 기계가 아니라 이미 있는 두 축의 교차점이다. 유저 표현: *"각 탭의 규격 내보내기가 이제
규격에 맞춰 AI에게 맡기기로 확장되는 느낌."*

## 재료 점검 — 이미 있는 것

- **`buildTabExportPrompt(schema, tabKey, opts)`** (editor.js) 가 벌써 조립한다:
  (a) 그 절의 규격서 + 패턴 예시, (b) **현재 정의된 변수 목록** — "없는 변수를 지어내지
  못하게", (c) 항목 수 **체크섬**, (d) `WANT` 자리표시자 = *"여기를 채우세요"* ← **유저 요구가
  들어갈 칸이 이미 뚫려 있다.**
- **📥 가져오기** — 코드펜스 제거·JSON 파싱·`pickTabFragment` → 통째 교체 + **되돌리기 1단** +
  항목 급감 경고 + 변수 교체 시 깨진 탭 안내(`breakageAfterVarImport`).
- **`ai.generate` 직결 경로** — 진단의 `✨ 이 결과로 바로 고쳐달라기`(v0.47)가 같은 배선의 선례.
- **patch.js** — add/update/remove 병합, 충돌 감지(v0.44.2), 검증 실패 시 무변화, 되돌리기.
  부분 수정 요구는 통 교체 대신 이쪽으로 흘릴 수 있다.

→ 신규로 쓸 것은 **"`WANT` 칸에 유저 문장을 넣고 `copyWidget` 대신 `ai.generate`로 쏜다"**
+ 슬라이스 보강 + 안전판 하나. 병합 코드는 새로 쓰지 않는다.

## 슬라이스 현황과 구멍

`TAB_SLICES` 7종 — `vars` / `commands` / `actions` / `checks` / `rules` / `presets` / `party`.
**없는 것: `statusUI`(+`promptState`) · `calendar` · `time` · `assets`.**

- **상태창이 1번 작업이다.** `PATH_TABS`에서 상태창은 `false`(= "직접 고쳐야 합니다")로
  분류돼 있다. 상태창의 기존 AI 경로는 **스킨 CSS·배치 템플릿**용이라 *행 구조*를 만드는
  규격서가 아니다. 유저가 첫 예로 든 게 하필 상태창이라 여기부터 뚫는다.
- **상태창 슬라이스 규격서의 필수 조항**: **"날짜·시각 행을 직접 만들지 마라 —
  시간 체계의 `{date}`·`{clock}` 노출 이름을 참조하라."** (design-시간.md §결정 1)
- **`time`은 슬라이스로 열지 않는다.** 설정값 예닐곱 개짜리 폼이라 AI보다 폼이 낫다.
  대신 켜기 마법사가 **진행 입구를 같이 고르게 강제**한다 (design-시간.md §결정 2).
- `calendar`·`assets`는 후순위 — 각각 골격 버튼·🎨 층이 이미 있다.

## 기능 목록 (요청 카드)

카드가 하는 일: ① 전제 검사 → ② 대상 슬라이스 선택 → ③ 규격서 + 현재 스키마 + 유저 요구
조립 → ④ 생성 → ⑤ 가져오기(되돌리기 포함).

| 기능 | 대상 슬라이스 | 전제 | 비고 |
|---|---|---|---|
| 📊 상태창 한 벌 | `statusUI` **(신설)** | 변수 몇 개 | 날짜 행 금지 조항 필수 |
| ⚓ 편성표 | `party` | 인물 list 또는 enum | 초상·css는 원문 보존 지시 기존재 |
| 🌳 스킬트리 | `vars`(SP) → `party`(items) | — | 2슬라이스 **순차** |
| 📜 퀘스트 보드 | `rules` + `actions` | `time` | 기한 `@+N`·expire·수주 choices |
| 🛒 상점 | `actions` | 골드 int, 소지품 list | |
| 📈 레벨·성장 | `vars` → `rules` | — | 레벨업 이벤트로 SP 지급 |
| 💕 호감도 인물 | `vars` → `rules` | — | 인물명 하나 받아 3종 지시문까지 |
| 📅 달력+일정 | `calendar` **(신설)** | `time` | v0.61 골격 버튼의 상위 호환 |

## 안전 — 통 교체가 이 설계의 유일한 위험

탭 가져오기는 **통째 교체**다. 기능 하나 얹으려다 그 탭 전체가 AI 재작성본으로 갈릴 수 있고,
그건 §방향 전환에서 폐기한 바로 그 사고("작업하다가 넣는 순간 망가진다")의 재발이다.

이미 있는 방어: 요청서의 *"손대지 않은 항목까지 전부 포함해 한 세트로"* 지시 + 항목 수
체크섬 + 급감 경고 + 되돌리기 1단.

**추가할 것 — 적용 전 diff 미리보기.** 사라지는 id 목록을 넣기 *전에* 보여준다. 경고는
이미 넣은 다음에 뜨지만, 미리보기는 넣기 전에 막는다. 이게 걱정에 대한 실질적인 답이다.

- 여러 슬라이스가 걸린 기능(스킬트리·성장)은 **한 번에 하나씩 순차** — 변수부터 확정하고
  그 다음 절로 간다(변수 먼저는 기존 규칙 그대로).
- 부분 수정 성격의 요구는 통 교체 대신 **패치 경로**로 흘린다.

## 병행 트랙 — ✨ AI에게 맡기기 다듬기

기능 요청과 한 몸이다. 카드에 없는 요구는 그대로 자유 입력으로 흘러야 하고, 반대로 AI가
만든 것이 템플릿과 같은 품질 기준을 맞춰야 한다.

- 기능 카드 바로 아래에 자유 입력창 — "이 중에 없으면 말로 시키세요"의 동선.
- 기능 카드 목록은 규격서에 싣지 않는다 (AI 경로는 이미 자유 조립이 되므로 — 중복 가르침 방지).
- v0.50 aiguard 네 겹(규격서·린트·진단·템플릿)에 **기능 요청 결과물도 같은 게이트**를 태운다.
  카드로 만든 스키마가 진단에 걸리면 그건 카드(요청서) 버그다.

## 원칙

- 요청서의 예제는 **템플릿과 같은 코퍼스 기준** — 예제가 곧 교본이다 (ai-mistakes.md #1).
- 설치 후 **진단이 깨끗해야 한다** — v0.60 정적 검사가 품질 게이트.
- **기존 항목 무손실이 합격선이다.** 새로 생긴 것보다 사라진 것이 없는지가 먼저다.

## 진행

1. ✅ **`statusUI` 슬라이스 신설** (v0.62.0) — `TAB_SLICES.status`는 `statusUI` 통째가 아니라
   `groups`만 갈아끼우고 `layout`만 덤으로 받는다(`subOpt`). customCSS·커스텀 템플릿·테마 보존.
   날짜 금지 조항 포함. `PATH_TABS`의 상태창 `true` 승격, `promptState`는 'AI 설정'으로 분리.
   - 부수 발견: **`varContractTable`에 시간 노출 이름이 없었다.** 날짜 조항이 성립하려면
     계약표에 `date`·`clock`이 있어야 하는데 빠져 있어서, AI가 "날짜는 못 쓰는구나" 하고
     `day` 변수를 새로 만들자고 할 판이었다 — 막으려던 바로 그 길. 시간 절 추가로 수정.
2. ✅ **`tabAiTools`에 직결 버튼 + 요구 입력칸** (v0.62.0) — 모든 탭 공통. `copyWidget`은
   옆문으로 유지(호출 차단 환경 폴백). 붙여넣기와 직결이 같은 문(`applyTabImport`)으로 들어간다.
3. ✅ **꾸미기 창구 공용화** (v0.62.0) — 1층 👁 결과에만 있던 스킨/배치 생성기를 `cssAiTools()`로
   빼 3층 상태창 탭에도. 요청 문구·되돌리기 슬롯 공유. *"AI에게 요구하는 거면 아예 배치까지
   맡기는 게 더 편하고 낫다"*(유저).
4. ✅ **적용 전 계획** (v0.62.1) — `tabItemIds`(개수가 아니라 신원) + `planTabImport`(사본 비교).
   손실 0이면 통과, 하나라도 있으면 목록을 보여주고 [그래도 적용] / [취소]. 취소 = 무변화.
5. ✅ **🧩 기능 추가 카드** (v0.63.0) — 창작 탭, 자유 입력창 **위**에 7장

   카드가 하는 일은 `tabWant[슬라이스]`를 채우고 `runTabGenerate`를 부르는 것뿐 —
   **새 병합 코드 0줄.** `needs(schema)`로 전제를 검사해 못 쓰면 버튼을 잠그고 이유를 띄운다.
