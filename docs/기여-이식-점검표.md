# 커뮤니티 기여본 이식 점검표

외부에서 **번들(`simcore.plugin.js`) 수정본**을 받아 이식할 때의 절차.
v1.9.28(의뢰판·메신저 UI 기여본) 이식에서 나온 것을 절차로 굳힌 것 — 그때 네 군데가 걸렸다.

받는 것은 대개 번들 한 파일이다. **번들을 그대로 덮으면 안 된다** — 우리 정본은 `core/*` + `adapter/`이고
번들은 생성물이라, 소스↔번들 바이트 일치가 깨지면 다음 빌드가 남의 수정을 통째로 지운다.

## 1. 무엇이 바뀌었는지부터 (추측 금지)

기여본의 **base 버전**을 헤더에서 읽고 그 시점 번들을 꺼내 디프한다.

```sh
git show <base 커밋>:simcore.plugin.js > /tmp/base.js
diff -u /tmp/base.js <받은 파일> > contrib.diff
grep -c '^@@' contrib.diff     # 덩어리 수 — 이게 검토 범위의 전부다
```

디프에 안 잡힌 부분은 바이트 단위로 같다는 뜻이다. 이 한 줄이 "3.9만 줄짜리 파일"을
"13덩어리"로 줄여 준다.

⚠ **파일에 붙어 온 설명을 믿지 말 것.** v1.9.28 기여본 머리에는
`// Local compatibility rebuild: runtime logic is unchanged`가 붙어 있었는데 **사실이 아니었다**
(네 함수가 다시 쓰였다). 도구가 해시 불일치를 설명하려고 자동으로 넣은 문구로 보이지만,
그대로 두면 다음 사람이 "로직 안 바뀌었다니 디프는 건너뛰자"가 된다. **이식하지 않는다.**

## 2. 안전성 (추가된 줄만 보면 된다)

```sh
grep '^+' contrib.diff | grep -nE "fetch|XMLHttpRequest|WebSocket|eval\(|new Function|atob|btoa|\
document\.cookie|localStorage|sessionStorage|https?://|sendBeacon|apiKey|token"
```

플러그인은 유저의 리수 안에서 **유저의 API 키로** 돈다. 통신·저장소·키를 건드리는 추가가
있으면 거기서 멈추고 기여자에게 묻는다.

## 3. 실제로 도는가

- `node --check <받은 파일>` — 문법
- **새로 참조하는 식별자가 정의돼 있는가** (`nextEditorId`, `createdVariableCard` 같은 것)
- **새 마크업이 쓰는 CSS 클래스가 정의돼 있는가** — 하나씩 `grep -c "\.<클래스>[ ,{:>]"`
- ⚠ **폴백 없는 `var(--sce-*)`의 정의가 있는가.** 없으면 오류 없이 **그 선언 한 줄이 통째로 죽는다**
  (감싼 `color-mix()`까지). 기여본이 `--sce-warning-bg`·`--sce-success-bg`를 정의 없이 썼고,
  우리 팔레트에도 일곱이 같은 상태로 잠복해 있었다. `테스트/test-reportarea.js`가 전수로 본다.
- **받은 파일에 우리 테스트를 걸어 본다** — 가장 강한 확인:

```sh
cp simcore.plugin.js /tmp/backup.js && cp <받은 파일> simcore.plugin.js
node 테스트/test-editortabs.js          # 16탭 렌더 예외 없음
git checkout -- simcore.plugin.js       # 반드시 복원
```

## 4. 얹을 수 있는가

base가 현재 master보다 뒤처져 있기 마련이다. **그들이 손댄 함수가 그 사이 우리 쪽에서 바뀌었는지**만
보면 된다.

```sh
git diff <base> HEAD -- core/editor.js | grep "function tabQuest"   # 안 나오면 그대로 얹힌다
```

그다음 디프를 소스에 그대로 적용한다 (번들 줄 번호는 어긋나지만 문맥이 같아 오프셋만 밀린다):

```sh
{ echo "--- core/editor.js"; echo "+++ core/editor.js"; sed -n '<편집기 첫 덩어리>,$p' contrib.diff; } > editor.patch
patch --dry-run -p0 -F5 core/editor.js < editor.patch
```

적용 후 **반드시** `node build.js && cp dist/simcore.plugin.js simcore.plugin.js && cmp`로 바이트 일치.

## 5. 받은 그대로 얹지 않는다 — 내용 검토

기여자는 우리가 왜 그 문장을 썼는지 모른다. v1.9.28에서 실제로 되살린 것:

- **보증 문구** — "이미 있는 변수 목록이 함께 나가서 없는 이름을 못 지어낸다". 이 창구를
  믿어도 되는 **이유**라서, 짧게 줄이더라도 지우면 안 된다.
- **다음 길로 가는 버튼** — 💬 어시스턴트로 가는 `jumpRow`. 통 교체 경고 옆이 그 말이 필요한 자리다.
- **이름표 커버리지** — 오류 경로를 접기 뒤로 숨기는 UI라면, 대신 앞에 세우는 이름표가
  **전수**여야 한다. 넷이 빠져 "작업본"으로 뭉개지고 있었다.

일반화: **기여본이 문장을 짧게 만들었으면, 그 문장이 원래 무엇을 보증했는지 확인한다.**
디자인은 대개 기여자가 옳고, 문장이 왜 거기 있었는지는 대개 우리가 안다.

## 6. 마무리

- 걸린 것마다 **테스트로 못 박는다** (다음 기여본에서 같은 자리가 또 무너진다)
- 체인지로그에 **받은 그대로가 아닌 부분**과 그 이유를 적는다
- 버전·`display-name` 동반 범프 + `테스트/test-bundle.js` 핀
