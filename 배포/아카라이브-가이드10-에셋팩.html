0. 감정 이미지 봇, 매 턴 뭘 싣고 있는지 아는가


감정 이미지 쓰는 봇 열어보면 로어북에 이런 게 들어있음. {{assetlist}} 통짜 덤프 — 인물 8명 × 표정 70종이면 560줄이 매 턴 프롬프트에 실림. 거기에 수동 키워드 목록 + "이미지는 이렇게 넣어라" 지침 문단까지 하면 턴마다 700~900토큰이 이미지 안내에만 나감.


성인 키워드 목록은 대부분의 턴에서 완전한 낭비인데도 상시 실려 있고, 모듈 여러 개 붙이면 모듈마다 자기 이미지 규약을 프로즈로 들고 와서 문맥에서 서로 싸움. 같이 쓰면 찐빠 나는 이유가 이거임.


에셋 팩은 이걸 통째로 대체함. 핵심 아이디어는 하나임:


조합(인물×감정)을 칸(인물+감정)으로 바꾸면 목록이 곱셈에서 덧셈이 됨.

8×70 = 560줄 → 8+70 = 78줄. 감정 축은 인물과 무관한 공용 축이라 한 번만 적으면 됨.


그리고 조합·삽입을 시스템이 소유하니까 AI는 어느 모듈의 사설 규약도 배울 필요가 없음. AI는 "이번 장면 주인공 = Hana / 감정 = shy"만 고르고, Hana_shy로 붙이는 건 SimCore가 함.



1. 개념 — 팩과 칸


팩(pack) = 이미지 규약 한 벌임. 구분자가 뭐고(_인지 -인지), 출력 태그가 뭐고(<img="...">인지 모듈 전용 태그인지), 어휘가 뭔지를 한 카드에 선언함. 봇 자체 이미지가 팩 하나, 붙인 모듈이 팩 하나 — 규약이 서로 달라도 팩이 각자 흡수하니까 안 싸움.


칸(slot) = 에셋 이름의 조각임. Hana_shy라는 이름은 인물 칸(Hana) + 감정 칸(shy)이 구분자 _로 붙은 거. 칸을 몇 개로 쪼갤지는 자유임 — 인물_감정_의상 3칸도 되고, 의상 칸은 "생략 가능"으로 두면 인물_감정도 유효함.



2. 만들기 — 버튼 하나면 됨


봇 편집 사이드바에서 🎨 에셋 팩 층으로 가면 됨. 캐릭터에 에셋이 이미 들어있으면:


[🔍 에셋에서 자동 감지] — 실물 에셋 이름을 읽어서 구분자·칸 구조를 알아내고 팩 카드를 만들어 줌


"구분자 '_' 기준 78/80개 이름에서 칸 2개 감지" 이런 식으로 뜸. 유저가 할 일은 칸마다 이름표 달기(1번 칸 = 인물, 2번 칸 = 감정)랑 출력 태그 확인뿐임. 출력 태그는 그 봇의 표시 정규식이 알아듣는 문법 그대로 적어야 함 — 미리보기에 "예시 출력: <img="Hana_normal">"가 떠서 눈으로 확인 가능.


[스샷: 자동 감지로 만들어진 팩 카드]


[📇 실존 대조 새로고침] 누르면 팩이 선언한 조합 중 실물 에셋에 진짜 있는 게 몇 개인지 카드마다 표시됨. "필수 조합 480개 중 462개 실존 — 빠진 예: Seiko_wink" 이런 식. 인물마다 표정 개수가 달라도 상관없음 — 그건 아래 폴백이 알아서 처리함.



3. 팩 카드 칸 풀이


- 켜짐  체크 풀면 팩이 통째로 꺼짐. 모듈 잠깐 뗄 때 지우지 말고 이걸 끄셈
- 출처  이 팩이 어디서 왔는지 ("맨션봇 자체", "노조미 모듈 v1.2"). 나중에 모듈 뗄 때 어느 팩이 고아인지 알려면 꼭 적어야 함
- 구분자  이름 조각 사이 문자. 기본 _
- 출력 태그  {name} 자리에 조합 결과가 들어감. {칸id}도 자리표시자로 쓸 수 있어서 <char-noz emotion="{emo}"> 같은 모듈 전용 문법도 그대로 됨
- 게이트  조건식이 참일 때만 팩이 열림 (5절)
- 고정 인물  이름에 인물 칸이 없는 단일 캐릭 모듈용 — 여기 적은 인물이 뜨면 이 팩으로 감


칸마다는 어휘(쉼표 구분 값 목록), 생략 가능, 폴백이 있음. 폴백이 물건임:


폴백 사다리 — AI가 고른 조합(Hana_wink)이 실물에 없으면 → 같은 인물의 폴백 감정(Hana_normal)으로 강등 → 그것도 없으면 그 턴은 이미지 생략.

깨진 이미지가 뜨는 일이 구조적으로 없음. 인물마다 표정 개수가 달라도 팩엔 합집합 한 번만 적으면 되는 이유이기도 함.



4. 두 모드 — 누가 고르는가


팩이 하나라도 있으면 카드 위에 삽입 주체 선택이 뜸.


보조가 고름 (aux, 기본·권장) — 상태 갱신하러 어차피 도는 보조 AI가 "이번 장면 주인공·감정"을 얹어서 답함. 추가 LLM 호출 0, 메인 프롬프트에 실리는 목록 0. 실존 대조·폴백까지 다 돌아서 깨진 이미지도 0. 대신 이미지는 메시지당 1장, 본문 맨 앞에 붙음.


메인 모델이 직접 (main) — 칸 목록 + 조합 규칙을 지시문으로 매 턴 메인 프롬프트에 실음. 지금 손으로 쓰던 지침 블록을 시스템이 대신 쓰는 거라 곱셈이 덧셈 되는 절감은 같음. 문단 사이사이 여러 장 넣는 연출이 되는 대신, 실존 대조가 불가능해서 "확신 없으면 태그 생략해라" 지시로 버팀.


문단마다 표정이 바뀌는 연출 밀도가 중요하면 main, 비용·정확도가 중요하면 aux. ⚠ 루아 브리지로 쓰는 봇은 보조 결과가 한 턴 늦게 적용되니까(suggest랑 같은 제약) 이미지도 한 턴 늦게 붙음 — 브리지 환경이면 main을 추천함.



5. 성인 팩은 따로 만들어서 잠그셈


성인 키워드는 어휘만 다른 게 아니라 출력 형식까지 다른 경우가 있어서, 같은 팩 안에서 거르지 말고 팩을 하나 더 만들어서 게이트로 잠그는 거임.


게이트: nsfw_on  (bool 변수든, 지속 액션 무장 상태든, 아무 조건식이나 됨)


게이트가 닫히면 그 팩이 프롬프트에서 통째로 빠짐. 성인 어휘 45줄이 필요한 턴에만 실리는 거라 절감이 제일 큰 자리임. 조건 만들기 귀찮으면 지속(hold) 액션 하나 만들어서 켜고 끄는 게 제일 확실함 — 4탄에서 배운 그 무장 버튼임.



6. 남의 모듈 지침 옮기기 — 📋 모듈 지침 가져오기


이미 쓰던 봇이나 받아온 모듈엔 이미지 지침이 프로즈로 들어있을 거임. 🎨 층 아래 [📋 모듈 지침 가져오기]에 그 원문(키워드 목록 + 지침 문단)을 통째로 붙여넣고 [✨ AI로 팩 변환] 누르면 팩 선언으로 바꿔줌. 앱 내 AI가 없으면 [📋 변환 요청서 복사]로 외부 AI에 시키면 됨. 변환 결과는 검증 통과해야만 반영되니까 이상한 게 섞여 들어올 걱정은 안 해도 됨.


⚠ 변환했으면 로어북의 원래 지침 블록은 꼭 지우셈. 그대로 두면 시스템 주입이랑 이중으로 실려서 토큰만 두 배로 나감.



7. 실물 구경 — 연애 템플릿


연애 템플릿에 예시 팩이 들어있음. 인물 칸(Hana) + 감정 칸 6종 + 폴백(normal)짜리 표준형인데, 일부러 꺼진 채로 배송됨 — 어휘가 실물 에셋 이름이랑 맞아야 작동하는 기능이라서. 캐릭터에 Hana_smile 형태로 에셋 넣고 어휘 맞춘 다음(또는 자동 감지로 새로 만든 다음) 켜짐 체크하면 됨.


[스샷: 연애 템플릿 예시 팩 + 켜짐 체크]



정리


왜 씀  매 턴 실리던 이미지 지침(인물×감정 곱셈 목록)이 팩 선언 하나로 대체됨 — 목록이 덧셈이 되고, 안 쓰는 팩은 통째로 빠짐

만들기  🎨 에셋 팩 층 → [🔍 에셋에서 자동 감지] → 칸 이름표 달고 출력 태그 확인

모드  aux(기본) = 보조가 골라서 추가 비용 0·깨진 이미지 0, 맨 앞 1장 / main = 문단 사이 여러 장, 대신 목록이 매 턴 실림

성인 어휘  팩 따로 + 게이트(when)로 잠금 — 닫히면 통째 제외

모듈 지침  [📋 모듈 지침 가져오기]로 변환 → 원래 프로즈 블록은 삭제

안전  팩이 없으면 기능 자체가 꺼짐 — 기존 봇은 아무것도 안 바뀜


팩 만들었으면 카드의 실존 대조 줄 한 번 확인하는 거 잊지 마셈 — 선언한 조합이 실물에 몇 개나 있는지, 뭐가 빠졌는지 바로 보여줌.
