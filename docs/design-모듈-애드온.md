# 설계 — 모듈 애드온 (⚙simcore-addon)

> 2026-08-26, 유저 방향 확정. 미구현 — v0.94 모듈 팩 매니페스트의 다음 단계 후보.
> 원문: "모듈 자체에 모든 걸 싣어버리자니 그냥 봇으로 만들면 그만인지라. 딱 에셋 출력식과
> 캐릭터에 한정된 상태창 그 정도가 가장 적절해 보임 — 다른 봇 세계관이나 설정 그 외 기타
> 충돌 안 나게끔."

## 1. 선긋기 — 왜 "통짜 스키마 모듈"은 안 만드나

모듈에 스키마 전체를 실을 수 있으면 그건 봇의 다른 포장일 뿐이다 (봇으로 만들면 그만).
모듈의 본분은 **아무 봇에나 얹는 애드온** — 히로인 추가 모듈, 집사 모듈, 시스템 모듈.
그 본분에 맞는 것만 싣는다:

| 싣는 것 | 안 싣는 것 (봇 몫) |
|---|---|
| 자기 캐릭터의 변수 몇 개 (호감도·게이지·기분) | 시간·달력·시나리오 |
| 그 변수만 보여주는 상태창 칸 | 액션·판정·갈림길·명령 |
| **자기 변수만 읽고 쓰는 지시문·이벤트** (§1a) | 호스트 변수를 만지는 모든 것 |
| 자기 에셋 팩 (= v0.94 ⚙simcore-pack, 이미 완성) | promptState·커스텀 템플릿 |
| 자기 변수의 updater.allow 항목 (+desc 필수) | updater 지침·모델 설정 |

**세계관 톱니를 하나도 안 가져가므로 충돌 표면이 구조적으로 작다.** 호스트 봇이 심코어
봇이든 아니든(스키마 0개) 동작한다 — 후자가 오히려 주 사용처다 (아무 봇에나 모듈 켜면
그 캐릭 상태창이 뜬다).

### 1a. 지시문·이벤트를 왜 넣나 — "게이지는 반응이 없으면 장식이다" (유저 확정)

변수+상태창만 있는 애드온은 있으나 마나다 — 게이지의 존재 이유는 AI가 그 수치에 따라
**연기를 바꾸는 것**(지시문)과 문턱을 넘는 순간이 **사건이 되는 것**(이벤트·notify)이다.
충돌이 무서웠던 건 호스트 상태를 건드리는 이벤트지 이벤트 자체가 아니므로, 검증으로
참조 범위를 강제한다:

- 지시문 when·text의 `{변수}`, 이벤트 when·effects의 대상 = **애드온 자기 변수만.**
- **호스트 변수는 읽기도 금지** — 특정 봇에 묶이는 순간 "아무 봇에나"라는 이식성이
  죽으므로, 금지가 안전이자 설계 강제다.
- once·cooldown 허용, effects는 자기 변수 set/list만, notify 허용.

이 한 칸으로 활용처가 성립한다 (전부 유저 예시):
- **정신병 게이지 모듈** — 게이지 + 구간별 지시문("30 이하: 언행에 균열" / "0: 발작") +
  문턱 notify 1회
- **성욕 게이지 모듈** — 위와 같음 + **팩 `when` 게이트 연동**: "게이지 70 이상일 때만
  열리는 성인 이미지 팩". 애드온 변수가 팩 게이트를 연다 — 게이지·연출·이미지가 한
  모듈에서 맞물리는 완성형
- **파워 에너지 모듈** — 소모·회복은 보조 AI가 서사 따라 기록(desc), 바닥나면 지시문이
  "힘을 못 쓴다"를 강제

## 2. 규약 — ⚙simcore-addon 로어북 항목

v0.94 팩 매니페스트와 같은 꼴: 모듈 로어북 항목 하나, comment = `⚙simcore-addon`,
content = JSON. **허용 키 화이트리스트**로 범위를 구조로 강제한다 (금지 키가 있으면
그 키만 버리고 경고 — 깨진 매니페스트가 봇을 못 죽인다는 팩 원칙 그대로).

```json
{
  "name": "히로인 아리スAddon",
  "vars": [
    { "id": "aris_favor", "label": "아리스 호감도", "type": "int", "init": 20, "min": 0, "max": 100,
      "desc": "아리스와의 관계가 서사에서 실제로 진전·후퇴했을 때만 ±. 언급만으로는 움직이지 않는다." }
  ],
  "allow": [ { "id": "aris_favor", "maxDelta": 8 } ],
  "status": { "label": "아리스", "items": [ { "var": "aris_favor", "bar": { "max": 100 } } ] },
  "packs": [ /* ⚙simcore-pack과 같은 팩 정의 — 이 캐릭터의 감정 이미지 */ ]
}
```

- 변수 id는 애드온 제작자가 접두어로 자율 네임스페이스 (`aris_…`) — 강제 접두는 안 한다
  (기존 이름 규칙 그대로). **충돌 = 호스트·선착 우선, 해당 항목 skip + 경고** (팩 규칙 동일).
- desc는 사실상 필수 — 보조 AI의 기록 기준 (v0.93.1 원칙: AI는 기록자, desc가 기준).
- 병합된 변수·팩은 `origin:'module'` 표시 → 편집기 표시 전용·저장에서 걸러냄 (유령 방지).

## 3. 렌더 — 독립 박스가 답

애드온 상태는 호스트 상태창 **안**에 끼우지 않는다 — 호스트가 template 모드면 끼울 자리
자체가 없고, 그룹 모드라도 꾸미기 CSS와 얽힌다. **별도 `sim-status` 박스**로 호스트
상태창 아래 독립 렌더:

- 호스트 꾸미기·배치와 충돌 0 (자기 박스 안에서 끝)
- 호스트 스키마가 없는 봇 = 애드온 박스만 뜬다 (마커·렌더 파이프라인은 기존 것 그대로)
- 여러 모듈 = 박스 여러 개 (선언 순)

프롬프트 쪽은 자동 생성 한 줄 블록 (`[아리스 — 호감도 62/100]` 식) — promptState 템플릿을
애드온이 못 가져가는 대신 엔진이 변수 라벨·값으로 찍어 준다.

## 4. 상태 저장·수명

- 기존 세션 키 `sim:{캐릭터}:{채팅}` 그대로 — 애드온 변수도 같은 상태에 산다.
  (수치의 봇 간 공유 — 계정형 `sim:module:{id}` — 는 **비목표.** 봇마다 세계관이 다른데
  수치가 따라다니는 게 맞는지부터 별개 논의. 필요해지면 v2.)
- 판 중간 모듈 제거 → 변수 잔존값은 세이브에 남지만 무해 (막 축소 방어와 같은 규율).
  다시 켜면 이어진다.
- 판 중간 토글은 재스캔 필요 (팩과 동일 제약, 문서화).

## 5. 스캔 트리거 — 성능 원칙과의 충돌 해소가 핵심 미결

팩(v0.94)은 **스키마의 옵트인**(assets.moduleManifests)이라 "안 읽는다 = 안 멈춘다"가
성립했다. 애드온은 **스키마 없는 봇이 주 사용처**라 스키마 옵트인이 불가능하다. 후보:

- (a) 플러그인 @arg 전역 스위치 (기본 off) — 켠 유저의 모든 봇에서 로드 시 1회 스캔
- (b) 관리 패널 수동 버튼 ("모듈 애드온 읽기") — 무비용이지만 UX 한 단계 추가
- (c) pluginStorage에 "애드온 쓰는 유저" 깃발 — 첫 수동 스캔 후 자동화

(a)+권한 팝업 1회가 유력. **[집에서 결정]**

## 6. 제약 (팩과 동일 — 문서화만)

- **웹리스 불가** (getDatabase 자체가 없음) — 애드온은 앱 리수 전용
- 권한 거부 시 조용히 실패하면 "왜 안 뜸" 사고 → 패널에 전용 안내 + [권한 요청] 버튼 필수
- 루아 브리지는 카드에 실리는 물건 — 스키마 없는 봇 + 직접 호출 차단 환경이면 보조 갱신
  불가. 애드온 안내문에 명시

## 6a. 우선순위 — 착수 신호

"만들면 쓸 사람 있는" 기능이지 "지금 아픈" 기능이 아니다. **v0.94 팩 실기가 먼저** —
팩 실기에서 "정의·이미지만으론 부족하다, 게이지·연출도 모듈로 왔으면"이라는 신호가
오면 착수한다 (이 프로젝트 원칙: 길이가 아니라 찐빠·수요 증거로 움직인다).
