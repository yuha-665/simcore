## 요청 요약

SimCore의 기능 자체를 다른 방향으로 포크하려는 작업이 아니라, 실제 사용
중 반복적으로 확인된 편집 난이도·정보 밀도·필드 폭·설명 부족·좁은 화면
배치 문제를 줄이기 위해 관리 UI와 심층 편집기의 화면 구성을 다듬은
작업입니다.

핵심 원칙은 다음과 같습니다.

> **코드는 최신 공식판을 따르고, 기능이 바뀌지 않은 UI 영역은 검증된
> 기존 UI를 유지하며, 공식 기능이 추가·변경된 부분만 같은 디자인
> 규칙으로 적응한다.**

따라서 엔진 기능을 UI 취향 때문에 재설계하기보다는 기존 스키마·실행
계약을 보존하고, 사용자가 기능을 이해하고 편집하는 층을 개선하는 데
초점을 두었습니다.

## 디자인 방향

-   큰 둥근 카드의 반복보다 **얇은 경계선, 작은 반경, 그래파이트 계열
    표면, 제한적인 파란 강조색**을 사용합니다.
-   모든 입력을 같은 폭으로 만들지 않고 ID·숫자·선택값·긴
    프롬프트·JSON·CSS 등 **실제 값의 성격에 따라 폭과 배치를 다르게**
    잡습니다.
-   섹션은 장식보다 **제목 → 설명 → 작업 영역 → 보조/고급 기능** 순으로
    읽히게 구성합니다.
-   기능이 많은 화면도 중첩 카드를 무한히 쌓지 않고 얇은 workgroup과
    구분선으로 위계를 만듭니다.
-   좁은 화면에서는 필요한 부분만 1열로 전환하고 긴
    제목·메타데이터·버튼이 서로 눌리지 않도록 보정합니다.
-   위험/삭제 기능, AI 보조 기능, 고급 CSS 기능은 주 작업보다 낮은
    시각적 위계에 둡니다.
-   색상만으로 상태를 구분하지 않고 문구·구조·아이콘을 함께 사용합니다.

## 적용 범위

### 1. 관리 패널 / 현황

새 시작과 다음 행동, 상태 변수와 엔진 요약, 클릭 조작과 보조 모델 연결
테스트를 역할별 작업 영역으로 분리했습니다. 세션 시계를 별도 전폭
영역으로 정리하고 잠긴 액션의 비활성 이유를 가까이 보여 주며, 상태 변수
수동 조작의 짧은 값이 불필요하게 넓은 입력을 차지하지 않도록
정리했습니다.

### 2. 도움말

단순 기능 나열보다 실제 한 턴의 흐름과 변수 → 파생 → 규칙 → 액션 → AI
설정의 관계를 따라 읽을 수 있도록 재구성하고 내부 개발 용어 노출을
줄였습니다.

### 3. AI 어시스턴트

창작/생성, 결과 확인, 진단의 역할을 분리했습니다. `스킨만 / 배치까지`의
기존 흐름을 유지하면서 요청 입력과 결과 확인 공간을 정리했고, Hallmark
계열 보정은 사용자가 선택했을 때만 추가 지침으로 붙도록 유지했습니다.

### 4. JSON 관리자

전체 작업본과 부분 수정 작업을 구분하고 검사 → 구성 확인 → 적용 →
되돌리기의 상태를 분리했습니다. 긴 결과는 다시 접을 수 있도록 했습니다.

### 5. 에셋 관리자

연결 설정, 도구, 비용/검증 상태, 팩 목록의 우선순위를 정리하고 팩/슬롯
설정을 실제 값 길이에 맞게 배치했습니다. 에셋 해석 및 모델 연결 코어
자체는 UI 편의 때문에 재설계하지 않았습니다.

## 심층 편집기

현재 탭 순서는 다음과 같습니다.

`변수 → 명령 → 상태창 → 편성표 → 달력 → 보드 → 상점 → 규칙·이벤트 → 시나리오 → 액션 → 판정 → 시간 → 새 시작 → AI 설정`

작업도구 내비게이션 순서는 기존 확정 순서를 유지하며 임의 재배치하지
않았습니다.

### 6. 변수

변수 ID/형식 → 형식별 값 → 상태창/AI 관련 정보 순으로 통일하고
int/float/text/bool/enum/list 각각 필요한 입력만 표시합니다. 오류 문구,
참조 중 ID 변경 경고, 삭제 되돌리기, 접기, 문제 중심 확인, 자동 ID와
이동 보조를 정리했습니다.

### 7. 명령

연결 변수 선택 후 해당 형식에 맞는 명령과 사용 예시를 확인하는 흐름으로
정리했습니다. 빈 화면 방어, 문제 중심 확인, AI 작업 영역의 폭과 위계를
보완했습니다.

### 8. 상태창

핵심 설정, 자동 구성/커스텀 HTML, 그룹, 개별 항목을 역할별로
분리했습니다. 개별 항목은 과밀한 단일 행 대신 2단 정보 구조로 정리했고
게이지·최대값·표시 조건·색상 등 조건부 설정은 필요할 때만 보이도록
했습니다. 액션 사용 안내 문구만 숨기는 옵션도 제공하되 액션 자체와 잠긴
액션 목록은 유지합니다.

### 9. 편성표

기존 기능과 데이터 계약을 유지하면서 카드/필드의 정보 위계와 폭을 공통
UI 규칙에 맞췄고 긴 값과 좁은 화면에서 조작부가 서로 밀지 않도록
정리했습니다.

### 10. 달력

공식 달력 기능과 `list + @기한` 규약을 유지합니다. 달력 설정과 공식
monthView 기반 미리보기를 분리하고, 기념일은
`1회 지정 / 매년 / 매달 / 매주`에 필요한 날짜 필드만 노출합니다. 1회
지정의 연도를 포함한 날짜 입력은 2단 구조로 안정화했습니다.

편집기에서 별도로 제공하던 **새 채팅용 일회성 일정 seed 입력 UI**는
실사용에서 레이아웃 파손을 유발해 제거했습니다. 실제 달력의 일정
등록/삭제, list 변수, `@기한`, expire 자동 정리, AI 일정 등록, monthView
표시 기능은 유지합니다.

### 11. 보드

보드 기본 정보, 게시물 정의, 자동 동작, 고급/AI 기능을 구분하고 카드
위계를 보강했습니다. 좁은 화면에서 제목과 메타데이터가 서로 압박하지
않도록 보정했으며 클릭 가능한 보드 행의 Enter/Space 키보드 접근을
보강했습니다.

### 12. 상점

기본 설정, 상품 분류/가격, 판매, 환전, 운영 지침, 화면 꾸미기를 역할별로
나눴습니다. 좁은 화면의 stock 행과 운영 지침 textarea의 실기 레이아웃
문제를 국소 수정했습니다. 상점 코어·환전·구매 규약은 유지합니다.

### 13. 규칙·이벤트

규칙, 이벤트, 효과, 통지, 시험 실행의 관계가 읽히도록 정보 위계를
정리했습니다. 기존 1턴 시험 실행과 실제 엔진 규약은 유지합니다.

### 14. 시나리오

전체 진행 요약과 각 막의 기본 정보, 진행 조건, 공개 연출 지시, 비공개
내막, 전환 통지, 진입 효과를 분리했습니다. 첫 막에서 사용되지 않는
해금/minTurns의 의미를 안내하고 `secret`은 위험 설정이 아니라 비공개
서사 정보로 취급합니다. 막 추가/삭제/순서 변경과 진행 엔진은 유지합니다.

### 15. 액션

액션 한 개를 하나의 작업 카드로 보고 기본 정보 → 사용 조건 → 비용/소모 →
판정 연결 → 효과 → 모델 전달/통지 → 고급 동작 순으로 읽히게
정리했습니다. requires, cooldown, 효과 실행, toggle/arm/once 계열 동작,
판정 연결 및 1턴 시험 실행은 유지합니다.

### 16. 판정

판정 설정을 식별 정보, 조건/굴림, 성공·실패 결과, 효과/통지 등 실제 편집
순서에 맞춰 정리했습니다. 판정 엔진과 액션 연결 계약은 유지합니다.

### 17. 시간

시간 체계 선택과 현재 설정, 노출 변수, 시간 이동 관련 조작을 역할별로
정리했습니다. 시간 엔진의 예약 키와 날짜/시간 계산 계약은 유지하며
내보내기/가져오기 흐름을 찾기 쉽게 정리했습니다.

### 18. 새 시작

최초 시작 설정과 프리셋을 분리하고 시작 시점 입력 폭을 실제 날짜/시간
값에 맞게 넓혔습니다. 프리셋 미리보기, 적용값 차이, startAt 등 기존
기능을 유지하며 AI 최초 설정 도구는 낮은 위계로 분리했습니다.

### 19. AI 설정

상태 요약 프롬프트, 보조 모델 업데이트 허용 변수, 감지/잠금/등장 조건 등
기존 AI 설정을 기능군별로 정리하고 긴 설명과 프롬프트의 편집 공간을
개선했습니다.

## 런타임 관련 주의 --- v1.7.5 스트리밍 중복 처리 대응

UI 작업 도중 실제 Risu 스트리밍 환경에서 한 메인 응답에 보조 처리와 상태
갱신이 여러 번 실행되는 문제가 확인되었습니다. 공식 후속 수정 방향을
따라 다음 안전장치를 반영한 상태입니다.

-   `chat.isStreaming === true`를 스트리밍 판정의 우선 신호로 사용
-   문자열 비교는 구버전/폴백 판정으로 유지
-   한 실제 턴에 대한 처리 guard를 `chaIdx:chatIdx` 기준으로 둠
-   guard는 새 요청의 `beforeRequest`에서 초기화
-   inline/settle의 outIndex가 달라질 수 있으므로 guard key에 outIndex를
    넣지 않음
-   스트리밍 중 확정 처리를 반복하지 않고 최종 저장 메시지를 기준으로 한
    번 정산

이 부분은 순수한 디자인 변경과 성격이 다르므로 upstream 검토 시 **UI
커밋과 분리해서 검토**하는 것을 권장합니다.

## 원작자에게 요청드리는 병합 방식

전체 파일을 그대로 교체하기보다 다음처럼 나눠 검토해 주시는 편이
안전합니다.

1.  공통 UI 토큰/간격/입력 폭/반응형
2.  현황·도움말 등 표시 중심 화면
3.  JSON·에셋 관리자 UI
4.  변수·명령·상태창
5.  편성표·달력·보드·상점
6.  규칙·이벤트·시나리오·액션·판정
7.  시간·새 시작·AI 설정
8.  편집기 전용 조작 보조 --- 접기, 이동 피드백, 삭제 되돌리기, 키보드
    조작 등
9.  v1.7.5 스트리밍/턴 중복 처리 대응 --- UI와 별도 runtime 검토

특히 8\~9는 단순 CSS/DOM 재배치가 아니므로 별도 커밋으로 분리하는 편을
권장합니다.

## 보호해야 할 범위

-   공식 스키마 및 데이터 의미
-   엔진의 변수/파생/규칙/이벤트/액션/판정/시간 처리 계약
-   공식 공개 API 및 Risu 플러그인 API 연결
-   실제 게임 패널의 기능 계약
-   보조 모델/생성 모델 호출 방식
-   달력 `list + @기한` 및 expire 규약
-   시나리오 unlock/minTurns/direct/secret/onEnter/notify 의미
-   기존 작업도구 내비게이션 순서
-   `FLOOR` 매핑
-   공식 기능이 바뀌지 않은 영역의 기존 검증 UI

## 검증 상태

정적 검사와 실제 Risu 화면 확인을 같은 것으로 취급하지 않았습니다. 여러
UI 탭은 실제 Risu 화면에서 사용자 피드백을 반복 반영했지만, 모든 폭·모든
데이터 조합의 회귀가 완전히 증명되었다고 주장하지 않습니다. upstream
병합 시 공식 최신판에 이식한 뒤 데스크톱/좁은 폭, 기존 스키마 불러오기,
저장/복원, 실제 게임 패널, 스트리밍 on/off를 다시 확인하는 것을
권장합니다.

-   본 파일은 공식판을 사칭하는 배포물이 아니라 UI/UX 개선 제안용 비공식
    작업본입니다.
-   최종 병합 여부, 코드 정리, 명칭, 버전 정책은 원작자의 판단을
    따릅니다.
-   외부 참고 프로젝트/가이드가 사용된 부분은 해당 자료의 라이선스와
    출처 정책을 따릅니다.

## 전달 메시지용 짧은 요약

안녕하세요. SimCore를 실제로 사용하면서 편집 UI를 중심으로 계속 손본
비공식 개선본을 전달드립니다.

엔진을 다른 방향으로 포크하기보다는 공식 기능과 스키마를 최대한
유지하면서, 관리 화면과 각 심층 편집 탭의 정보 위계·입력
폭·설명·반응형·오류 가독성을 정리하는 쪽으로 작업했습니다. 최근 탭까지
실제 사용 화면을 보며 반복 수정했고, 달력/보드/상점/시나리오/액션 등
후반부 편집 화면도 같은 UI 규칙으로 맞췄습니다.

전체 파일을 그대로 병합해 달라는 의미보다는, 원작자님이 괜찮다고
판단하시는 UI/UX 변경을 선별해서 공식판에 적용할 수 있는 참고 구현으로
봐주시면 좋겠습니다. 런타임 쪽 변경은 UI와 분리해서 검토할 수 있도록
문서에 따로 적었습니다.
