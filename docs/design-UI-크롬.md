# 서랍 — UI 크롬·게임감 강화 (미착수, 아이디어 보관)

> 2026-08-26. 계기: 스카이림 플러그인(PageFold, S2D 계열 시나리오 감독 v0.9.26) 스샷 —
> 퀘스트 일지 패널·분기 트리·시네마틱 선택 확정 카드. "심코어도 저런 식이었으면" (유저).
> **정리만 하고 착수 안 함.** 우선순위는 팩 실기 등 뒤.

## 0. 제약 — 어디는 만지면 안 되나

- **관리 패널·편집기 크롬 = 동결.** UI 개조판(docs/기여-UI개조판-v0.61.md, 브랜치
  feat/ui-mod)이 그 영역을 재구성 중 — 공식판이 크롬을 흔들면 개조판과 계속 충돌한다.
  일부러 안 건드리고 있는 것 (유저 확정).
  - **2026-09-07 갱신 — CSS 층은 흡수한다.** 개조판 2탄(v1.0.7 기준, docs/기여-UI개조판-v1.0.7-요청.md)의
    **편집기 CSS 층만** 공식에 이식 (브랜치 feat/ui-css → v1.7.13). 유저 판단: "UI 자체는 확실히 더 깔끔". 개조본의
    룩을 공식이 품으면 그 분이 다음 판을 최신 공식 위에 얹기 쉬워져 충돌이 오히려 준다 — 동결의 목적이 그거였다.
    이식 범위 = 토큰·기존 클래스 재스타일·@media (916규칙). **버린 것** = 개조본이 새로 짠 DOM 전용 셀렉터 1,233규칙
    (탭 그룹·time workbench·2단 카드…) — DOM 재구성은 CSS로 못 옮긴다. 관리 패널 CSS는 v0.61 재병합 블록이 이미
    있어 그대로 두었다(개조본 전용 29규칙은 `.sc-play-grid` 등 그쪽 DOM용). **채팅 상태창 BASE_CSS는 양쪽 다 안 건드림.**
    이식 도구 = 스크래치의 filter.js(모드 CSS를 규칙 단위로 파싱 → 셀렉터의 모든 클래스가 우리 DOM에 있을 때만 유지).
    개조본이 참조만 하고 정의 안 한 토큰 5종(`--sce-border`·`--sce-font-body`·`--sce-success-soft`·`--sc-weekend-sat/sun`)은
    `.sce` 블록에 폴백을 줬다. 실기 확인 항목: 15탭 전부 열어 입력 폭·좁은 화면·달력 미리보기 주말색.
  - **2026-09-07 2차 — DOM까지 흡수 (같은 브랜치).** CSS만 옮기니 "뭐가 바뀐 건지 모르겠다"(513/620 규칙이 이미 같았다).
    시간 탭을 개조본 DOM으로 통째 바꿔 보인 뒤 유저 승인("오 잘바뀌었네") → 편집기 탭 함수 16개 전부 + 어댑터 9함수를
    개조본 본문으로 교체. 방식 = **함수 단위 드롭인**(v1.0.7 이후 우리 변화 0줄인 탭) + **3-way**(우리 델타를 개조본 본문에
    되살림: 편성표 wide·액션 자동 동작 3칸·보드 범위 글수/화제 기사·상점 perCat/시세/단위/다중 환전/다중 상점·에셋 실황/
    확장자 관대/모듈 팩 카드·어댑터 캐시 비우기/정규식 덧붙임/의뢰판·메신저 CSS). 상점은 개조본 6단 섹션을 최상위
    헬퍼(shopField·shopSection)로 올려 shopFieldBlock이 상점마다 찍는다. 탭 내비는 4묶음(기본·세계·진행·자동화 — 개조본은
    3묶음, 우리 탭이 16개라 '게임 규칙' 12개를 둘로 나눔). **우리 것 유지** = 메신저·의뢰판 탭(개조본에 없음), processTurnOutput
    스트리밍 가드(v1.7.5), 시작 시각 무작위 기본 6~22시. **개조본에서 새로 들인 것** = 검증 오류 친절화·점프, 관리 패널
    SVG 내비 아이콘·변수표 스크롤·인라인 오류 안내, 달력 주말색·6주 고정, 사이드 메뉴(햄버거) 런처, 문구 "무장"→"준비".
    테스트는 동작 단언 그대로 두고 문구·식별자 핀만 갱신(mkItem→makeStatusItem, pair→field, pv→core-pv 등).
    옛 상태창 항목 행 규칙 8개(CSS 1차 때 되살린 것)는 DOM이 바뀌며 용도 소멸 → 삭제.
- 만질 수 있는 자리 = **채팅 쪽 상태창** (render.js BASE_CSS·THEMES·카드) — 개조 범위 밖.
  게임 패널(대장 탭 등)은 개조 범위인지 확인 후. 봇별 꾸미기(customCSS·템플릿)는 원래
  제작자 자유 영역이라 무관.

## 1. 저쪽이 잘한 것 (분석 요약)

- 활자·글리프 승부: ◆/◇ 마름모, 라벨 자간, `PAGE · 01` 쪽번호 표식 — 기능이 아니라 서체·여백 규칙
- 디제틱 프레임: 대시보드가 아니라 "게임 안 퀘스트 일지"인 척 (좌 색인 + 우 페이지 = 책)
- 인챗 시네마틱 카드: 선택 확정을 가운데 대문짝으로 — 체감의 8할
- 키보드 어포던스: Tab 뒤로 / Enter 저장 / N HUD — 콘솔 게임 메뉴 감각
- 단, 저쪽은 자체 세션이 화면을 점유하는 설계라 가능한 것 (전면 모달·단축키).
  심코어의 "리스 본체 안 건드림·타 플러그인 무충돌"과 트레이드 — 그건 안 판다.

   원칙은 기본 테마가 지키고, 장르 몰입은 테마가 진다 (mystery 사건 파일과 같은 규율).

## 3. CSS 베이스 전략 (유저 방향)

직접 발명하지 말고 **CSS 전문 공유 사이트의 스니펫을 베이스**로 삼는다 — 테마 추가나
AI 꾸미기 규격서의 참고 베이스로. **아카라이브에 배포되는 봇에 실리므로 라이선스가
확실한 것만** (MIT/CC0 위주, 출처 주석 남기기).
