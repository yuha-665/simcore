# 설계 — 편성표 (게임 패널 1호, v0.55 → 탭 v0.56)

> 2026-08-01. 레코드 층 순서 2의 구현 — **"파티 편성표는 레코드 없이 지금 재료로 된다"**
> (design-레코드.md). 에셋 완주 직후, 유저의 다음 목표(편성표 → 장비창 → 상점 → 스킬트리)의 첫 판.
> v0.55 실기 확인 당일 유저 제안으로 **탭(v0.56)** 확장 — 롤모델은 칸코레.

## 결정 — 사이드바 재편 (유저 결정)

> "이런 게임용 UI 출력부분은 액션버튼이 차지하는 사이드바로 할당하자. 액션버튼은
> 상태창 아래 뜨는 걸로 충분할 것 같아 — 이제 굳이 양쪽에 있을 필요 없을 듯."

- 우상단 `registerButton(location:'action')` 자리에서 **액션별 플로팅 버튼 제거** (v0.11~v0.54).
  v0.42 클릭 조작(상태창 범례가 진짜 버튼)이 생긴 뒤로 같은 버튼이 두 군데 있었다.
- 그 자리는 **게임 패널을 여는 유틸 버튼** 몫 — 지금은 편성표 하나, 장비창·상점도 이 통로로.
- 액션 토글 통로 셋:
  1. **상태창 범례 클릭** (v0.42, mainDom 권한) — 주 통로
  2. **편집기 패널**의 액션 토글
  3. **`/액션 이름`** 채팅 명령 (v0.55 신설) — mainDom 거부 환경의 폴백.
     /선택과 같은 내장 명령이고, `toggleAction`과 같은 검증(쿨다운·when)을 탄다.
     변수 cmd가 '액션' 이름을 선점하면 내장은 양보한다 (하위 호환).

## 게임 패널 (#sc-game)

- `showContainer('fullscreen')` 하나뿐인 컨테이너를 편집기(#sc-root)와 나눠 쓴다 —
  겉모습은 **팝업**(배경막 + 가운데 카드). 열 때 상대 루트를 `display:none`으로 비켜 준다.
- **우리 iframe DOM이라 클릭이 온전하다.** 좌표 히트테스트의 격자 취약성
  (리렌더마다 좌표가 흔들림 — design-레코드.md의 경고)이 여기엔 아예 없다.
  그 경고는 메인 채팅 DOM 얘기였고, 패널은 처음부터 그 문제 밖이다.
- 패널이 떠 있는 동안 `panelVisible = true` — 히트테스트 휴식·권한창 가림 방지 규약을
  편집기와 공유한다.
- **제작자 CSS**: `schema.party.css`를 `scopeCss(css, '#sc-game')`로 가둬 주입 —
  상태창 customCSS와 같은 기계, 같은 안전 규약 (앱 UI를 못 깨뜨림).
  클래스: `.scg-card .scg-title .scg-slot .scg-slot-label .scg-slot-val .scg-chip
  .scg-chip.scg-on .scg-chip.scg-used .scg-chip.scg-locked .scg-roster` +
  슬롯·칩에 `data-slot` / `data-val` 속성 (인물별 색).

## 편성표 데이터 모델 (schema.party)

```json
{
  "party": {
    "label": "편성", "icon": "⚔️",
    "slots": [ { "var": "front", "label": "전위" }, { "var": "rear" } ],
    "roster": "allies",
    "empty": "없음",
    "note": "동료를 영입하면 편성할 수 있다."
  }
}
```

- **슬롯 = enum 변수 하나.** 그 enum의 값 목록이 편성 후보다 — 제작자가 확정하고
  **AI는 명사를 못 만든다** (레코드 층 원칙 그대로). 슬롯마다 enum이 따로라
  "전위엔 전사만" 같은 슬롯별 제약이 값 목록으로 자연스럽게 표현된다.
- **보유 = list 변수 (roster).** 지정하면 목록에 있는 이름만 후보로 열린다 —
  영입/이탈은 보조 AI·명령이 목록을 움직인다 ("존재한다"와 "가지고 있다"의 분리).
  목록 규약 꼬리(`아린 @3일`, `바크 +2`)는 걷어내고 이름만 대조한다.
- **empty = 빈 슬롯 값.** 각 슬롯 enum에 있어야 한다 (없으면 비울 수 없음 — 검증이 잡는다).
- **중복 편성** (unique, 기본 켜짐): 이미 딴 슬롯에 앉은 인물을 고르면 게임 표준대로
  **이동**(원래 자리를 empty로), empty가 없으면 **맞교환**.
- **저장은 그냥 변수.** 상태창 `showWhen`·지시문 `when`·프롬프트 템플릿이 전부
  그대로 읽는다 — **새 표시 문법이 하나도 없다** (v0.31 기능이 그대로 화면 전환을 맡는다).
- AI도 편성을 움직이게 하려면 슬롯 변수를 `updater.allow`에 넣으면 된다 (선택 사항 —
  기본은 유저 전용, 편집기 탭이 현재 상태를 알려준다).

## 탭 (v0.56) — 롤모델 칸코레

> 유저 제안: "편성을 더 추가할 수 있게 — 수복·제작 이렇게 늘리고, 편성마다 탭에
> 버튼을 추가해 이벤트/규칙 연결하게."

```json
"party": {
  "label": "함대", "icon": "⚓", "empty": "없음", "roster": "ships",
  "tabs": [
    { "id": "f1",   "label": "제1함대", "slots": [{"var":"f1_flag","label":"기함"}], "actions": ["sortie"] },
    { "id": "f2",   "label": "제2함대", "slots": [{"var":"f2_flag"}] },
    { "id": "dock", "label": "수복",   "roster": "dock_q", "slots": [{"var":"dock1"}] },
    { "id": "fac",  "label": "제작",   "actions": ["build"] }
  ]
}
```

- **탭 = 편성 하나 또는 시설 하나.** 슬롯이 있으면 편성 탭, 슬롯 없이 `actions`만 있으면
  수복·제작 같은 **시설 탭**. 둘 다 없는 탭은 검증이 막는다.
- **탭 버튼 = 기존 액션.** 이게 핵심 — "이벤트/규칙 연결"에 새 트리거 기계가 필요 없다.
  액션이 이미 effects(규칙)·check(판정)·inject(서사 전달)로 배선돼 있으므로, 팝업 칩이
  `onActionButton`을 그대로 부른다. 무장 ●·잠금 🔒 표시는 상태창 범례·조작줄과 같은 출처
  (`currentActionStates`)라 세 자리가 항상 짝이 맞는다. "출격" = 액션 하나 만들고 탭에 걸면 끝.
- **탭별 roster 오버라이드** — 수복 탭은 `dock_q`(대기열)만 열고, 함대 탭은 공용 `ships`를 쓴다.
- **한 인물 = 한 자리, 탭을 가로질러.** 1함대 기함을 2함대에 앉히면 1함대에서 이동해 온다
  (usedBy·이동·맞교환이 전부 탭 무관 — 칸코레의 "한 함선은 한 함대" 규칙).
- **축약형 하위 호환** — v0.55의 최상위 `slots`/`actions`는 탭 1개로 정규화된다.
  tabs와 혼용하면 검증 오류 (어느 쪽이 이기는지 아무도 모르게 되는 상태를 안 만든다).
- 편집기: 축약형에서 [🗂 탭 구조로 전환] 버튼 → 탭 추가/삭제/정렬 + 액션 체크 연결.

## 초상 (v0.57) — 팝업에 캐릭터 에셋

봇들이 CSS 사이드 패널에서 쓰는 `{{raw::이름.png}}`는 **메시지 렌더 전용 CBS**라
우리 iframe 팝업에서는 안 통한다. 대신:

```json
"party": { "portraits": { "레닌그라드": "leningrad_profile", "민스크": "minsk_profile" } }
```

- 어댑터가 `getCharacter().additionalAssets`([이름, assetId, 확장자])에서 이름을 대조하고
  `readImage(assetId)`로 실물을 읽어 blob URL로 그린다. 확장자는 생략 가능.
- **명시 맵인 이유**: 한글 함명 ↔ 영문 에셋명은 자동 유도가 안 되고, 근사매칭은 에셋 팩에서
  이미 버린 방식이다. 오타는 검증이 경고로 잡는다 (조용히 안 뜨는 사고 방지).
- 실패 사다리: readImage 없음/차단 → 글자 폴백(이름만) + 콘솔 1회 안내. 편성 기능은 무손상.

## 업그레이드 (v0.58) — 스킬창·시설 레벨·특성

레코드 문서가 "레코드 타입 필요"로 분류했던 스킬트리가, 범위 확정("굴린 값을 계산에 안 쓴다")
뒤에는 **지금 재료로 된다**: 스킬 = int 변수(레벨), 선행조건 = 조건식, 찍기 = 포인트 차감 + 레벨 +1.

```json
{ "id": "train", "label": "수련", "points": "sp",
  "items": [
    { "var": "skill_sword", "cost": 1 },
    { "var": "skill_heal", "cost": 1, "requires": "skill_sword >= 2", "requiresLabel": "검술 2 필요" },
    { "var": "mine", "cost": "(mine + 1) * 30" }
  ] }
```

- 탭 종류 셋: 편성(slots) / 시설(actions) / **업그레이드(items)** — 버튼 하나에 다 들어간다.
- `cost`는 숫자 또는 식 — 식이 자기 레벨을 참조하면 점증 비용. `points`는 탭별 오버라이드
  (스킬=SP, 시설=골드 — roster와 같은 규약). **max 1 항목 = 특성(해금).**
- 내리기(환불) 없음 — 게임 표준이고 포인트 세탁 여지를 안 만든다.
- 파생 연동은 공짜: `mod: "... + skill_sword"` 같은 식을 판정·파생에 쓰면 찍은 레벨이
  굴림에 바로 반영된다 (성공/실패 판정까지가 어울린다는 범위 확정 그대로).
- 유저가 말한 파생들이 전부 이 위에 있다: 영지 시설 레벨(포인트=골드), 특성(max 1),
  정책(enum — 편성 슬롯 또는 /명령으로 이미 가능).

## 편성 연동 (v0.59) — deployed 가상 목록 + 탭 표시 조건

유저 제안(2026-08-01): "편성에 들어온 애들만 상태창에 보여주기, 스킬창 목록에서도 —
그렇게 하면 인벤토리랑 다른 것도 관리 가능할 거고." v0.58.1 셀렉트+검색이 "많은 탭에서
찾기"라면, 이쪽은 "안 볼 탭을 아예 안 보이기" — 두 기능이 겹벌이가 된다.

핵심은 새 함수가 아니라 **가상 목록 하나**:

- `deployed` — 편성 슬롯(모든 탭)에 앉은 이름들의 읽기 전용 목록. 편성표가 있으면 자동 제공.
  `has(deployed, '아린')`이 상태창 showWhen·지시문 when·이벤트 조건·requires·`{deployed}`
  자리표시자 어디서든 통한다. 꽂은 곳은 두 관문뿐 — allIds(validate)와 makeLookup(engine).
  같은 id의 실제 변수/파생이 있으면 그쪽이 이긴다 (+ 그림자 경고).
- `party.tabs[].when` — 표시 조건. 거짓이면 탭이 뷰에서 통째로 숨는다. 인물별 스킬트리
  탭을 `has(deployed, '이름')`으로 걸면 편성된 인물의 탭만 남는다.
  - 숨은 탭의 자리 점유는 유효 (한 인물 = 한 자리 유지 — seat 지도는 allSlots 기준)
  - 깨진 식은 보이는 쪽으로 넘어진다 (조용히 사라지면 원인을 못 찾는다 — 검증이 잡는다)
  - 모든 탭이 숨으면 이유를 말하는 안내문 (+ 전 탭 when이면 검증 경고)
- 진단: deployed를 보는 액션/이벤트 = 편성 게이트 (low '편성 담당 문턱/이벤트', v0.52 원칙)
- 템플릿 예: RPG 지시문 `arin_in_party` (아린 편성 시 서사 지시), 함대 정비창 탭
  `when: "count(damaged) > 0 or dock1 != '없음'"` (볼 일 있을 때만 — dock1 조건은
  수리 끝난 함이 정비석에 남은 동안 탭이 사라져 자리가 잠기는 것을 막는다)

v0.59 실기 확인:
- [ ] 아린 편성 → 수련(인물) 탭이 나타나고, 빼면 사라지는가
- [ ] `has(deployed, ...)` showWhen이 편성 직후 상태창에 반영되는가
- [ ] 모든 탭 숨김 안내문

## AI 경로·진단의 편성표 대응 (v0.60)

v0.55~59 동안 편성표가 자랐는데 AI 제작 경로가 못 따라온 것을 일괄 보수 (유저 지적).

- **규격서**: 최상위 키에 `party` 등재 + `SCHEMA_PARTY_RULES` 절 — 검증기 원문은 "있으면
  검사"지 "만들라"가 아니라서, 절이 없으면 AI는 party의 존재 자체를 모른다.
- **패치 요청서**: party는 패치 불가로 명시하되, **다이제스트에 편성표 참조 절**을 실어
  편성표가 가리키는 액션·변수의 remove를 금지시킨다 (지우면 가져오기 정지 — AI가 원인을
  모르는 사고의 예방).
- **부분 요청서**: `TAB_SLICES.party` — [편성표] 탭에도 AI 도구. party 통째 교체라
  portraits·css "원문 그대로" 지시 + 기존 액션 id 계약 동봉. ⚠ 편집기 seg는 테스트가
  단독 평가(new Function)하므로 **seg 안에서는 require 금지** — 정규화는 인라인.
- **진단 정적 검사 3종** ("측정 불가" 원칙의 반대급부 — 정말 죽은 경로는 정적으로 잡는다):
  ① 못 버는 포인트 ② 영입 경로 없음 ③ 열리지 않는 탭 (deployed·슬롯·팝업 이동 값이
  조건에 끼면 편성 게이트 = 정상이라 안 잡는다).
