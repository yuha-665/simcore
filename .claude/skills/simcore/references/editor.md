## 1층 — ✨ AI 어시스턴트 (`topFloor`)

내부 탭 3개 (빈 스키마면 창작만): **✍ 창작 / 👁 결과 / 🔬 진단**

- **✍ 창작**: 🧩 기능 카드 먼저, 자유 입력은 그 아래. 기존 작업본이 있으면 부분 패치 생성
  (변경 계획 확인 → 적용 — JSON 관리자의 패치 검사와 같은 UI·같은 규율).
- **👁 결과**: 상태창 미리보기 + `디자인 생성`(🎨 꾸미기 창구 — 아래 참조) + 만들어진 것들
  (변수/이벤트/액션/판정/지시문 개수 + 세부 목록 접기).
- **🔬 진단**: 아래 진단 절 참조.

### 🧩 기능 추가 카드 (`FEATURE_RECIPES`, 9종)

카드 = 고정 패치가 아니라 **요청서** — `tabWant[슬라이스]`를 채우고 그 탭의 직결 생성을 부른다.
검사·계획 확인·되돌리기 전부 탭별 도구의 것을 그대로 탄다. steps 여럿이면 **순차** (변수부터
확정해야 다음 절이 그 이름을 본다 — 한 번에 시키면 없는 이름을 지어낸다).

| 카드 | 단계(탭 순서) | 전제 (`needs`) |
|---|---|---|
| 📊 상태창 한 벌 | status | 변수 2개 이상 |
| 🛒 상점 | actions | 숫자 변수 + 목록 변수 |
| 📜 퀘스트 보드 | vars → rules | 시간 체계 |
| 📈 레벨·성장 | vars → rules | — |
| 💕 호감도 인물 | vars → rules | — |
| 🌳 스킬트리 | vars → rules → party | — |
| ⚓ 편성표 | party | enum 또는 목록 변수 |
| 📅 달력·일정 | vars → rules → calendar | 시간 체계 |
| 📖 시나리오 | scenario | 변수 1개 이상 (해금 조건이 읽을 것) |

## AI 내보내기/가져오기 — `TAB_SLICES` ★

각 탭의 `tabAiTools(tabKey)`가 ① 직결 생성(입력칸 — 예시 문구는 `TAB_WANT_PH`, 버튼
`✨ {라벨} 만들어 달라기`) + ② 규격 내보내기/`📥 가져오기`를 붙인다.

| 슬라이스 키 | 라벨 | 갈아끼우는 키 | 특수 |
|---|---|---|---|
| `vars` | 변수 | `vars`, `derived` | |
| `commands` | 명령 | `vars` | `merge: 'cmd'` — **cmd 배정만 얹는다** (통째로 바꾸면 변수가 날아가므로) |
| `actions` | 액션 | `actions` | |
| `checks` | 판정 | `checks` | |

| `status` | 상태창 | `statusUI` | `sub: 'groups'`, `subOpt: ['layout']` — **구조 창구** (v0.62). customCSS·커스텀 템플릿·테마는 보존 — 꾸미기는 👁 결과 탭 몫 |

`setup.ai`(지침·가이드)·`meta`는 패치로도 못 다룬다 → **편집기 칸이 유일한 입력 경로.**

### 제작 도구 (v1.0 — 협업자 피드백 일괄)

- **[변수]**: 파생 카드에 "시작값 기준 계산: N" · 변수/파생 카드에 "N곳에서 참조 중" 펼치기
  (`varReferenceIndex` 역색인 — 파생/틱/이벤트/지시문/액션/판정/계약표/상태창/프리셋/패널들).
- **[규칙·이벤트]**: 랜덤 이벤트마다 시작 상태 실효 확률 (발동% × weight/Σ후보, 쿨다운 제외 근사).
- **[규칙·이벤트]·[액션]**: 🧪 1턴 시험 실행 — 실제 엔진 헤드리스 1턴, changeLog 출처별
  타임라인 + 통지 + 최종 diff. 시드 고정·다른 운 재굴림. 보조 AI 없는 시스템 축 전용.
- **[새 시작]**: 프리셋마다 [👁 미리보기] — 기본→적용값 diff + startAt + 그 상태의 상태창.
- **[달력]**: 시작 날짜 기준 실물 카드 미리보기 (기념일·일정·기한 점 + 사용자 CSS 격리 적용).
- **과거 상태창 (#1, 어댑터)**: 과거 마커를 out:N 스냅샷으로 렌더 (램 캐시 histStates —
  저장 가로채기 + 프리페치, 미스는 현재 폴백. 과거 렌더는 범례·하이라이트 없음).

### 가져오기 안전판 (통 교체 방어)

- **넣기 전에** `planTabImport`가 신원(id) 비교 — 사라지는 게 있으면
  `⚠ 적용하면 N개가 사라집니다` 정지 → `[그래도 적용]` / `[취소]`
- 요청서에 개수 체크섬(`tabItemCounts`) 동봉 — "고친 것만" 돌려주는 습성 방어
- `↩ {라벨} 가져오기 되돌리기` 1슬롯
- `vars` 가져오기 후 `breakageAfterVarImport` — 사라진 이름이 깨뜨린 탭을 검증기로 뽑아

## 상태창 꾸미기 — 두 창구 (같은 절을 나눠 쥔다)

- **구조 창구 (무엇을 보여줄까)** = 세부 편집기 [상태창] 탭의 status 슬라이스 (그룹·게이지·표시 조건)
- **꾸미기 창구 (어떻게 보일까)** = 👁 결과 탭 `디자인 생성` — 모드 스위치 2개:
  - `스킨만 · 색·글꼴·질감` → `buildCssSpecPrompt` → `customCSS`만 채움. 복사 버튼 `📋 CSS 규격 복사`
  - `배치까지 · 템플릿 전체` → `buildLayoutSpecPrompt` → 커스텀 템플릿 통째(`<style>`은 자동 분리).
    복사 버튼 `📋 배치 규격 복사`
- ☑ `획일적인 AI 디자인 줄이기` — Hallmark 보정 지침을 규격서에 더함
- `꾸미기 되돌리기` 1슬롯 — mode·template·customCSS 세 값을 함께 복원.
  배치 적용은 **원자적** — 적용 후 검증에서 새 오류(없는 자리표시자 등)면 통째로 되돌림
- 커스텀 템플릿 봇에서 스킨 모드를 고르면 "힘을 못 쓴다" 경고

### 스킨 규격서 클래스 (`CSS_SPEC_CLASSES`)

`.sim-status`(바깥 상자) · `.sim-status summary` · `.sim-group` · `.sim-group-label` · `.sim-row` ·
`.sim-label` · `.sim-value` · `.sim-bar` · `.sim-bar-fill`(너비 인라인 — 건드리지 말 것) ·
`.sim-badge` · `.sim-tags`/`.sim-tag` · `.sim-empty` · `.sim-actions` · `.sim-action-hint` ·
`.sim-action`(`.sim-armed`/`.sim-disabled`) · `.sim-action-glyph` · `.sim-action-state` ·
`.sim-log`/`.sim-log-item`
+ **시나리오 켜진 봇만**: `.sim-scn` / `.sim-scn-prog` (이야기 진행 칩 / (i/N막) 표시)

규격서에는 그 봇의 실제 상태창 HTML 뼈대가 동봉된다 (4KB 초과 시 잘림).

### 배치 규격서 계약 ({자리표시자}가 생명)

- `{변수id}` · `{파생id}` · 목록형은 `{id:tags}`로 칩 렌더
- **시나리오 켜진 봇만**: `{scenario}`(진행 칩) · `{scn_label}` · `{scn_turns}`
- **목록에 없는 자리표시자 = 설치 거부** (실패해도 안전)
- 라디오·체크박스 `id`/`name`에 `{uid}` 필수 (메시지마다 새로 그려져 엉킴 방지),
  숨김은 `display:none`으로 (absolute 0×0은 포커스 스크롤 사고)
- 자리표시자 수식 가능 (`{hp < 30 ? '위험' : '안정'}`), class 안에 넣으면 조건부 스타일
- `{{img::에셋이름}}` 두 겹 문법은 그대로 통과, `{{img::지역A_{region_a}}}` 조립 가능
- `position: fixed` 금지, `absolute`는 템플릿 안의 `relative` 컨테이너 내부만 (지도·핀 패턴 안내 포함)

### AI 왕복 패치 (core/patch.js)

통짜 재생성 없이 **바꿀 부분만** 패치 JSON으로 받는 경로. 1층 ✍ 창작의 내장 생성과
2층 붙여넣기가 **같은 계획·충돌·적용 UI를 공유**한다.

- 패치 형식: `{ patchVersion: 1, add, update, remove, randomEventsChance }` — 섹션 키는 평평
  (`vars`/`derived`/`checks`/`events`/`randomEvents`/`directives`/`actions`/`allow`)
- **add가 기존 id와 겹치면 정지** → 항목별 3지선다 (교체 / 새 id로 추가=패치 내 참조 일괄 개명 / 건너뛰기·기본)
- **같은 id를 remove+add에 같이 넣으면 거부** — 갈아엎기도 update(전문 다시 쓰기)로
- update는 항목 **통 교체** — 다이제스트에 이벤트·액션·판정·지시문·allow **전문**이 실려
  AI가 기존 본문을 보고 고쳐 쓴다. 변수는 계약표(요약)만. 시간 체계 켠 봇은 노출 이름 목록도 동봉
- remove는 diff에서 **기본 해제** (체크한 것만 삭제) · 적용은 원자적 (병합 후 `validateSchema` 실패 = 전무)
- **일괄 처리**: 충돌 3건부터 [전부 교체]/[전부 새 id]/[전부 건너뛰기] · 삭제 후보 3건부터 [전체 체크]/[전체 해제]
- 적용 전 백업 1슬롯 `↩ 되돌리기` · statusUI·onTurn·setup·meta·time은 패치 미지원 → 탭별 창구로
- 연속 패치 시 **적용 후 다시 내보내기** (옛 다이제스트 기준의 update는 낡음)

#### 변수 정리 마법사 (v0.45) ★
쓰이는 변수의 `✕`는 바로 안 지우고 **정리 계획**을 먼저 띄운다 (`planVarPurge`).
참조를 전 구간에서 걷어낸다 — 파생 **재귀 캐스케이드**, `updater.allow`, `setup.ai.vars`·`presets`,
`rules.onTurn`, `events`/`randomEvents`(**조건(when)이면 항목 통째, 효과면 그 한 줄만**), `choices`,
`directives`, `actions`, `checks`(굴림식이 무너지면 통째 + 그걸 가리키던 `check` 연결 해제),
`statusUI` 항목·빈 그룹·템플릿, `promptState`.

- 자리표시자: 산문(`promptState`·지시문 text)은 **값이 안 남는 줄째** 버리고,
  상태창 HTML은 **토큰만** 걷는다 (줄을 버리면 여는 태그만 남아 깨진다)
- 적용은 **원자적** — 정리 후 `validateSchema` 실패면 거부하고 이유 표시 · 되돌리기 1슬롯
- 아무 데도 안 쓰이면 계획 없이 그냥 지운다
- **이게 없으면 변수 삭제가 원천 불가능하다**: 참조가 `onTurn`·`promptState`·`setup`에도 있는데
  그 셋은 왕복 패치 미지원 영역이라, 패치로는 지울 수 없고 검증이 계속 거부한다 (실전 사고)

### 명령
- 안내: "변수에 이름을 붙이면 그 이름의 명령이 생긴다 — 안 붙이면 그 변수엔 명령이 없다"
- 붙일 변수 고르는 select는 **목록형을 맨 위로** 올린다
- h4 `유저가 이 목록을 보는 자리` — `{commands}`가 없으면 경고

### 상태창
- `상태창 제목` — **meta.name의 유일한 입력칸** (meta는 패치·탭별 내보내기 미지원 영역).
  상태창 머리글 + 메인 AI 상태 블록 제목 + 진단 리포트 제목. 비우면 "상태"
- `표시 방식` (자동 구성 / 커스텀 HTML 템플릿) · 테마 · ☑ `접을 수 있게`
- h4 `표시 그룹` · 그룹 행의 `다른 그룹에 합치기` 셀렉트 (그룹 2개 이상일 때)
- `⚡ 빠진 변수 자동 배치` — 미배치 변수·파생을 마지막 그룹에 일괄 추가 (min/max 있는 숫자는 게이지 자동)
- `⚡ 접두사로 그룹 묶어 배치` — `noz_aff`·`noz_mood`처럼 접두사를 공유하는 미배치 변수
  묶음이 2개 이상일 때. 묶음당 그룹 생성(제목은 라벨 공통 앞부분), 다인 봇 손조립 노가다 제거용
- 템플릿 모드: `[탭 뼈대 넣기]` `[접기/펼치기 뼈대]` `[버튼 팝업 뼈대]` — 그 봇의 그룹·변수로 채워 나옴.
  이미 내용이 있으면 **한 번 더 눌러야** 덮어씀
- h4 `조건부 템플릿 (한 봇에 여러 판이 있을 때)` — `[조건부 템플릿 추가]` · 표시 조건
- 🤖 **구조 창구** (status 슬라이스 — "무엇을 보여줄까") + h4 `디자인 레시피` · 커스텀 CSS 칸 ·
  미리보기. "어떻게 보일까"는 👁 결과 탭의 디자인 생성 몫

### 규칙·이벤트 (UI 순서 주의)
1. h4 `매 턴 자동 처리 (수입·소비 같은 정기 틱)`
2. h4 상태 지시문 — 조건을 만족하는 동안 매 턴 AI에게 전달  ← 이벤트보다 **위**
3. h4 조건 이벤트 — `조건` · ☑`1회만` · 효과 · `AI 통지`
4. h4 랜덤 이벤트 — `턴당 발동 확률 %` · `가중치` · `쿨다운` · `조건` · 효과 · `AI 통지`

효과 행은 `[변수 선택] = [식]`. **`+=`가 아니라 `=`** — `gold + 10`이라고 써야 한다.

갈림길: 이벤트 블록마다(조건·랜덤 공통) `[⌛ 갈림길로 만들기]` → 선택지 행(번호·이름·조건) +
효과 + `AI 전달문` + `[+ 선택지]` + 타임아웃 + `[갈림길 떼기]`. 별도 탭 아님 —
이벤트의 속성이라 rules 슬라이스에 자동 동승.

### 판정
- 판정마다: id·표시 이름 / `굴림식`(rand 허용 유일 자리) · `보정식` · `목표치` / 등급 목록
- 등급마다: `조건`(비우면 기본 등급) · 등급 이름 · 효과 · `연출 지시`
- `[+ 등급]` · `[🎲 액션 버튼 만들기]`(그 판정을 단 oneshot 액션 생성, 이미 있으면 `✓ 액션 버튼 있음`)
- `[판정 추가]`는 d20 4등급(대성공 roll==20 / 대실패 roll==1 / 성공 total>=vs / 실패) 뼈대로 시작

### 액션
필드: `영문id` · `버튼 이름` · 모드(`1회성`/`지속형`) · `쿨다운` · `사용 조건` · `판정`(셀렉트 —
켠 턴에 그 판정을 굴림. 판정이 없으면 "[판정] 탭에서 먼저 만들 것") · `AI 전달문` · 효과.
실행 버튼은 화면 우상단 — 누르면 무장(ON), 1회성은 자동 OFF, 지속형은 끌 때까지 매 턴 적용.

### 시간
- 꺼짐: 손 만든 날짜 변수(`LEGACY_TIME_RE`: day/clock_h/sim_* 등) 감지 안내 + `[🕐 시간 체계 켜기]`
- 켜짐: **시작 시점 미리보기** / `시작 시점` · `진행`(explicit/perTurn) · `달력`(gregorian/flat30) /
  날짜·시각 형식 / 요일·계절 / 노출 이름 체크박스(EXPOSABLE)
- h4 `진행 입구`: skip 변수 없으면 ⚠ + `[진행 입구 만들기]`(skip_day·skip_min + allow maxGain 7/720),
  있으면 ✓ + `[🌙 '하루를 마친다' 액션 추가]`
- h4 `옛 날짜 변수 정리`: `[🧹 정리 마법사로 한꺼번에 지우기]` — planVarPurge 재사용
- `[시간 체계 끄기]` — schema.time만 지운다. 세이브의 time_epoch는 남아 다시 켜면 이어진다

### AI 설정 (탭별 내보내기 없음)
상태 요약(`{변수id}` 자리표시자) + `[⚡ 변수로 자동 생성]` / 이벤트 통지 · 메인 AI 지침 /
보조 AI에게 보낼 최근 대화(1/3/5턴) / 다음 행동 제안(`suggest`) /
h4 `보조 AI가 조정할 수 있는 변수와 한도` — `증가 한도`·`감소 한도`(또는 `최대 글자`) +
☑`등장할 때만`(mentions) + `액션 잠금` / `[⚡ 빠진 변수 모두 추가]` / 보조 AI 추가 지시

### 🔬 진단 (1층 내부 탭)
`턴 수` · `시드 수` · `[진단 실행]` · `직전 진단과 비교`(턴/시드 같을 때) ·
액션별 기여도 · 프리셋별 실제 난이도

**수정 요청은 패치 경로가 기본이다.**
- 내장 생성 가능하면 `[패치 만들기 · N건]` — 부분 패치를 만들어 창작 탭의 계획 확인으로
- 외부 AI용 `수정 패치 규격서 복사 · N건` — 받은 패치는 JSON 관리자의 `[패치 검사]`로
- `탭 전체 재작성`(접기)의 탭별 전체 요청서는 **전면 재작성용** — "빠진 항목은 삭제될 수 있다" 경고
- `진단 내용 복사` — 기록·공유용 산문
- 🔵(low)는 어느 경로로도 안 보낸다. 요청문에 "진단은 보조 AI를 안 돌린 결과라
  **AI가 바꾸는 변수는 '안 움직임'으로 잘못 나온다**"를 명시한다

잡아 주는 것: 영영 안 뜨는 이벤트 · 아무도 안 바꾸는 변수 · 한 번도 못 누르는 액션 ·
눌렀을 때 오히려 손해인 버튼 · 이름과 어긋난 난이도 순서.

**시뮬은 보조 AI를 안 돌린다** — 그 사각지대에 걸리는 것들은 결함이 아니라 🔵로 분류돼
수정 요청에서 빠진다. 지적문에서 이 태그를 보면 **고치지 말 것**:

| 태그 | 뜻 |
|---|---|
| `AI 담당 문턱` | 문턱에 걸린 값을 보조 AI가 그 방향으로 민다 — 시뮬에선 시작값 근처에 머문다. **문턱을 내리면 실제 플레이에서 폭주한다.** 방향(`maxGain: 0`)·범위(선언 상한)·사거리(`maxDelta × 턴`)를 봐서 진짜 도달 불가와 구분한다 |
| `설정 의존` (🔵) | 조건의 bool/enum을 프리셋·액션·보조 AI가 세운다 — 다른 판에서는 뜬다 |
| `연쇄` | 안 뜬 이벤트**만이** 세우는 값에 막혔다 — 원인은 그 이벤트 하나다 (래치 짝의 회복 쪽·경보 플래그) |
| `안전장치` | `notify` 없는 값 되돌리기 규칙 — 안 뜨는 게 성공이다 |
| `후반부 이벤트`·`후반부 액션` | 판을 두 배로 늘리면 실제로 뜬다 — 턴 수를 올려 보라는 안내 |
| `측정 불가` | 보조 AI·최초설정·프리셋만 정하거나 효과 안에서만 쓰이는 값 (`pay_tmp`류) |

## 편집기 주의

- 라이브 검증 리포트(json·deep 층 하단)·패치 적용 보고의 **경고는 4건부터 `<details>`로 접힌다**
  (`sce-fold`). 오류는 항상 펼침. 배경: 맨션봇 실전에서 mentions 겹침 경고 147줄이 오류를 가림
- `rerender()`가 DOM을 새로 만든다 → 확인용 임시 상태(두 번 누르기 등)는 **탭 함수 바깥**에 둘 것
- 전역 편집기가 캐릭터 전환 후에도 이전 내용을 유지해 **다른 봇 스키마를 덮어쓴 사고**가 있었다.
  v0.11에서 캐릭터 귀속 추적 + 설치/제거 전 자동 백업(`sim:schema-backup:<chaId>:<ts>`, 5개)을 넣었다
