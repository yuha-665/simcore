# 설계 — 봇 제작 대화 (설정집 → 로어북·캐릭터 시트)

> 2026-10-10, 유저 제안. **v1.16.0 1단계(쓰기 없음) 구현, v1.17.0 2차(📁 폴더·🪪 시트 형식·📥 원문 적재, §4b).** 2·3단계는 §5.
> 제안 원문: "지금은 봇 제작 보조 유틸리티 도구인데 아예 봇 제작에 쓸 수 없냐고 하는 사람들이 있더라. 로어북을 작성하고
> 캐릭터 시트 만들고 하면 일일이 손작업해야 하고, 제작 위치가 사실 리수 봇 컨텍스트에서 OOC로 주고받고 하는 식으로밖에
> 힘들긴 한데. AI 채팅 기능이 내장한 김에 완전히 독립된 탭으로 AI 채팅 창 크게 만들고, AI가 요청받으면 설정집 정리해서
> 로어북이랑 캐릭터 시트 만들어 주게. 사용자가 해당 봇 수정을 심코어가 해도 된다고 허가하는 체크를 만들어서, 그러면 그 봇의
> 로어북·정규식·트리거를 수정할 수 있게."
> 유저 결정: 제안한 3단계 순서대로 — "좋은 제안이야 그렇게 하도록할까".

## 1. 왜 되나 — 부품이 거의 다 있다

| 부품 | 어디 | 상태 |
|---|---|---|
| 쓰기 경로 | 번들 적용(`applyBundleToChar` → `setCharacter`) — 로어북 전체·정규식, 적용 전 백업 3개, [교체 되돌리기], 되읽기 레이스 방어 | ✅ (2단계가 재사용) |
| 읽기 경로 | `getBotContextForEditor` — 설명·로어북 20KB 상한 | ✅ |
| LLM 호출 | `callGenLLM`(보조·센티널·직접 지정), 모델 선택 행 | ✅ |
| 대화 UI | 💬 어시스턴트(말풍선·이력 예산·말풍선 지우기·토큰 미터) | ✅ (구조 복제) |
| 캐릭터별 로컬 저장 | pluginStorage `sim:ui:editor:<chaId>`·`sim:worklog:<chaId>` | ✅ (`sim:bible:<chaId>` 추가) |

새로 만드는 것: **큰 탭**, **설정집 객체와 출력 계약**, **컴파일(로어북·시트)**, 2단계부터 **항목 단위 적용·diff·허가**.

## 2. 핵심 결정 — 설정집은 중간 작업본이다

대화 이력에 설정을 누적하면 몇 턴 안에 컨텍스트가 터진다. 스키마 작업본과 같은 구조로 간다:
**설정집(bible) = 구조화된 객체**, 매 턴 다이제스트로 시스템 프롬프트에 싣고, AI는 **패치**(id로 덮어쓰기)만 보낸다.
로어북·캐릭터 시트는 설정집을 **컴파일**한 결과다. 대화는 💬과 같이 편집기를 닫으면 사라지고, 설정집만 캐릭터별로 남는다.

```json
{ "v": 1, "title": "…", "premise": "한 줄 전제",
  "folders": [ { "id": "기초-설정집", "name": "기초 설정집", "key": "\uf000folder:<uuid> (리수에 이미 있는 폴더일 때만)" } ],
  "sections": [ { "id": "arin", "kind": "character", "name": "아린", "keys": ["아린", "감시탑"], "always": false, "folder": "기초-설정집", "body": "…" } ],
  "sheet": { "name": "", "desc": "설명란 글", "first": "첫 메시지" },
  "sim": [ { "what": "아린 호감도", "how": "변수", "why": "플레이가 바꾼다" } ],
  "source": "사용자가 붙여 넣은 캐릭 설정집 원문 (v1.17.0)", "sourceOn": true }
```

| 필드 | 뜻 |
|---|---|
| `sections[].kind` | world · character · place · faction · rule · term · plot · style · other — 기계는 하나, 종류는 카드 묶음·어법만 |
| `sections[].keys` / `always` | 리수 로어북 `key` / `alwaysActive`로 그대로 컴파일 |
| `folders[]` / `sections[].folder` | **로어북 폴더**(v1.17.0) — 리수 폴더 = `mode:'folder'` 항목(key 머리 `\uf000folder:`) + 자식의 `folder`(=그 key). key 있는 폴더 = 리수에 이미 있는 것(그 안으로), 없으면 내보낼 때 새 폴더 |
| `source` / `sourceOn` | 📥 캐릭 설정집 **원문 적재**(v1.17.0) — 사용자가 붙여 넣는 재료. AI 수정안으로는 못 바꾼다. 시트 형식(OOC 명령어)은 설정집이 아니라 기기 공통 prefs |
| `sheet` | 캐릭터 설명란(desc)·첫 메시지(first) 초안 — 리수 설명 필드에 손으로 붙인다(1단계) |
| `sim` | **심코어로 갈 것** — 로어북이 아니라 변수·이벤트·액션·판정·비밀·무대 뒤·시나리오·갈림길. [💬 어시스턴트에게 보내기]로 요청문이 된다 |

수정안 = `{ "bible": { title?, premise?, folders?(id 덮어쓰기, key 불가), sections?(id 덮어쓰기 · folder는 있는 폴더 id만), remove?, sheet?(칸만), sim?(통째 교체) } }`.
모르는 키·없는 kind·없는 remove id는 거부(스키마 패치와 같은 규율 — 검증이 잡는 건 규약에도 같은 말로).
거부되면 설정집은 안 변하고 오류를 첨부해 한 번 더 받는다(💬과 같은 2회 규율).

## 3. 차별점 — 심코어식 분담

OOC로 짜는 것과 이 도구의 차이는 **규약**에 있다 (memory simcore-bot-design의 규칙을 프롬프트에 실었다):
- 로어북 = 안 변하는 것(설정·이유·어휘). 플레이가 바꾸는 것(호감·소지금·상태·진행)은 `sim`으로 — "At the start…"·"현재…"가 본문에 들어가면 변수 자리.
- 밝혀지기 전엔 모델이 몰라야 하는 것은 로어북에 적으면 샌다 → `sim` how="비밀", 본문엔 "숨기는 사람"의 행동만.
- 항목 하나 = 주제 하나, keys는 장면에 실제로 등장할 말 2~6개, always는 늘 필요한 것에만(토큰).
- 모르면 지어내지 말고 묻되 한 턴에 셋 이내.

## 4. 1단계 (v1.16.0) — 쓰기 없음

- **사이드바 작업도구에 `봇 제작` 항목** (`data-floor="bible"`, `--sc-nav-bible`). 편집기 `floorView === 'bible'` → `bibleFloor()`.
  스택형 폴백(플레이그라운드)은 접기 하나 더.
- **화면** = 왼쪽 설정집(종류별 카드 — 이름·낱말·상시·본문 손편집 가능, 카드마다 📋·✕) + 오른쪽 대화(모델 선택·캐릭터 정보 동봉·토큰 미터·말풍선·입력).
  좁은 화면은 위아래로.
- **내보내기**: `[📋 로어북 JSON 복사]`·`[⬇ lorebook.json 내려받기]`(리수 로어북 [가져오기] 형식 `{ type:'risu', ver:1, data }`) · `[📋 캐릭터 시트 복사]` · 카드별 📋.
  `[💬 심코어로 보내기]` — `sim` 목록을 요청문으로 만들어 💬 대화 입력칸에 넣고 그 탭으로 이동.
- **되돌리기**: 수정안 적용 전 설정집을 10단계까지 쌓아 `[↩ 되돌리기]`. 수정안은 **자동 적용** — 우리 작업본일 뿐 캐릭터엔 아무것도 안 쓰므로 계획 상자 없이 바로 넣고, 되돌리기로 받친다.
- **저장**: 설정집은 `ai.loadBible/saveBible` → pluginStorage `sim:bible:<chaId>`(기기 로컬, 카드·번들에 안 실림). 대화는 안 남긴다.
- **프롬프트** = 📌 작업 지침(meta.notes) + 봇 제작 규약(`bibleRules`) + 설정집 다이제스트(24KB 상한) + 현재 캐릭터(설명·로어북 20KB, 끌 수 있음) + 작업본 변수 요약(있을 때 — 이미 시스템이 쥔 값을 알고 분담하게).
- 호출은 `ai.generate`(callGenLLM) — **자기 정산 함정**(design-내장-AI-생성 §함정 1)은 재사용으로 자동 회피.

## 4b. v1.17.0 — 📁 로어북 폴더 · 🪪 시트 형식 · 📥 원문 적재

유저 제안(v1.16.3 실기 "흠 잘 불러오네" 뒤): "캐릭터 시트 — 원하는 시트 OOC 명령어를 붙여 넣는 곳을 만들고 그 아래 캐릭 설정집 적재를 만들고.
로어북이 그룹 기능도 지원하니 어떤 그룹을 만들지, 어떤 그룹에 로어북을 생성할지 정할 수 있으면 봇 제작이 더 수월할 것".

- **📁 폴더** — 설정집 머리 아래 폴더 칸: 칩(이름·항목 수·"리수에 있음"·✕), 새 폴더 만들기, "리수에 있는 폴더" [+ 이름](캐릭터 정보 `folders`에서 — key가
  붙는다). 카드마다 폴더 고르기(폴더가 있을 때만), 폴더가 있으면 카드 묶음이 종류별 → 폴더별. 규약: 폴더가 있으면 새 항목은 알맞은 폴더에, 맞는 폴더가
  없으면 `folders`에 제안, 없는 폴더 id는 거부, 폴더가 없으면 억지로 안 만든다. key는 AI가 못 정한다.
- **컴파일** — 쓰이는 폴더만: key 없는 폴더는 `mode:'folder'` 항목(새 uuid, 내보낼 때마다 새 것), key 있는 폴더는 항목 없이 자식 `folder`에 그 key.
  순서 = 폴더 → 자식 → 다음 폴더 → 폴더 없는 항목. 📚 보낼 것 고르기 목록엔 "폴더 › 이름".
- **🪪 시트 형식(OOC 명령어)** — 🪪 캐릭터 시트 접기 맨 위 textarea. **기기 공통**(`ai.loadBiblePrefs/saveBiblePrefs` → pluginStorage `sim:bible:prefs`) —
  유저의 취향이지 봇의 설정이 아니라서. 프롬프트에 `## 캐릭터 시트 형식` 블록, 규약에 "desc는 그 형식의 항목·순서·어조를 그대로".
- **📥 캐릭 설정집 적재** — 그 아래 textarea(봇별 `bible.source`), 동봉 체크(`sourceOn`) + KB, 48KB(`SOURCE_CAP`) 위는 앞부분만 + ⚠. 프롬프트에 `## 적재한 원문`
  블록("정리의 재료 — 설정집에 없는 것을 항목으로, 시트에도 참고, 겹치면 설정집 기준"). [🪪 시트 써 달라기] = 요청문을 대화 입력칸에.
- 전부 `bibleUserBlocks(bible, sheetFormat)`가 만든다 — 설정집 다이제스트 뒤. 여전히 캐릭터엔 아무것도 안 쓴다.

## 5. 2·3단계 (미구현 — 순서는 유저 결정)

- **2단계 — 로어북 항목 단위 적용.** 허가 체크 "심코어가 이 봇의 로어북을 고쳐도 됨" = pluginStorage(캐릭터 id 키, 카드에 안 실림) + 세션마다 재확인.
  적용은 **diff 카드(추가·교체·삭제) → [적용]**, 제목(`comment`)이 같은 항목만 교체하고 나머지는 보존(정규식 사고의 원칙: 덮지 말고 덧붙인다).
  적용 직전 `getCharacter` 재읽기 → 그새 바뀌었으면 보류(v1.14.10 규약), 적용 전 백업(번들 백업 링 재사용)·되돌리기. `⚙simcore` 항목은 절대 안 건드린다.
- **3단계 — 설명·첫 메시지·정규식.** 설명 통째 교체는 CBS `{{…}}` 보존 검사(v0.76 사고). 정규식은 `regexAdd` 방식(같은 comment만 교체 + 덧붙임).
  리수의 `lowLevelAccess`는 루아 브리지용 플래그 — 우리 허가와 섞지 않는다.

## 6. 함정 (설계 제약)

1. **setCharacter는 현재 선택 슬롯에 통째 덮어쓴다** — 2단계에서 묵은 객체로 부르면 다른 봇이 날아간다. 번들 경로의 현재 캐릭터 확인·되읽기 방어를 그대로.
2. **토큰** — 설정집이 커지면 다이제스트 상한에서 본문이 생략된다(머리줄은 전부). 상한을 넘으면 UI가 알리고, 항목을 지우거나 합치라고 안내.
3. **보조 모델 품질** — 💬과 같은 경고("메인급 권장").
4. **리수 1.8.1의 로어북 가져오기 형식** — 모듈 메뉴·캐릭터 로어북 둘 다 `{ type:'risu', ver:1, data:[loreBook] }`(또는 CCv3 `entries`). 항목 필드 = key·comment·content·mode('normal')·insertorder(100)·alwaysActive·secondkey·selective.
5. **폴더 key는 그 캐릭터 안에서만 뜻이 있다** (v1.17.0) — "리수에 있는 폴더"로 보낸 항목을 다른 캐릭터·전역·모듈 로어북으로 가져오면 `folder`가 가리키는 폴더가 없다.
   리수의 정렬은 폴더를 못 찾은 항목을 최상위에 그대로 두지만(드래그 정렬 코드 확인) 표시가 어긋날 수 있다 — 안내문에 "같은 캐릭터로 가져올 때"를 박아 둔다.
   새 폴더 key는 내보낼 때마다 새 uuid라 같은 JSON을 두 번 가져오면 폴더도 둘(가져오기가 덧붙임).

- `core/bible.js` 순수 함수(정규화·패치 적용·다이제스트·규약·컴파일·응답 가르기) + run-tests + 테스트/test-bible.js.
- 편집기 `bibleFloor` + 어댑터 사이드바·저장 통로 + 스택형 폴백.
- 스킬 문서(editor.md 사이드바 표·새 층 절, risu-facts 로어북 형식) + 이 문서.
