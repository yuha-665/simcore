0. AI한테 주사위를 맡기면 안 되는 이유


TRPG풍 봇 만들어본 사람은 다 겪어봤을 거임. 프롬프트에 "d20을 굴려서 판정해라"라고 적으면 AI가 굴리는 척하면서 결과를 지가 정함.


성공이 어울리는 장면이면 성공이 나옴. 긴장감 있어야 할 것 같으면 실패가 나옴. 그건 주사위가 아니라 연출임.


그리고 진짜로 랜덤하게 굴렸다 쳐도, 리롤하면 결과가 바뀜. 대실패 떴을 때 리롤 한 번이면 세탁 끝. 긴장이고 뭐고 없는 거임.


그래서 v0.40부터 주사위를 시스템이 굴림. AI는 결과를 통보받고 서사만 씀.


결과를 AI가 못 뒤집음  — 판정 결과는 변수가 아니라 시스템 기록이라 보조 AI한테 열어줄 방법 자체가 없음

리롤해도 같은 눈  — 같은 턴을 다시 굴리면 같은 결과가 나옴. 세탁 불가

능력치 연동  — 보정식이 변수를 그대로 읽어서, 근력이 오르면 판정도 같이 강해짐



1. 어떻게 생겼나 먼저 보기


TRPG 템플릿이나 대장간 템플릿으로 새 봇 만들면 바로 볼 수 있음. TRPG에서 ⚔ 공격 버튼 켜고 아무 말이나 보내면:


[판정] 공격 판정: 14 + 2 = 16 vs 13 → 성공


이 줄이 같은 턴 서사에 실려 감. AI는 이 결과를 받아서 명중 장면을 씀. 굴린 눈(14) + 근력 보정(+2) = 합계(16)가 목표치(13)를 넘어서 성공 — 계산이 다 보임.


[스샷: 판정 결과가 반영된 서사 + 상태창 변화 로그의 🎲 줄]


상태창 변화 로그에도 🎲 줄로 남고, 눈이 20이면 대성공(피해 주사위 2배 + "압도적인 일격으로 그려라" 연출 지시), 1이면 대실패(반격까지 맞음)임.



2. 판정 탭 뜯어보기


봇 편집 > 판정 탭으로 들어가면 됨.


[스샷: 판정 탭 전체]


대장간 템플릿에 들어있는 실제 판정임.


id  ck_forge  /  표시 이름  단조 판정

굴림식  stoked ? max(rand(1, 20), rand(1, 20)) : rand(1, 20)

보정식  skill_mod

목표치  dc


칸 세 개가 전부임.


- 굴림식  주사위 자체. rand()는 여기서만 쓸 수 있음. 위 예시는 "화로를 달궈놨으면(stoked) 두 번 굴려 좋은 눈" — 이점 굴림임
- 보정식  능력치 보너스. 변수·파생을 읽음. 비우면 0
- 목표치  넘어야 하는 값. 숫자(13)도 되고 변수(dc)도 됨. 비우면 목표치 없는 판정


그 아래가 등급임. 위에서부터 조건이 처음 맞는 등급 하나가 걸림.


대성공  roll == 20  →  평판 +3, 공임 두둑  /  연출 지시 "걸작의 탄생을 극적으로 그려라"

대실패  roll == 1  →  무쇠 하나 더 날림, 평판 -1

성공  total >= vs  →  공임 + 평판 +1

실패  (조건 없음 — 나머지 전부)


등급의 조건이랑 효과에서는 roll(굴린 눈) / mod(보정) / total(합계) / vs(목표치)를 그냥 변수처럼 쓸 수 있음. 그래서 "성공하면 공임 = 30 + total×2" 같은 것도 됨 — 얼마나 잘 굴렸는지가 값이 되는 거임.


연출 지시는 그 등급일 때만 AI한테 덧붙는 문장임. 3탄의 AI 통지랑 같은 결인데 등급별로 다르게 나가는 것.


⚠ 맨 마지막 등급엔 조건을 달지 마셈


등급은 첫 매치라서, 전부 조건이 달려 있는데 아무것도 안 맞으면 등급 없는 판정이 됨. 마지막은 조건 비운 "실패"로 두는 게 정석임. [판정 추가] 누르면 나오는 뼈대가 이미 그렇게 돼 있음 — 뼈대 순서 안 건드리는 게 젤 편함.



3. 실행 통로는 세 개


① 액션 버튼 — 제일 기본. 판정 블록 아래 [🎲 액션 버튼 만들기] 누르면 실행 버튼이 자동으로 생김. 4탄에서 배운 그 액션임 — 버튼 켜고 전송하면 같은 턴에 굴러서 서사에 반영됨.


[스샷: 판정 블록 아래 🎲 액션 버튼 만들기]


② 기존 액션에 달기 — 액션 탭의 판정 칸에서 고르면 됨. TRPG의 ⚔ 공격이 이 방식임: 공격 액션이 기력을 깎으면서 공격 판정을 굴림.


③ 이벤트에 달기 — 이벤트에도 판정 칸이 있음. 이벤트가 터질 때 굴러서 [판정] 줄이 다음 전송에 통지로 합류함. TRPG 템플릿이 이걸로 재밌는 걸 함: 보조 AI가 "여긴 판정이 필요한 상황"이라고 깃발을 켜면 → 이벤트가 반응해서 시스템이 대신 굴려 줌. 유저가 버튼을 깜빡해도 판정이 빠지지 않는 배선임.



4. 이점(어드밴티지) 패턴


"다음 판정 한 번을 유리하게" 같은 소모성 버프는 이렇게 만듦. TRPG·대장간 둘 다 이 구조임.


1) 참/거짓 변수를 하나 둠  (TRPG는 adv, 대장간은 stoked)

2) 굴림식이 그걸 읽음  —  adv ? max(rand(1,20), rand(1,20)) : rand(1,20)

3) 끄는 건 액션의 효과에 둠  —  adv = 0


"굴리기 전에 꺼지면 이점이 날아가는 거 아님?" 싶을 텐데 순서가 정해져 있음: 굴림 → 등급 효과 → 액션 자체 효과. 굴림식이 이점을 먼저 읽고 나서 꺼지니까 안전함. 끄는 걸 등급 효과에 넣으면 실패 등급에서만 꺼지는 식으로 구멍 나니까 액션 효과에 두는 게 정석임.



5. 이것도 AI한테 시키면 됨


다른 탭들이랑 똑같음. 판정 탭 맨 위에 규격 내보내기가 있음.


이 봇에 어울리는 판정 2~3개 만들어줘. 능력치 보정이랑 등급별 효과·연출 지시까지 채워주고, 실행할 액션 버튼도 같이
