# 설계 초안 — 판정(완벽 주사위) · 선택지

> 2026-07-28, 회사 노트북 세션에서 정리한 **미구현 설계 초안.**
> 구현은 core/* 이관 후 소스에서. 수치·이름 전부 바꿔도 됨 — 제약 조건 절만은 지킬 것.

동기: 시뮬을 게임처럼 만드는 두 축이 비어 있다. 주사위 = **불확실성**, 선택지 = **선택권**.
trpg 템플릿은 판정을 변수 5개(roll/total/grade/adv/roll_pending) + 규칙 + 액션으로 손조립하고
있다 — 그 패턴을 일급 개념으로 승격하는 것이 이 문서다.

---

## 1. checks — 판정 프리미티브 ("완벽 주사위")

핵심 약속: **굴림은 엔진이 하고, AI는 결과를 받아 서사만 쓴다.**
schema.md의 기존 원칙("주사위·판정값은 allow에서 뺀다")의 기능화다.

### 스키마 초안

```js
checks: [{
  id: 'attack',
  label: '공격 판정',
  roll: 'rand(1,20)',            // 굴림식. rand 허용 (rules.expr과 같은 컨텍스트)
  mod: 'floor(str/2) + weapon',  // 보정식. rand 불가
  vs: 12,                        // 고정 DC 또는 식 ('10 + danger')
  grades: [                      // 위에서부터 첫 매치. total = roll + mod
    { when: 'roll == 20', label: '대성공', effects: [...] },
    { when: 'total >= vs', label: '성공',   effects: [...] },
    { when: 'roll == 1',  label: '대실패', effects: [...] },
    { when: 'true',       label: '실패',   effects: [...] },
  ],
}]
```

### 흐름

1. 유저가 판정을 요청 (액션 버튼 또는 `cmd` — 기존 두 통로 그대로 재사용, 새 입력 통로 없음)
2. 무장(armed) → 다음 sendPhase에서 엔진이 굴림 (기존 액션과 같은 타이밍 모델)
3. seededRng(chatId, msgIndex)로 굴린다 — **리롤해도 같은 굴림.** 리롤로 주사위를 다시 굴리는
   순간 "완벽"이 깨진다. 이게 이 기능의 존재 이유이므로 unstable 옵션을 주지 말 것
4. 프롬프트 주입: `[판정] 공격: 14 + 3 = 17 vs 12 → 성공` — AI가 모르는 것(결과)만 말한다.
   어떻게 서술할지는 안 시킨다
5. 상태창 changeLog에 같은 줄 표기. `{lastcheck}` 자리표시자 검토

### 제약 (어기면 기존 사고 재발)

- 판정 결과 변수는 **updater allow에 못 넣게 검증에서 막는다** (경고 아니라 오류로)
- 편집기 **판정 탭 신설 필수** — 엔진에만 넣으면 v0.35 cmd·v0.37 mentions 3호 사고
- grades의 `when`은 `roll`/`total`/`vs`를 임시 식별자로 연다 — checkExpr에 컨텍스트 추가 필요
- trpg 템플릿을 checks로 재작성해서 회귀 확인 (기존 손조립과 같은 분포가 나와야 함)

## 2. choices — 선택지

actions와 결이 다르다: actions = 상시 동사, choices = **이 순간의 갈림길.**
이벤트가 터지면서 2~4개 선택지를 내밀고, 고를 때까지 기다린다.

### 스키마 초안

```js
rules.events[]: {
  id: 'bandit_raid',
  when: '...',
  notify: '산적이 마을 어귀에 나타났다.',
  choices: [                     // 있으면 이 이벤트는 pending 상태로 들어간다
    { label: '토벌대를 보낸다', effects: [...], inject: '토벌을 선택했다' },
    { label: '금화로 무마한다', when: 'gold >= 100', effects: [...], inject: '...' },
    { label: '외면한다', effects: [...], inject: '...' },
  ],
  timeout: 3,                    // 선택 없이 N턴 지나면 마지막 항목 자동 (기한 개념은 v0.34 참조)
}
```

### 입력 통로 — 채팅 명령만

- `/선택 2` 또는 `/선택 금화` (번호·앞머리 매칭 — v0.35.1의 완전일치→앞머리→부분일치 규칙 재사용)
- 상태창 안 버튼은 **불가** (리수가 클릭 target을 자름, v0.11 확정 — risu-facts.md)
- 상태창에는 번호 붙은 목록만 그린다. `when` 거짓인 항목은 잠김(🔒) 표시하되 번호는 유지
  (번호가 밀리면 이전 메시지의 상태창과 어긋난다 — 상태창은 메시지마다 그려짐)

### pending 동안의 규칙 (설계 포인트)

- **보조모델 갱신을 멈추지 않는다.** 멈추면 선택과 무관한 값(호감도 등)까지 얼어붙는다.
  대신 pending인 이벤트의 effects가 만질 변수만 이번 턴 allow에서 뺀다 — 서사가 결과를
  앞질러 굳히는 것만 막으면 된다
- 프롬프트에는 "선택지가 제시되어 있고 아직 고르지 않았다"만 주입. **선택을 대신 하거나
  재촉하는 서술을 시키지 말 것** (지시문은 AI가 모르는 것만)
- pending 중 같은 이벤트 재발동 금지, 다른 이벤트는 정상 (스택 없음 — 동시 pending 1개 상한이
  단순하고, 둘 이상 필요한 스키마는 아직 없다)

### 제약

- 편집기: 이벤트 탭에 choices 편집 붙이기 (별도 탭 아님 — 이벤트의 속성이므로 merge 방식은
  v0.36 cmd 슬라이스 참조)
- `/선택`이라는 cmd 이름을 변수가 쓰면 검증 경고 (commands 자리표시자 충돌과 같은 부류)
- 진단(diagnose)에 choices 관련 체크를 넣는다면 **템플릿 전체 오탐 0 확인 후** (v0.28·v0.30·v0.38.2)

## 구현 순서 제안

1. checks — 독립적이고 trpg 템플릿이라는 실측 대상이 이미 있다
2. choices — 명령 파이프라인·이벤트·상태창 세 곳을 건드려서 더 크다
3. 각각 편집기 칸 + 템플릿 반영(trpg 재작성 / daily에 choices 예시 하나) + 테스트까지가 완료 정의
