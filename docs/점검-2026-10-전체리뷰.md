# 전체 점검 2026-10 — 플러그인 체급이 커진 뒤 첫 리뷰

**왜 지금인가.** 커뮤니티 제보 하나(text `maxLength`를 어시스턴트가 모른다, v1.14.2~3)를 파다 보니 같은 부류의 구멍이
열몇 개 더 나왔다(v1.14.4 — 섹션별 아는 키 표). "한 군데가 아니다"가 확인된 셈이라, 영역마다 같은 눈으로 한 번씩
훑는다. 코어 23모듈 + 어댑터 + 편집기 = 41.8K줄, 실측 테스트 110파일.

**유저 결정(2026-10-09):** "이참에 다른 영역들도 문제가 없는지 순서대로 점검하는 게 좋겠네. 플러그인 체급이 커지면서
한번쯤 리뷰해볼 시간이 필요하긴 했어."

## 방법

- **층 사이 계약 대조**가 핵심이다. 이 플러그인의 버그는 대개 "한 층이 아는 것을 다른 층이 모른다"에서 난다 —
  프롬프트 ↔ 파서 ↔ 적용 ↔ 검증기 ↔ 편집기 ↔ 문서. 한 층 안의 로직보다 층 경계를 먼저 본다.
- **기계 감사 먼저, 손 리뷰는 그 다음.** 키 이름 감사처럼 스크립트로 전수 대조할 수 있는 건 스크립트로(스크래치패드
  `audit_*.js`, 결과만 여기 적는다). 사람 눈이 필요한 건 영역별 읽기 감사(읽기 전용 에이전트 → 보고 → **직접 코드로
  재확인한 것만** 고친다. 에이전트 보고는 후보일 뿐이다).
- **고치면 같은 판에**: 검증기 경고 + 요청서 문구 + 편집기 칸 + 테스트 + 문서 한 줄. 한 층만 고치면 다음 제보가 또 온다.
- 한 영역 = 한 커밋(또는 몇 개). 판본은 1.14.x 패치 번호로 올린다. 영역 끝마다 전체 스위프(110파일) 통과 확인.

## 기계 감사 결과 (스크립트, 2026-10-09)

- **키 이름 전수 대조** (`audit_keys.js`): 스키마 25종 사용 키 ↔ 대화·요청서·탭 프롬프트. 대화·요청서에 이름 없는 키
  열몇 개 → v1.14.4 필드 사전으로 해소. 코드가 읽는데 어떤 스키마에도 없는 키는 `maxLen` 식구(v1.14.3)뿐.
- **밖에서 안 쓰는 export** (`unused_exports.js`): 대부분 테스트용·대칭용이라 해롭지 않음. 정리 후보만 적어 둔다 —
  engine `dayCloseAction`(어디서도 안 씀), choice `liveRaw`·`liveConfigs`·`askedConfig`·`liveOpen`·`liveChance`, shop
  `initShop`·`ensureShop`·`mergeIntoList`·`clampPrice`·`exchangePair`, time `normPins`·`seasonIndex`·`normStartRandom`.
  **죽은 코드인지 내부에서 쓰는지 각각 확인한 뒤**에만 지운다(11번 영역에서).
- **모듈 ↔ 전용 테스트**: 110파일이 번들을 통째로 평가하므로 require 기준 집계는 과소. 전용 테스트가 1개뿐인 모듈은
  11번 영역에서 계약 대조형으로 보강.
