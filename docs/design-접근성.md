# 최우선 과제 — 접근성 (이층 구조)

> 2026-07-30 확정. **기능 개발보다 앞선다.** 신규 기능 개발 속도를 늦추고 여기에 붙인다.
> 결론이 하루 안에 세 번 진화했다: 입구 통합 → 내장 AI 생성 → **이층 구조**.
> 최종형: 위층 = AI 딸깍(내장 생성), 아래층 = 기존 탭(디테일 작업용, 정리만).
> 결정 근거(유저): "나도 어제 직접 해보니 상당히 어렵다고 느껴져서 하는 내내 클코한테
> 물어봐야 할 수준이었으니 다른 사람들은 더 심할 듯", "기능도 너무 많고 자유도마저 너무 높아서
> 사실상 코딩하는 느낌", "AI 규격 내보내기가 있어도 어디가 뭘 해주는 건지 헷갈릴 것 같아 —
> 실제로 나도 그랬고".

## 진단

**만든 사람이 자기 도구를 쓰면서 AI 보조가 필요했다.** 도구의 멘탈 모델이 소스 전체를 들고 있는
사람에게만 접근 가능하다는 뜻이다. 이게 이 문서가 존재하는 이유다.

### 근본 원인 — 스키마 구조를 화면에 그대로 펼쳤다

탭 10개(변수·명령·상태창·규칙·액션·판정·새 시작·AI 설정·진단·JSON)가 곧 스키마 섹션이다.
**만든 사람의 구조이고, 쓰는 사람의 목적 구조가 아니다.**

→ 가이드를 9탄까지 써도 어려운 이유가 이것이다. **미로 지도를 정밀하게 그려도 미로는 미로다.**
문서를 더 쓰는 것으로는 안 풀리고, 정보 구조를 고쳐야 풀린다.

### 측정된 증상 — AI 입구 13개

같은 행위(AI에게 맡기기)의 입구가 8개 탭에 흩어져 있고, 부르는 동사가 넷이다.

| 위치 | 입구 |
|---|---|
| 탭별 AI 도구 (`tabAiTools`) | vars · rules · commands · actions · checks · presets = 6 |
| JSON 탭 | ① 통짜 생성 · ② 왕복 패치 · ③ 오류 돌려주기 = 3 |
| 상태창 탭 | CSS 규격서 = 1 |
| 진단 탭 | 패치 요청(권장) · 탭별 수정 요청 · 결과 글 복사 = 3 |

동사도 제각각: **"요청할" / "내보내기" / "돌려주기" / "복사"**.
"어디가 뭘 해주는 건지"를 만든 사람도 헷갈렸다면 그건 UI 문제가 확정된 것이다.

## 마법사에 대한 정정 — 두 종류를 구분한다

| | 무엇 | 크기 | 판단 |
|---|---|---|---|
| **무거운 마법사** | 단계별 빌더 — 뭘 만들지 대신 해준다 | 크다 | 미룬다 |
| **얇은 마법사** | 목적 → 목적지 라우터 — 어디로 가야 하는지만 알려준다 | 작다 | **이게 곧 아래 2번이다** |

"마법사는 무겁다"는 무거운 쪽 이야기다. 얇은 쪽은 **첫 화면 재배치와 같은 작업**이므로
따로 미룰 항목이 아니라 최우선 과제 안에 이미 들어 있다.

**후속 정정**: 내장 AI 생성(`design-내장-AI-생성.md`)이 들어오면 무거운 마법사 문제 자체가
소멸한다 — 단계별로 안내할 필요 없이 AI가 걷고, diff·검증이 난간이 된다. 목적 카드는
그 입력창의 프리셋 문구로 흡수된다.

## 작업 순서

### 1. AI 입구 통합 → **내장 AI 생성으로 완성한다** (`design-내장-AI-생성.md`) — ✅ v0.46 구현됨

13개 입구를 한 곳으로 — 인데, 후속 논의에서 한 단계 진화했다: 규격을 복사해 공홈을 왕복하는
대신 **플러그인이 직접 유저의 모델을 불러**(callAuxLLM 재사용, 배관 기존재) 요청 입력창
하나로 접는다. 봇 desc·로어북도 자동 동봉되므로 유저는 원하는 것만 말하면 된다.

- 생성 함수(`buildSchemaSpecPrompt` · `buildPatchExportPrompt` 등)는 **그대로 재사용** —
  복붙용 문서가 곧 API 요청 본문
- 응답은 기존 패치 파이프라인(검증·diff·충돌·원자 적용)으로 — **안전망이 이미 있어서
  가능해진 프론트**다
- 복붙 경로는 옆문으로 유지 (API 크레딧 없이 공홈 구독 쓰는 유저)
- 상세·함정 3개(자기 정산·모델 품질·병행 경로)는 `design-내장-AI-생성.md`

### 2. 이층 구조 (확정 — 목적 카드를 대체) — ✅ v0.46 구현됨

> 2026-07-30 최종 확정: "유저들은 위층에서 AI에게 요청하면서 딸깍 맡기기, 더 디테일하게
> 들어가고 싶은 사람은 아래층 탭에서 작업." 첫 화면을 따로 설계할 필요가 없다 —
> **이층 분리 자체가 첫 화면이다.**

```
┌─ 위층 (기본 화면) ──────────────────────────┐
│  ✨ AI에게 맡기기 — 요청 입력창 + [생성]      │   ← design-내장-AI-생성.md
│  (봇 설명·로어북 자동 동봉, 결과는 diff 확인)  │
│  + 템플릿 고르기 (난이도 태그)                │
├─ 아래층 (🧰 직접 만지기 — 접힘) ─────────────┤
│  지금의 탭 10개 그대로                       │   ← 재배치 아니라 "정리"만
└─────────────────────────────────────────┘
```

- 위층이 기본. 아래층은 한 번의 클릭 뒤에 (없애는 게 아니라 접는 것 —
  "기능은 반드시 칸과 함께" 원칙 그대로)
- **아래층에 UX 곡예를 하지 않는다.** 원래 계획대로 다듬기만: 용어 통일(§5)·인라인
  도움말(§3)·죽은 중복 정리. 구조 개편은 위층이 흡수했으므로 불필요
- 위층에서 적용된 결과는 아래층 탭에 그대로 반영된다 (같은 스키마·같은 rerender) —
  두 층은 같은 집이다

### 3. 도움말은 인라인

별도 가이드 10탄이 아니라 **칸 옆 한 줄.** 가이드는 "찾아가야 하는 것"이라 이미 진 싸움이다.
`pair(label, el, title)`에 title이 이미 있으므로 그 위에 얹는다. 게시 가이드는 그대로 두되
**깊이 읽는 사람용**으로 성격을 분리한다.

### 4. 템플릿 난이도 하/중/상 태그

눈으로 보고 익히는 단계. 메타데이터 + 정렬이라 거의 공짜.
→ 참고: 지금 템플릿 12종은 **전부 단일 주체**다 (반복 엔티티 예시 0). §5 참조.

### 5. 용어 통일 (거의 무료)

같은 행위에 "요청할 / 내보내기 / 돌려주기 / 복사" 넷을 쓰고 있다. 하나로 고른다.

## 역할 분담 — 외부 UI 기여자와

UI를 고쳐서 공유해 준다는 유저가 있다. 충돌을 막기 위해:

- **기여자**: 시각적 정리 (여백·타이포·카드·색·밀도)
- **이쪽**: 정보 구조 (입구 통합·목적 카드·점진 노출·용어)

안 나누면 **예쁘게 정리된 미로**가 나온다. 시각 정리는 정보 구조 위에 얹혀야 한다.
