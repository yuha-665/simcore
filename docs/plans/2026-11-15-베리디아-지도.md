# 베리디아 지도 (+ 찾아낸 곳 목록 여러 개) 구현 계획

> 실행: `executing-plans`로 작업 순서대로 진행한다.

**목표:** 베리디아에 지도 세 장을 넣고(탐사 띠 12개 · 그림 한 장), 지도가 찾아낸 곳 목록을 여러 개 읽게 한다(SimCore v1.26.1).
**구조:** 엔진은 `map.moreLists` 한 칸(읽기 전용 목록들)만 더한다 — `listVar`의 뜻(플레이어가 적는 곳)은 그대로. 베리디아는 생성기(`베리디아/estate-vars.js`)에 띠 표·지도·통지 문구·자체 테스트를 넣는다.
**설계 문서:** `docs/design-베리디아-지도.md` (엔진 쪽 배경은 `docs/design-지도-여러장.md`)
**커밋:** 끝에 한 번 (feat/map-sheets에 이어서 — 유저: 개발이 다 끝나면 한 번에 배포)

## 전역 제약
- `sheets`·`moreLists` 없는 옛 지도의 재료·그림·검증은 v1.25.1 황금본(`테스트/fixtures/map-golden-v1.25.1.json`)과 글자까지 같다. 황금본은 다시 뜨지 않는다.
- 엔진에 넣은 것은 편집기 칸이 있어야 한다(금지 #3) · 규격서(`SCHEMA_MAP_RULES`)에 한 줄.
- 베리디아는 생성기만 고친다. 기존 세이브가 이어져야 한다(변수 이름·뜻을 안 바꾼다).
- 로어북의 "지도는 지형까지만" — 지도·그림·설명에 방향 안의 정체(둥지·광산·폐허)를 미리 적지 않는다.

## 검토 초점
1. 옛 세이브에 "이름 · 서" 꼴로 쌓인 발견 → 사라지지 않고 그 방향 가까운 띠에.
2. 보조가 위치를 지도에 없는 말로 적음 → 예외 없이 첫 장 + "지도 밖".
3. 함께 읽는 목록의 핀 카드 → 고치기·지우기 단추가 없다(그 목록은 시스템의 것).
4. 적어 넣는 이름이 함께 읽는 목록의 핀과 겹침 → 거절.
5. 변수 지우기로 moreLists의 목록을 지움 → 지도는 남고 그 목록만 빠진다.
