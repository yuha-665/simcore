> 2026-07-30, 접근성 논의 직후의 방향 전환. `design-접근성.md`의 1번(입구 통합)을 이것으로 완성한다.
> **✅ v1 구현·배포됨 (v0.46, 같은 날)** — 아래 완료 정의 전부 충족. 편집기 위층
> "✨ AI에게 맡기기"로 탑재, 이층 구조(접근성 §2)와 함께. 남은 것: 리수 실기 확인
> ([live-test] 지점 — runLLMModel 응답·getCharacter desc 필드명). v2 대화형 정제는 보류했다가
> **v1.9.0(2026-09-09)에 [💬 대화] 탭으로 구현** — 아래 "대화형 정제" 절.
> 유저 통찰: "내가 만든 건 거대한 프레임워크지 프론트가 아니었어. 리스 유저는 모두 API 키가
> 있으니 플러그인에서 직접 AI를 부르면 규격 내보내기로 공홈을 왕복할 필요가 없었다.
> 봇 디스크립션·로어북을 읽게 하면 일일이 정보를 안 적어도 되고."
> 참고 선례: metamyong의 RisuAI-Interface-Generation (API 키로 인터페이스 생성) —
> 우리는 한 수 위가 가능하다: **키 입력조차 필요 없다. 리수가 이미 들고 있다.**

## 왜 지금인가 — 부품 4개 중 3개가 완성품이다

| 부품 | 상태 | 어디에 |
|---|---|---|
| LLM 호출 | ✅ | `callAuxLLM` — `runLLMModel({mode:'submodel', allowPlugins})`, 차단 환경 우회(`scheduleDeferredAux` 4회), JSON 재시도 패턴까지 실전 검증 (v0.37.1~) |
| 보낼 프롬프트 | ✅ | `buildSchemaSpecPrompt`(통짜) · `buildPatchExportPrompt`(패치) · `buildFixPrompt`(오류) — 복붙용으로 만든 그 문서가 그대로 요청 본문 |
| 응답 처리 | ✅ | 코드펜스 벗기기 → `parsePatch` → 계획·충돌 3지선다 → **원자 적용 + 되돌리기** — 붙여넣기 칸으로 오던 것이 API 응답으로 올 뿐, 같은 파이프라인 |
| 봇 컨텍스트 | ✅ | `getCharacter()` → `desc`, `globalLore` — 유저가 봇 설명을 다시 적을 필요가 없다 |

**순서에 대한 기록**: 프레임워크를 먼저 만든 게 잘못이 아니다. 패치 계층(v0.44)의
검증·diff·원자성이 없었으면 이 기능은 "AI가 봇을 조용히 덮어쓰는 기능"이었다.
**안전망이 먼저 있어야 프론트를 열 수 있었다.**

## 흐름 (v1)

```
[✨ AI에게 맡기기]  ← 편집기 정문 (13개 입구가 여기로 접힘 — design-접근성.md §1의 완성형)

  ┌─────────────────────────────────────────────┐
  │ 원하는 걸 말하세요:                            │
  │ ┌─────────────────────────────────────────┐ │
  │ │ 산적 습격 이벤트 추가해줘. 경계 5 이상이면    │ │
  │ │ 발동하고 금화를 뺏기게                      │ │
  │ └─────────────────────────────────────────┘ │
  │ ☑ 봇 설명·로어북을 함께 보냄 (12KB)            │
  │ [✨ 생성]     [📋 복사해서 다른 AI에게]        │
  └─────────────────────────────────────────────┘
        │
        ▼ callAuxLLM(규격 + 다이제스트 + 봇 컨텍스트 + 요청)
        ▼ parsePatch → 계획·충돌·삭제 확인 (기존 v0.44 UI 그대로)
        ▼ [✅ 적용]  — 원자, 되돌리기 1슬롯
```

- **모드 자동 판별**: 스키마가 없으면 통짜 생성(`buildSchemaSpecPrompt` 계열), 있으면 패치
  (`buildPatchExportPrompt` 계열). 유저는 구분을 몰라도 된다.
- 진단·검증 오류가 있으면 입력창 위에 "이 문제를 고쳐달라고 보내기" 프리셋 칩.
- **목적 카드(접근성 §2)의 카드들 = 이 입력창의 프리셋 문구**가 된다. 무거운 가이드 마법사
  문제는 이 지점에서 소멸한다 — AI가 걷고, diff가 난간이다.

## ⚠ 함정 3개 (설계 제약)

### 1. 자기 정산 함정 — 절대 `mode:'model'`로 쏘지 말 것

생성 호출을 `'model'`로 보내면 **우리 자신의 beforeRequest가 그걸 진짜 턴으로 알고
상태 블록을 얹고 onSend 정산까지 돌린다.** v0.37.2 사고(남의 otherAx에 우리가 끼어듦)의
거울상이다 — 이번엔 우리가 우리에게 끼어든다. `callAuxLLM`(submodel) 재사용이면 자동 회피.
새 호출 경로를 만들거든 이 규칙부터 옮겨 적을 것.

### 2. 모델 품질 — 보조 모델은 보통 싸다

스키마 생성은 이 생태계에서 가장 어려운 작업인데, 유저의 보조 모델은 번역·요약용 싼 모델인
경우가 많다. 대응:
- 생성용 모델 선택 (기본 = 보조, 옵션 = 메인 모델·직접 지정. 리수 `runLLMModel`의
  `staticModel` 지원 범위 [live-test]) — **✅ v0.46.1 구현됨** (공홈 피드백 "submodel로
  스키마 생성하면 망한다"로 배포 전 승격). 메인 모델 경로는 `mode:'model'` +
  `GEN_SENTINEL`(⟦simcore:gen⟧) 자기 식별로 함정 1을 통과 — beforeRequest가 센티널을
  보면 주입·정산 없이 통과시키고 센티널만 지운다 (test-auxbleed 단언). 센티널 없는
  'model' 호출은 여전히 절대 금지. 기본값은 검증된 보조 유지, 실기 후 기본 변경 판단.
  **[실기 결과 2026-07-30]** 메인 모델 경로는 이 환경(Claude 공식 API)에서 **인증 실패** —
  리수가 플러그인發 mode:'model' 호출에 유저 API 키(x-api-key)를 안 붙인다. 요청 자체는
  파이프라인을 통과해 나갔으므로 **센티널 bypass는 정상 작동 확인** (자기 정산 없음).
  실질 경로 = 보조(기본) / 직접 지정(staticModel, 미검증) / 리수 보조 모델을 상위로 교체.
  v0.47.6에서 인증 실패 시 정조준 안내 추가. 남은 실기: staticModel 지원 여부.
  **[실기 2차]** 웹리스는 `getDatabase()` 접근 불가 — [🔎 id 읽기]는 우회 안내로 폴백 (설계대로).
  직접 지정·staticModel 검증은 키 등록된 환경(집)에서. 테스트 환경이 API 키 미등록이라
  인증 실패가 정상인 상황이었음도 참고 — 키 있는 실사용 환경에서는 보조 경로가 기본 답.
- 생성 결과가 검증에서 반복 실패하면 "더 강한 모델을 권합니다" 안내
- **실패해도 안전하다**는 게 이 설계의 핵심 — 쓰레기가 와도 검증·diff에서 멈춘다

**보류 (같은 피드백의 2번, ① 해결 후 실기 관찰로 판단)**: 통짜 생성을 버튼 하나 안에서
변수 → 액션 → 규칙 단계로 나눠 돌리기. 재료는 기존재 (`TAB_SLICES` +
`buildTabExportPrompt` 변수 계약 + `pickTabFragment` 병합, 진행 표시는 `.sc-prog` —
단 어댑터 패널 스코프라 편집기 CSS에 한 벌 필요). 약한 모델 × 긴 출력이 문제의 뿌리라
모델 슬롯이 먼저다 — 단계를 나눠도 약한 모델이면 실패 기회만 5번이 된다.

### 3. 복붙 경로는 강등이 아니라 병행

API 크레딧 없이 공홈 구독(GPT·클로드 웹)으로 강한 모델을 쓰는 유저가 실존한다.
[✨ 생성]이 정문, [📋 복사해서 다른 AI에게]가 옆문 — 옆문은 지금의 왕복 그대로.
같은 프롬프트 빌더를 쓰므로 유지비는 0에 가깝다.

## 컨텍스트 조립 (새로 만드는 유일한 부품다운 부품)

`getCharacter()`의 `desc` + `globalLore`를 생성 프롬프트에 동봉:
- **크기 가드**: 로어북이 수십 KB인 봇이 있다 — 상한(예: 20KB) + 체크박스로 끄기 + 실측 KB 표시
- `⚙simcore` 항목은 제외 (스키마는 다이제스트로 이미 실림 — 이중 전송 금지)
- 보조가 aux 델타 JSON 지시와 헷갈리지 않도록 생성 프롬프트는 **독립 문서**로
  (기존 buildAuxPrompt와 문구 격리 — 같은 모델이 두 역할을 하므로)

## 대화형 정제 (v2 — ✅ v1.9.0 구현, 2026-09-09)

"아니 이벤트는 3개로" 같은 후속 요청. 직전 요청·응답을 다음 프롬프트에 접어 보내면 되지만,
**v1은 단발로 갔다** — 단발이어도 공홈 왕복이 사라지는 것이 본체이고, 실패 시 재요청도
매번 최신 다이제스트 기준이라 어긋남이 없다. 정제 루프는 대화 상태 관리(맥락 크기·리셋 시점)가
따라와서 별도 설계 가치가 있다.

### 왜 다시 열었나 — 실기 제보 (2026-09-09)

한 제작자의 피드백: "AI 어시스턴트가 작업물을 **출력하지 않아서** 리테이크나 결과에 대한 논의가 불가능하다.
그래서 외부 AI(AD)와 논의하며 만드는데, 외부 AI는 **심코어 구조를 해석할 수 없어** 내가 구조를 스스로
알아내기 전엔 방법이 없었다. 공홈은 성인 요소 설정을 안 받고, 리수 OOC는 문장 만드는 곳이라 툭하면 RP로 샌다."
유저(제작자) 통찰: "AI에게 창작 맡기기는 결국 **VS Code에서 실시간으로 이야기 주고받듯** 이 형태가 됐어야 했다.
'해줘 → 결과물만 바뀜 → 무엇이 만들어지고 바뀐 건지 알기 힘듦' 구조가 어려운 지점이었다."

진단: v1이 결과를 안 보여준 건 아니다 — 변경 계획(추가·교체·삭제 diff)은 보여준다. 없던 것은 **"왜"와
"그럼 이렇게"**, 그리고 **구조 질문**이다. 세 번째가 핵심이다: 외부 AI가 논의 상대가 못 되는 이유는 규격을
모르기 때문인데, 내장 어시스턴트는 규격서를 이미 들고 간다. 유저 본인 모델이라 거부 문제도 없다.

### 모양 (v1.9.0) — 안전망을 감싸는 채팅

- **1층 [💬 대화] 탭** (창작·결과·진단 옆, 직결 호출 `ai.generate`가 있을 때만). 빈 작업본에도 뜬다.
- **응답 = 두 조각.** 사람에게 하는 말(말풍선) + 선택적 JSON 코드펜스 하나. JSON은 **기존 파이프라인 그대로** —
  패치면 parsePatch → planPatch → 변경 계획 → 적용 → 되돌리기, 빈 작업본이면 validateSchema → 통짜 확인 상자 →
  편집기에 넣기. 형식 불합격은 오류를 첨부해 1회 재요청("설명은 반복 말고 JSON만"), 그래도 실패면 사유+원문
  접기로 버린다. 논의 턴은 JSON이 없어 아무것도 안 바뀐다. `splitChatResponse`: 마지막 `{`로 시작하는 펜스,
  `js` 코드 예시 펜스는 산문.
- **맥락은 매 턴 새로 조립.** 시스템 = 대화 규약(`chatRules`) + 기존 규격서(통짜 `buildSchemaSpecPrompt` /
  패치 `buildPatchExportPrompt`, `chat:true`로 마감 문구만 "코드펜스 안에서만 하나"로 교체) + 봇 컨텍스트. 다이제스트가
  적용 뒤의 최신 작업본이라 이력과 어긋나지 않는다. 캐시 되는 모델은 앞부분 고정 덕을 본다.
- **이력은 접는다** (`chatHistoryMessages`): 산문 + 결과 표식만. 적용된 JSON → `[적용됨 — 추가 vars:x …]`,
  버린 것 → `[적용되지 않음]`, 계획 상자에 떠 있는 것만 코드펜스 그대로(후속 "아니 이렇게"용). 최근 12개·24KB,
  user로 시작. 떠 있는 수정안을 두고 다음 말을 하면 그 수정안은 지나간 것(상자 치움, 적용 안 됨으로).
- **토큰**: 리수 `runLLMModel` 결과에 사용량이 안 실려 와서 **추정**(`estTokens`, ±30%)이 한계 — 이번 전송·대화
  누적(보낸/받은)을 표시, 초기화로 0. 실기에서 응답 객체에 usage가 보이면 실측으로 바꾼다.
- **모델은 유저 몫.** 생성 모델 선택 줄을 대화 머리에 같이 붙이고, 보조 모델이면 "메인급 권장" 문구만(막지 않음).
  리수를 쓰는 이상 API 소모는 유저가 이미 감수하는 것 — 제작은 지금도 메인급 모델에 맡겨야 맞다.
- **어댑터**: `callGenLLM(input)`이 문자열(단발) 또는 `{ system, messages }`(대화)를 받는다. 세 경로(보조·메인·직접
  지정) 모두 같은 배열 — `callAuxLLM(promptText, maxTokens, messages)`. 대화 메시지엔 AUX_NUDGE가 없어 보조
  출력 상한 걸쇠에 안 걸린다(긴 답이 필요한 자리 — 의도). 메인 경로는 센티널을 시스템에 달아 자기 정산 함정 가드
  유지. 루아 브리지 전용 환경(직결 차단)에서는 대화가 안 된다 — 안내 문구.
- 대화는 편집기 인스턴스에만 산다(닫으면 사라짐). 저장이 필요해지면 그때 플러그인 저장소로.

### 같은 제보의 다른 반 — 편집기 만드는 순서

"작업 구조를 변수 설정[기본] → 변수를 관리[진행] → UI 아웃풋[세계]로 이해했는데, 중반에나 만질 [세계]가 중간에
있어서 [진행]의 규칙·이벤트를 못 보고 **규칙을 변수 설명에 넣고** 흐뭇해하다가 테스트에서 망가졌다. 흐름을
'변수 작성 → AI 설정에서 변수 등록 → 규칙·이벤트 실행'으로 정리하면 직관적일 것." 셋으로 받았다: 3층 묶음 순서
기본 → 진행 → 세계 → 자동화, 본문 머리의 "만드는 순서" 띠(① 변수 → ② AI 설정에서 열기 → ③ 규칙·이벤트 → ④ 상태창,
누르면 그 탭), 변수 [AI용 설명] 칸이 "규칙은 여기가 아니라 [규칙·이벤트]"라고 직접 말한다(규칙을 desc에 적으면
모델이 읽어 얼추 돌다가 판정·정산에서 깨지는 함정).

## 비용·시간 UX

- 요청당 대략: 규격 8~12KB + 다이제스트 + 봇 컨텍스트 = 10~30KB 입력, 출력 1~8KB.
  **전송 전에 실측 KB를 보여준다** (copyWidget이 이미 하는 것과 같은 예의)
- 생성 중 진행 표시 + 취소. 30초~수분 걸릴 수 있다 — 패널을 닫아도 완료되면 결과가
  남아 있게 (deferred 패턴 재사용)
- 응답이 JSON 파싱 실패면 1회 자동 재시도(기존 aux 재시도 문구 패턴), 그래도 실패면
  원문을 보여주고 "복사해서 다른 AI에게" 옆문 안내
