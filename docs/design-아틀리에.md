# 아틀리에 레슬레리아나 — 채집·연금·경영 시뮬 (설계)

원본: 아틀리에 레슬레리아나 RP 봇 (로어북 151항목 / 카드 디스크립션 / **루아 없음**).
얼헌과 달리 변환할 스크립트가 없다 — **로어북에서 심코어로 옮길 것만 옮기고, 남은 로어북과
디스크립션을 정리하면 끝**이다.

목표는 원본의 "서사로 굴러가는 아틀리에"를 **숫자로 굴러가는 공방 경영 시뮬**로 바꾸는 것.
원본 상태창(로어북 145 — 년도/날짜/요일/시간/위치/평판/콜/아이템/소재를 매 응답 본문에
찍으라는 지시 740토큰)이 심코어 상태창 하나로 통째 대체된다.

---

## 1. 가장 어려운 문제 — 시작이 시리즈마다 다르다

제작자가 아틀리에 전 시리즈 인물을 넣고 **퍼스트 메시지를 계열별로 쪼개 놨다.**
소피로 시작하든 로로나로 시작하든 라이자로 시작하든, 공방 이름·거점·스승·동행이 전부 달라진다.
그런데 채집·연금·경영 규칙은 계열과 무관하게 공용이다.

### 답: `setup.ai` (세션 0) — 첫 응답이 곧 시작 설정이다

`isSetupPending = setup.ai.enabled && !meta.setupDone && meta.turn === 0`
([core/engine.js](../core/engine.js#L126)) — **세션 0은 "첫 생성 응답" 딱 한 턴이다.**
퍼스트 메시지는 생성물이 아니라 turn 0 이전이므로, 유저가 계열을 고르고 첫 입력을 넣은
그 응답이 정확히 설정 턴이 된다.

- `setup.ai.instruction` → **메인 프롬프트에** 실린다 (engine.js:808). 기본 문구
  ("아직 시뮬레이션이 시작되지 않았다")는 쓰지 않는다. 첫 장면이 이미 제시된 봇이므로:
  > `[첫 장면] 지금 응답이 이 판의 시작이다. 앞의 도입부와 유저의 첫 입력을 근거로 공방의
  > 이름·자리·스승·동행을 장면 안에서 자연스럽게 확정하라. 목록으로 나열하지 마라.`
- 이어서 어댑터가 그 응답 본문을 읽고 **전용 보조 호출**로 초기값을 뽑는다
  (`buildSetupPrompt` — 절대값, 델타 아님).
- `setup.ai.vars`에 적힌 변수만 채워진다. 여기 없는 건 못 건드린다.

**채우는 것**: `atelier_name`(공방 이름) · `atelier_place`(공방이 있는 곳) · `mentor`(스승·후견인)
· `origin`(동행 계열 enum) · `location`(현 위치) · `allies`(동행 명단)

**그리고 이 여섯은 `updater.allow`에 넣지 않는다.** 한 번 굳으면 보조 AI가 영영 못 흔든다 —
"공방 이름이 턴마다 미묘하게 바뀐다"는 사고가 구조적으로 안 난다.
유저 수정 통로는 변수 `cmd` 하나: `atelier_name.cmd = '공방'` → `/공방 별빛 공방`.

### `origin` enum이 NPC 목록 3,792토큰을 쪼갠다 (P3 ✅ 실측)

로어북 144 `npc 리스트`는 **always-on 3,792토큰**이다 (전 시리즈 캐스트 맵).
`origin`으로 지시문 8벌로 갈랐고, **실측 절감은 초반 85% / 후반 최악 55%**다.

| 언제 | 실리는 것 | 토큰 |
|---|---|---|
| 초반 (renown 30, clues 0) | 란타르나 코어만 | **562t** |
| 후반 최악 (renown 700, clues 5, 아를란드) | 코어 + 월영회 + 극야 + 아를란드 11인 | **1,697t** |
| 원본 (always-on) | 전부, 언제나 | 3,792t |

- 적대 세력은 **이야기가 거기까지 갔을 때만**: 월영회 `renown >= 100 or clues >= 1` ·
  극야 `clues >= 2 or renown >= 300`. 초반엔 크리셀다가 프롬프트에 없다.
- **손으로 옮기지 않는다.** 생성기가 빌드 때 `lorebook_export.json`에서 `### ` 구간을 잘라
  굽는다 — 구간을 못 찾으면 빌드가 즉시 죽는다(조용한 빈 지시문 방지). 영/한/일 이름 병기를
  그대로 살려서, 모델이 그 이름을 쓰면 개별 인물 로어북 항목이 뜬다.
- **enum 값은 로어북 144가 스스로 묶어 둔 구간을 그대로 따른다** — 원본이 잘부르그·그람나트를
  한 구간, 비밀·추억·기타를 한 구간으로 묶어 놨다. 다르게 쪼개면 구울 때 어긋난다:

```
origin: 란타르나 | 잘부르그·그람나트 | 아를란드 | 황혼 | 신비 | 비밀·추억
```

세계는 언제나 란타르나다 (이방인은 란타르나에 흘러든 사람들). `origin`은 "어느 세계냐"가
아니라 **"이 판의 동행이 어느 계열이냐"**다 — 봇 디스크립션의 이방인 규약과 어긋나지 않는다.
남의 계열 인물도 **이름을 부르면 그대로 등장한다** (개별 항목이 키워드로 뜨고, 로어북 146
`퓨처플랜`이 전체 프로필을 끌어온다).

⚠ 이걸 켠 뒤에는 **로어북 144를 반드시 지운다.** 안 지우면 3,792토큰이 그대로 또 실린다.

## 2. 시스템 지도 — 6기능 → 심코어 모듈

| 기능 | 심코어 | 비고 |
|---|---|---|
| **채집** | `⛏ 채집` 액션 + `gather` 판정 + `materials` 목록 | 등급이 "몇 칸 얻었나"를 주고, 무엇을 얻었는지는 서사가 |
| **탐험·탐사** | `🔍 탐사` 액션 + `survey` 판정 + `areas`·`clues` | 새 채집지 개방 / 유적·마나 이상 단서 |
| **연금** | `🧪 조합` 액션 + `synth` 판정 + `items`·`recipes` | 난이도는 `synth_tier` enum, 보정은 평판+가마 |
| **경영** | `shop`(왕도 상점) + `quests` 목록 + `calendar` + `party` 설비 탭 | 콜·기한·설비 투자 |
| **전투** | `checks[].fight` (v1.6 전투 안무) + `⚔`·`🏃` | 게이지가 차야 결착 — 한 응답에 안 끝난다 |
| **의뢰** | `board`(카페 의뢰 게시판, 자율형) → `quests` 목록 | 2단계 |

**탐험과 탐사를 나누지 않는다.** 원본에서 둘의 경계가 없다 — 이동은 서사고, 굴릴 값이 있는
쪽(유적 조사·새 채집지 발견)만 `survey` 판정 하나로 받는다.

## 4. 판정

| id | roll | mod | vs | 등급 |
|---|---|---|---|---|
| `gather` | d20 | `floor(renown/100) + count(tools) + (stamina<30 ? -3 : 0)` | `8 + area_tier*2` | 만재 / 성과 / 빈손에 가깝다 / 헛수고+사고 |
| `survey` | d20 | `floor(renown/80) + library` | `10 + area_tier*2` | 발견(clues+1, areas 추가) / 흔적 / 허탕 / 사고 |
| `synth` | d20 | **§4.3** | `synth_tier` 사슬 (10/15/20) | 걸작 / 상품 / 보통 / 조잡 / 실패 |
| `battle` | d20 | `floor(renown/80) + min(bombs,3)` | `10 + foe_tier*2` | **fight** — 등급마다 `gain` |
| `guard` | d20 | `floor(stamina/20)` | `10 + foe_tier*2` | 회피 / 스침 / 피격 / 직격 (stamina 차감) |

- `synth` 실패 등급의 `inject`에 **로어북 149의 실패 연출**을 그대로 싣는다 (가마가 뻥,
  거품, 검댕, 이상한 냄새 — 평범한 레시피는 희극, 위험한 레시피만 진짜 사고).
- `battle.fight`: `gauge: "25 + foe_tier * 20"` · `reply: 'guard'` · `lose.when: 'stamina <= 0'`.
  **결착은 게이지에서 나온다** — 한 응답에 전투를 끝내지 않는다.

### 4.1 의뢰 — 서사가 계약하고, 시스템이 지급한다

**항목 형식** (`quests`, maxItems **3**):

```
별의 고치 카페 · 감기약 3병 (중급) @+5 +800
```

기한 `@+5`와 보상 `+800`이 한 줄에 공존한다 — `itemValue()`가 **기한 태그를 먼저 떼고
맨 끝 숫자를 잡기** 때문이다 ([core/expr.js](../core/expr.js#L49)). 보상은 반드시 맨 끝.
`@+5`는 다음 전송에 절대 기한(`@455`)으로 굳고, 화면·프롬프트에는 `(5일)`로 환산돼 나간다.

**세 단계**

1. **수주** — 서사가 "이걸 해 주면 800콜"이라고 정하고, 보조가 그대로 목록에 박는다.
   **여기가 유일한 창작 지점**이라 로어북 150의 보상대(심부름 50~200 … 중대사 5,000~15,000)를
   `updater.guide`에 싣는다.
2. **꽉 참** — `directives { when: "count(quests) >= 3", text: "의뢰 수첩이 가득 찼다.
   새 의뢰는 정중히 거절하거나 하나를 끝낸 뒤로 미루게 하라." }`
   > 지시문이 **꼭 필요하다.** 4번째는 엔진이 `slice(0, maxItems)`로 **조용히 잘라 버린다**
   > (engine.js:390) — 서사에선 받았는데 목록엔 없는 유령 의뢰가 된다. 거절을 서사에 시켜야 한다.
3. **납품·정산** — 보조가 `quest_pay`에 **그 항목에 박힌 숫자를 옮겨 적고** 항목을 `remove`.
   이벤트가 지급한다:
   ```
   events: { when: "quest_pay > 0",
             effects: [ cole = cole + quest_pay, quest_pay = 0 ],
             notify: "약속된 보수를 받았다." }
   ```
   **왜 액션이 아니라 이벤트인가**: 액션 효과는 *전송 단계*(장면이 써지기 전)에 돌고,
   보조 델타는 *응답 단계*에 온다. 이벤트는 보조 델타 **뒤**라서 같은 턴에 정산된다.
   `📮 납품` 버튼은 `deliver` 판정으로 **평판만** 건드린다 — 돈은 계약액(결정적),
   평판은 솜씨(변동). 의뢰인은 약속한 만큼 준다.

`quest_pay.desc` = "목록에 박힌 숫자를 그대로 옮겨 적어라. 새로 정하지 마라." + maxGain 15000.

**4. 기한 — 미리 보여 주고, 넘기면 알린다**

*사전 경고는 공짜다.* 기한 `@455`는 화면·프롬프트로 나갈 때 **`(3일)` / `(오늘)` / `(지남)`으로
자동 환산**된다 (v1.7.1). 환산되는 곳에 **상태창과 지시문·`promptState.template`이 다 들어 있어서**,
지시문 한 줄만 깔면 메인 모델이 매 턴 남은 날짜를 글자로 읽는다:

```
directives { when: "count(quests) > 0",
             text: "수주 중인 의뢰: {quests} — 기한이 임박한 것은 서사에서 압박으로 드러내라." }
```

*만료 통지는 세 줄로 만든다.* `onTurn`의 `expire`는 항목을 **조용히** 떨어뜨리므로,
갯수 차이로 잡아낸다 (`applySets`가 효과를 순차 적용해 앞 결과를 뒤가 본다 —
[engine.js:433](../core/engine.js#L433)):

```
onTurn (순서 그대로):
  1. { list: 'quests', expire: 'elapsed' }
  2. quest_lost = max(quest_n - count(quests) - (quest_pay > 0 ? 1 : 0), 0)
  3. quest_n    = count(quests)                        ← 다음 턴 비교용 기준

events { when: "quest_lost > 0",
         effects: [ renown = max(renown - 15 * quest_lost, 1), quest_lost = 0 ],
         notify: "기한을 넘긴 의뢰가 취소됐다. 의뢰인의 말을 전해 들은 참이다." }
```

> **처음에 `expire: 'elapsed - 2'`로 2일 유예를 두려다 접었다 (실측).** expire 식은 만료 기준이자
> **`@+N`을 굳히는 시계이자 화면 환산의 기준**이라 셋이 같은 식이다 — 오프셋이 세 곳에서 똑같이
> 상쇄돼 `'elapsed'`와 결과가 **완전히 같다**. 유예를 두려면 시계를 갈라야 하는데 그런 통로가 없다.
> 지금 동작: 기한 당일까지 살아 있고 `(오늘)`로 보이다가, 다음 날 떨어지면서 통지가 뜬다.
> `(지남)` 상태는 자동 만료 목록에선 볼 일이 없다 (틱이 화면보다 먼저 돈다).

`quest_pay > 0` 항을 빼는 이유: 납품으로 빠진 것까지 만료로 세면 안 된다 (보조 델타는 5단계,
틱은 6단계라 같은 턴에 이미 빠져 있다). 효과가 `quest_lost`를 0으로 되돌리므로 **조건 자기해제**다.
`quest_n`·`quest_lost`는 카운터라 **allow 금지**. `calendar.list = 'quests'`로 달력에도 선다.

### 4.2 채집지 난이도 — 스키마에 미리 박는다

먼저 버린 안: `areas`에 `"버려진 갱도 3"`처럼 숫자를 박고 `sum(areas, location)`으로 읽는 것.
문법상 되지만 매칭이 **`항목.includes(필터)`**([core/expr.js](../core/expr.js#L246))라
*항목이 위치를 품어야* 하는데, 자유 텍스트 `location`("잊혀진 평원 깊은 곳")은
`"잊혀진 평원 1"`에 안 걸리고 **안 걸리면 조용히 0**이 된다.

**확정안: `location`을 enum으로 만들고 `area_tier`를 파생으로 뽑는다.**
난이도를 매번 정하지 않는다 — 표가 스키마에 박혀 있어 영영 안 흔들린다.

로어북이 이미 **고유명사가 아니라 지형으로** 써 놨다 (15 던전과 채집지 · 58 지역별 소재 배치).
그래서 enum도 지형·권역으로 잡는다 — 어느 계열에서 시작하든 그대로 쓰인다.

| `location` (enum) | `area_tier` |
|---|---|
| 공방 · 왕도 · 별의 고치 카페 · 왕도 뒷골목/부두 · 지방 도시 | **0** (채집 불가) |
| 왕도 주변 들판 · 프리겐/시골 | 1 |
| 숲 · 꽃밭/초원 · 강가/폭포 · 해안 | 2 |
| 습지/늪 · 광산/동굴 | 3 |
| 설산 능선 · 사막 · 유적/마나 이상 지대 | 4 |
| 세계의 끝 | 5 |

- `area_tier`는 **파생**이라 AI도 규칙도 못 건드린다. 보조는 `location` enum만 고른다
  (enum은 절대값 적용이라 델타 함정도 없다).
- 서사는 원하는 이름을 그대로 쓴다 — "잊혀진 평원 깊은 곳"이라 부르든 enum은 `숲`이면 된다.
- `⛏ 채집`·`🔍 탐사`는 `when: 'area_tier >= 1'`로 잠근다 (도시에서 채집 버튼이 안 눌린다).
- 어디서 뭐가 나오는지는 **로어북 58이 그대로 담당한다** — 심코어는 몇 칸인지만 정한다.
  `directives { when: "area_tier >= 1", text: "지금은 {location}이다. 여기서 날 만한 소재만 내라." }`
- `areas` 목록은 숫자 없는 **순수 지도**(가 본 곳의 도감)로 남는다.

### 4.3 품질 — 판정이 곧 가챠

**품질 변수를 아이템마다 달지 않는다.** 조합 판정 자체가 가챠고, 숙련도가 확률을 밀어 올린다.

```
mod = floor( <synth_cat에 해당하는 숙련> / 12 )   ← 0~8   분야 숙련
    + cauldron * 2                                ← 0~10  공방 도구 수준
    + floor(renown / 150)                         ← 0~6   평판이 거든다
    + (stamina < 30 ? -3 : 0)
vs  = 10 / 15 / 20                                ← 레시피 자체 난이도(synth_tier)
```

**난이도를 3단으로 줄인다 — 로어북 문단 구조가 곧 등급이기 때문이다.**
로어북 45~48이 이미 `Common ~` / `Advanced ~` 두 문단으로 갈라 놨고, 43이 `희귀와 고위`다.
5단으로 쪼개면 경계가 애매해져 매번 달라지지만, **"그 아이템이 로어북 어느 문단에 있나"**는
흔들릴 여지가 없다. `synth_tier.desc`에 그 대응을 그대로 박는다.

| `synth_tier` | 로어북 근거 | vs |
|---|---|---|
| 기초 | `Common attack/recovery/support items` 문단 (프람·레헤른·힐링 살브·중화제) | 10 |
| 고급 | `Advanced ~` 문단 (드라코 봄·테라 봄·힐링 클라우드) | 15 |
| 비전 | 43 `희귀와 고위 연금술` (현자의 돌·엘릭서·에테르널 크리스탈) | 20 |

숙련 0·가마 1·평판 50이면 mod +2라 비전(20)은 d20으로도 못 넘는다. 숙련 100·가마 5·평판 1000이면
+24라 비전도 안정적으로 넘긴다 — **"도전은 되지만 위험하다"**는 로어북 149의 규약 그대로다.

`synth_cat`·`synth_tier` 둘 다 **보조가 서사에서 읽어 기록한다**(allow). 유저가 매번 칠 필요가
없고, 판단 기준표가 `desc`에 고정돼 있어 AI 재량이 아니다. `cmd`(`/분야`·`/난이도`)는 덮어쓰기용으로만 남긴다.

**등급 = 품질**: 걸작(`total >= vs+8`) / 상품(`>= vs+3`) / 보통(`>= vs`) / 조잡(`>= vs-4`) / 실패.
각 등급 effects가 `last_quality`를 세우고 **그 분야 숙련만** 올린다
(걸작 +3 / 상품 +2 / 보통 +1 / 조잡 +1 / 실패 +1 — 실패해도 배운다).

> 분야가 6종이라 "어느 숙련을 올릴지"는 `set`으로 못 고른다. 등급마다 6줄을 깔고
> 각각 `expr: "synth_cat == '폭탄' ? sk_bomb + 3 : sk_bomb"` 꼴로 쓴다 — 생성기가 찍는다.

품질은 **`last_quality` 하나**만 상태에 남는다. 그 아이템이 계속 고품질인지는 `items` 목록의
이름이 들고 간다("고품질 힐링 살브" — 원본 상태창 예시가 이미 그렇게 쓴다).

|---|---|

  **카페 벽의 손글씨 벽보**로 못박고, guide에서 줄임말·밈·"ㅋㅋ"를 금지한다.

  그때 공고의 보수·기한을 그대로 옮긴다 (지시문 `board_quest`).

|---|---|---|
| 퀘스트 보드 탭 | **안 만든다** | 의뢰는 이미 세 곳에 있다 — 상태창 「의뢰」 그룹(수주분·`(N일)` 환산) · 📅 달력(기한이 날짜에 박힘) · 📋 게시판 「의뢰」 칸(수주 전 공고). 넷째는 중복이다 |
| 채집지 지도 탭 | **만든다** | `areas`가 「여정」 그룹의 평문 목록뿐이라 "어디가 얼마나 위험한가"를 한눈에 볼 자리가 없었다 |

지도는 **새 패널이 아니라 🏠 공방 패널의 둘째 탭**이다 (`party.tabs[].template` — 얼헌 서울 지도와
같은 문법). 버튼은 늘지 않는다 — 탭 하나에 fab을 달아 버튼이 둘 뜬 실기 제보 직후라 지름길도
안 달았다 (원하면 `fab: '🗺️'` 한 줄).

- **지형표(`PLACES`)에서 그대로 굽는다** — 격 0~5 사다리에 지형 17종. 표와 어긋날 수 없다.
- 가 본 곳은 `{areas:tags:지형}` 필터로 **제 칸에 꽂힌다.** 그래서 `areas` 항목 규약을
  **"이름 (지형)"** 으로 바꿨다 — 지형은 `location` enum 값 그대로 (`"버려진 갱도 (광산·동굴)"`).
  지형을 안 붙인 항목은 어느 칸에도 안 들지만 상태창 「여정」에는 그대로 남는다 (조용한 소실 없음).
- 머리에 `지금 {location} · 격 {area_tier}`. 현재 칸 강조는 **일부러 안 했다** — 새니타이저가
  `data-*`를 지우므로 CSS 속성 선택자 트릭이 상태창에선 죽는다 (render.js:552). 글자로 충분하다.
- 실측 10건: 갱도가 광산 칸에·들판 칸엔 근교+평원·갱도는 들판에 없음·미치환 0·CSS `#sc-game` 격리.

**P3 ✅ 세계** — 캐스트 맵 분할 + 시나리오 + 서신 + 에셋 뼈대. 자체 테스트 **93건 통과**.

| | |
|---|---|
| 캐스트 맵 | 지시문 8벌 (코어 1 · 적대 2 · 계열 5). 초반 562t / 최악 1,697t — 위 §1 |
| `scenario` 「잊혀진 기술」 | 5막: 이름 없는 공방 → 쓸모 있는 것 → 소문이 돈다 → 눈길 → 혜성의 자취 |
| `messenger` 「서신」 | `contactsVar: allies` · `notesVar: ally_notes` · `when: area_tier == 0` |
| `assets` | 뼈대만, **`enabled: false`로 출고** |

- **시나리오는 캐논을 따라가지 않는다.** 로어북 147 타임라인은 참고 자료지 레일이 아니고,
  봇 디스크립션도 "session continuity wins"라고 못박았다. 이 척추는 **유저 자신의 연금술 부흥**이라
  어느 계열에서 시작하든 그대로 선다. 해금은 `renown`(세상의 신용)과 `clues`(실마리)가 민다.
  실측: 문턱을 넘겨도 `minTurns` 전엔 안 넘어가고, 전환은 턴당 한 막이다.
- **서신은 단말기가 아니다.** 심부름꾼·행상인이 전해 주는 편지 — guide가 줄임말·이모티콘을 막고
  "급한 일은 편지로 오지 않는다(사람이 직접 뛰어온다)"를 못박는다. 들판에선 발신·선톡이 멈춘다.
- **에셋은 꺼진 채로 나간다.** 카드에 실린 **실제 에셋 이름을 모르는 채로 켜면 조합이 전부 대조
  실패해 이미지가 0장**이 되고, 그건 에러 없이 조용히 실패한다 (v1.4.1 사고). 카드의 에셋 이름을
  확인해 `who` 값·`sep`·`format`을 맞춘 뒤 `enabled: true`로 켠다.

작업 파일: `아틀리에/atelier-vars.js` (생성기 — **여기만 고친다**) → `아틀리에/공방-아틀리에.json` (68.8KB).

**확정** (유저 결정, 2026-09-05): 의뢰 = 서사 계약 + 이벤트 정산, 3개 상한 + 거절 지시문(§4.1) ·

**등장인물은 제한이 아니다.** `origin`은 always-on 캐스트 맵만 가른다 — 개별 인물 로어북
항목은 이름 키워드로 뜨므로, 어느 계열의 누구를 불러도 그대로 등장한다.
로어북 146 `퓨처플랜`의 `[💡Request Profile| …]`이 그 순간 전체 프로필을 끌어오는 통로고,
그건 심코어가 대체하지 않는다 — **그대로 남긴다.**

**추가 확정** (2026-09-05): 의뢰 기한은 `(3일)`→`(오늘)`→`(지남)` 자동 환산으로 **미리 보이고**,
